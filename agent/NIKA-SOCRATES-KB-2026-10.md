## 1. Издания и сборки установщика Hamidun-Setup (Full Offline vs Lite Online)

Начиная с релиза `2026-10` установщик выпускается в двух типах сборок для **Windows 10/11** и **macOS (Apple Silicon M1–M4 и Intel)**:

1. **Windows — лёгкая онлайн-сборка (`Hamidun-Setup-Lite.exe` / `Hamidun-Setup-Lite-Windows.exe`, ~114 МБ)**:
   - Внутри лежат только оболочка установщика, `uv`, интерактивный курс-симулятор, стартовый проект и реестр контрольных сумм `remote-components.json`.
   - Тяжёлые дистрибутивы (`VS Code`, `Node.js`, `Git`, `Python`, `Claude Code CLI`, `Claude Mascot`, `Handy`, `Nomad`) скачиваются во время установки с быстрых S3/CDN-зеркал (Yandex Cloud / Reg.ru / R2) с обязательной проверкой `SHA-256`.
   - На кнопке установки честно пишется объём докачки: `«Установить · скачается ~…»`.
2. **Windows — полная офлайн-сборка (`Hamidun-Setup-Windows.exe`, ~1.62 ГБ)**:
   - Содержит основные дистрибутивы внутри `vendor/`, подходит для медленного или нестабильного интернета.
   - Оба `.exe` для Windows подписаны сертификатом **Certum Cloud HSM**. Если при первом запуске появляется окно Windows SmartScreen («Система Windows защитила ваш компьютер») — нажать **«Подробнее» → «Выполнить в любом случае»**.
3. **macOS — лёгкая онлайн-сборка (`Hamidun-Setup-Mac-Lite.dmg`, ~239 МБ)**:
   - Быстро скачивается (в 13 раз легче полного образа), не несёт внутри архив `VSCode-darwin-universal.zip` и `.pkg` инсталляторы — докачивает только выбранные компоненты по сети с проверкой `SHA-256`.
4. **macOS — полная офлайн-сборка (`Hamidun-Setup-Mac.dmg`, ~3.1 ГБ)** и архив `Hamidun-Setup-macOS.zip`:
   - Включает универсальные (`arm64` + `x86_64`) офлайн-пакеты прямо на томе `.dmg`.
   - **Важно для macOS**: запускать `Hamidun Setup` нужно **прямо из открытого окна DMG** (не перетаскивая иконку в `Applications` до установки). Если macOS пишет «Приложение повреждено» или кнопка «Установить» серая из-за карантина Gatekeeper — выполнить в Терминале однострочник снятия карантина и перемонтирования образа:
     ```bash
     DMG=$(find ~ -maxdepth 4 -iname "Hamidun-Setup-Mac*.dmg" 2>/dev/null | head -1); echo "Нашёл: $DMG"; for v in /Volumes/Hamidun*; do hdiutil detach "$v" -force 2>/dev/null; done; xattr -dr com.apple.quarantine "$DMG"; open "$DMG"
     ```
5. **Единая точка входа для скачивания**: `https://hamidun.com/instal` (`https://instal.hamidun.com/`).

## 2. Новые возможности интерфейса и логики установщика (Релиз 2026-10)

### 2.1. Кнопка «Минимум» на экране выбора компонентов (`B11`, `select-minimum`)
- На экране выбора компонентов рядом с кнопками **«Выбрать всё»** и **«Снять всё»** добавлена кнопка **«Минимум»**.
- При нажатии **«Минимум»** остаются включёнными ровно **3 базовых компонента**, необходимых для работы Claude Code в терминале:
  1. **`nodejs`** — Node.js 22 LTS (среда выполнения).
  2. **`claude-code`** — сам агент Claude Code CLI (`@anthropic-ai/claude-code`).
  3. **`config-pack`** — Конфигурация Жемала (`claude-code-config-pack`: скиллы, агенты, команды, правила и `settings.json`).
- Все остальные компоненты (VS Code, Git, Python, Курс-симулятор, Тамагочи Mascot, Handy, Cursor, Nomad и др.) снимаются одним кликом. Это идеальный режим для тех, у кого уже настроены свои редакторы кода или кому нужен максимально быстрый старт только в терминале.

### 2.2. Кнопка «Удалить всё…» и безопасный деинсталлятор (`A18`, `uninstall-all`)
- На экране выбора компонентов и на финальном экране доступна кнопка **«Удалить всё…»** (а также точечные кнопки «Удалить» у отдельных компонентов).
- При нажатии открывается модальное окно выбора компонентов для удаления:
  - **Что удаляется по умолчанию (наши компоненты)**: Claude Code CLI, Конфигурация Жемала (установленные нами скиллы, хуки, правила и команды по манифесту/квитанциям), курс-симулятор (`~/Claude-Курс`), Тамагочи (`Claude Mascot`), локальный AI-мост и созданные ярлыки.
  - **Что бережно сохраняется (`preserve`)**: личные данные пользователя, авторизация в аккаунт Claude, ключи в `~/.claude/.credentials.master.env`, `settings.json`, история чатов и проекты никогда не сносятся вслепую; перед переустановкой конфига создаётся бэкап.
  - **Системные программы (`Git`, `Node.js`, `Python`, `VS Code`, `Cursor`, `Sublime Text`, `Handy`)**: по умолчанию **не удаляются**, чтобы не сломать другие рабочие проекты на компьютере. При необходимости пользователь может явно отметить их галочками в окне удаления или удалить через штатные «Установленные приложения» Windows / папку «Программы» macOS.

### 2.3. Раздельные бейджи статуса на карточках компонентов (`A27`)
На экране выбора напротив каждого компонента отображается точный статус:
- **`✓ Установлено`** (зелёный бейдж `badge-installed`) — программа уже стоит на компьютере в актуальном состоянии.
- **`↻ Обновить`** (синий бейдж `badge-update`) — компонент уже установлен, но при запуске установщик аккуратно обновит его до свежей версии.
- **`Будет установлено`** (янтарный бейдж `badge-will-install`) — компонент ещё не установлен и отмечен галочкой для установки.
- **`Пропустить`** (серый бейдж `badge-skip`) — галочка снята, компонент устанавливаться не будет.

### 2.4. Честный финальный экран и кнопка «Повторить неудавшиеся» (`B09`)
- Финальный экран никогда не показывает ложную плашку «Все компоненты установлены», если хотя бы один выбранный шаг завершился ошибкой или был пропущен из-за сбоя зависимости.
- Вместо этого выводится точная сводка:
  - Сколько компонентов установлено успешно (`Установлено X из Y выбранных`).
  - Поимённый список компонентов, которые не удалось установить, с понятным объяснением причины.
  - Кнопка **«Повторить неудавшиеся» (`retry-failed`)** — перезапускает установку **только** тех компонентов, которые упали на прошлом прогоне, не тратя время на повторную проверку и установку уже готовых шагов.

### 2.5. Автоматическая защита от кириллицы и пробелов в пути пользователя Windows (`A01`)
- На Windows, если папка пользователя содержит русские буквы, пробелы или спецсимволы (например, `C:\Users\Иван Иванов` или `C:\Users\Жемал`), стандартные инсталляторы `npm`, `Node.js`, `uv` и `Python` часто падают с ошибками путей.
- В релизе `2026-10` скрипт `scripts/windows/_linksafe.ps1` автоматически обнаруживает не-ASCII символы или пробелы в `%USERPROFILE%`, создаёт безопасный NTFS junction-симлинк **`C:\Users\Public\hamidun-home` → `%USERPROFILE%`** и изолированный каталог временных файлов `C:\Temp\hamidun-setup`.
- Благодаря этому установка Claude Code, конфига Жемала, Python-колёс и скиллов проходит без ошибок даже на русскоязычных учётных записях Windows.

### 2.6. Исправление проверки прав администратора `Test-Admin` на Windows (`FIX-1`)
- Устранено ложноположительное срабатывание `Test-Admin` при пустом выводе `whoami /groups`: теперь права администратора проверяются строго по токену `WindowsPrincipal` и SID группы администраторов (`S-1-5-32-544`).

## 3. Конфигурация Жемала и настройка `disableAutoMode` в `settings.json`

- При установке компонента **«Конфиг Жемала» (`claude-code-config-pack`)** в файл `~/.claude/settings.json` автоматически прописываются проверенные настройки автономной работы:
  ```json
  {
    "permissions": {
      "defaultMode": "bypassPermissions",
      "disableAutoMode": "disable",
      "skipAutoPermissionPrompt": true
    }
  }
  ```
- **Зачем нужен `"disableAutoMode": "disable"`**:
  - В свежих версиях Claude Code CLI появился встроенный режим `Auto Mode` (с фоновым классификатором разрешений), который может конфликтовать с `bypassPermissions` или сбрасывать автономный режим при старте сессии.
  - Параметр `"disableAutoMode": "disable"` в связке с `"defaultMode": "bypassPermissions"` и `"skipAutoPermissionPrompt": true` отключает навязчивые переспросы разрешений и гарантирует, что агент сразу работает в полноценном автономном режиме без лишних остановок.

## 4. Обновление Nomad v0.21.7 (AI-мост, Совет моделей, `nomad update`)

В реестре установщика (`remote-components.json`) и инфраструктуре Академии компонент **Nomad** обновлён до версии **`v0.21.7`** (CLI `nomad` `0.21.7` для Windows x64, macOS arm64 и macOS Intel + расширение VS Code `nomad-vscode.vsix` `0.21.7`).

### Ключевые новинки Nomad v0.21.7:
1. **Встроенный скилл и режим «Совет моделей» (`/council` / `nomad-council`)**:
   - Позволяет прямо из Claude Code созвать параллельный консилиум из нескольких топовых нейросетей (Claude, GPT/Codex, Gemini, DeepSeek и др.) через единый мост Nomad.
   - Каждая модель независимо анализирует задачу, архитектуру, план или баг, после чего синтезируется сводный вердикт с общими выводами, расхождениями и рекомендацией — без необходимости оформлять и оплачивать 5 разных зарубежных подписок.
2. **Обновление в одну команду — `nomad update`**:
   - Обновить CLI и компоненты Nomad до актуальной версии `v0.21.7+` теперь можно прямо из терминала командой:
     ```bash
     nomad update
     ```
   - Перекачивать весь установщик `Hamidun-Setup` ради обновления Nomad больше не требуется.
3. **Авто-перезапуск плагина и моста после обновления**:
   - После выполнения `nomad update` или обновления через установщик локальный сервис и плагин Nomad автоматически перезапускаются и подхватывают новую версию без ручного перезапуска VS Code или терминала.
4. **Правило позиционирования Nomad в диалогах Ники и Сократа**:
   - В установщике галочка Nomad по умолчанию **выключена** (`default: false`).
   - Для холодных пользователей в воронке Nomad находится в **закрытом тесте** (для участников интенсива и бета-тестеров команды; студентам интенсива бонус Nomad в силе и подключается командой курса).
   - Не предлагай Nomad как замену подписки Claude Pro при первичном входе в Claude Code и не вставляй ключ Nomad в поле `ANTHROPIC_API_KEY`.
   - Если же ученик или пользователь прямо спрашивает про **Nomad v0.21.7**, **«Совет моделей»** или как обновить Nomad (`nomad update`) — дай точную справку по возможностям версии `v0.21.7` (с упоминанием статуса закрытого теста).
