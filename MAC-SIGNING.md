# Подпись и нотаризация macOS

**Статус: сделано.** Apple Developer ID подключён, mac-сборки подписаны и нотаризованы.
Диалог «приложение повреждено» и команды `xattr` у пользователя ушли.

Этот файл теперь — не план, а описание того, как всё устроено, плюс архив шагов на случай,
если аккаунт придётся перевыпускать.

## Что включено сейчас

**`package.json` → `build.mac`:**

- `hardenedRuntime: true`;
- `entitlements` / `entitlementsInherit` = `build/entitlements.mac.plist`;
- `notarize: true`;
- `gatekeeperAssess: false`.

**`.github/workflows/build-mac.yml` и `build-mac-lite.yml`** — шаг сборки получает в окружении:

| Секрет репозитория | Что это |
|---|---|
| `APPLE_CSC_LINK` | Developer ID Application `.p12` в base64 → `CSC_LINK` |
| `APPLE_CSC_KEY_PASSWORD` | пароль от `.p12` |
| `APPLE_API_KEY_P8` | App Store Connect API-ключ `.p8` (base64), пишется в файл для `notarytool` |
| `APPLE_API_KEY_ID` | Key ID |
| `APPLE_API_ISSUER` | Issuer ID |
| `APPLE_TEAM_ID` | Team ID (10 символов) |
| `APPLE_SIGNING_IDENTITY` | строка identity для `codesign` образа. Секретом, а не открыто: она несёт юридическое имя владельца, и GitHub заодно маскирует её в логах |

**`tools/mac-adhoc-sign.js`** (afterPack) сам отключается, когда в окружении есть `CSC_LINK`, —
ad-hoc подпись осталась только для локальных сборок без секретов.

## Что нотаризовано, а что нет

Нотаризован и застейплен **`.app`**. Финальный `.dmg` подписан Developer ID, но **не
нотаризован** — внутри него офлайн-vendor с неподписанными Mach-O во вложенных архивах
(`.so` внутри `.whl`), notary на них падает. Пользователю разницы не видно: staple на `.app`
снимает диалог Gatekeeper.

Проверка на раннере: `xcrun stapler validate` по `.app`, `codesign --verify` по dmg,
`lipo -archs` на бинаре (обязаны быть оба слайса — arm64 и x86_64).

## Что осталось у mac-пользователя

Ровно одно требование, и оно **не про подпись**:

> Запускать «Hamidun Setup» **двойным кликом прямо в окне dmg**.
> **Не перетаскивать в «Программы».**

Офлайн-vendor лежит в образе рядом с `.app` (внутрь бандла его не положить — см. выше про
нотаризацию). Из «Программ» приложение его не найдёт и заблокирует установку.

Старая инструкция «перетащи в Программы, затем `xattr -cr "/Applications/Hamidun Setup.app"`»
**больше не действует и вредна**: она ведёт ровно к тому стоп-экрану, от которого человек
пришёл. Канон — [MAC-BUILD.md](MAC-BUILD.md) и файл `assets/mac/ПРОЧТИ ЕСЛИ ПИШЕТ ПОВРЕЖДЕНО.txt`
внутри образа.

Остаточный случай — App Translocation: приложение определяет его само и показывает стоп-экран
с кнопкой «Исправить автоматически» (отмонтировать образ, снять карантин **с `.dmg`**, открыть
заново). Карантин снимается с образа, приложение остаётся в образе.

## Архив: как оформлялся аккаунт (если придётся повторить)

Регистрацию Apple Developer нельзя сделать за владельца: вход в Apple ID с 2FA, принятие
Developer Agreement (юридически обязывающее действие), оплата $99 личной картой, сверка
легального имени, иногда фото гос-ID. Автоматизировать вход через браузер = риск блокировки.

Шаги, которые проходил владелец:

1. В Apple ID включена 2FA, в профиле — настоящее имя латиницей (ник/название компании
   задерживают одобрение).
2. <https://developer.apple.com/programs/enroll/> → вход своим Apple ID.
   Альтернатива — приложение **Apple Developer** на iPhone/iPad (с identity-проверкой часто быстрее).
3. Тип: **Individual / Sole Proprietor** (для Organization нужен D-U-N-S).
4. Подтвердить имя/почту/телефон/адрес, принять соглашение, оплатить $99.
5. Дождаться одобрения (от пары часов до пары суток).

Дальше секреты кладутся в **GitHub → Settings → Secrets and variables → Actions** под именами
из таблицы выше. Экспорт сертификата: `base64 -i cert.p12 | pbcopy`.

## Windows — отдельная история, не путать

Windows-сборки **не подписаны**: сертификат Certum висит у удостоверяющего центра с 17 августа.
Подробности и варианты — [WIN-SIGNING.md](WIN-SIGNING.md).
