# Сборка macOS-версии

`.dmg` собирается **только на macOS** (нужен Mac-тулчейн: `hdiutil`, `codesign`, `notarytool`).
На Windows Mac-версию скомпилировать нельзя.

## Вариант A — облако (без своего Mac), рекомендуется

GitHub Actions собирает `.dmg` на облачном macOS-раннере.

1. Запушить проект в GitHub-репозиторий (один раз).
2. Вкладка **Actions → «Build macOS (.dmg)» → Run workflow**.
   Поле `config_ref` — коммит конфиг-пака, на котором закрепить сборку; пусто = свежий `main`.
3. Готовый dmg (~2,7 ГБ) уезжает в Reg.ru S3, а в GitHub Release появляется указатель на
   ссылку и sha256 — в ассеты Release такой размер не влезает (лимит 2 GiB).

Workflow: `.github/workflows/build-mac.yml` — полное офлайн-издание.
Лёгкое (стриминговое) издание собирает `.github/workflows/build-mac-lite.yml`.
Обе сборки подписаны Developer ID и нотаризованы.

## Вариант B — на своём Mac

```bash
npm install
npm run dist:mac          # -> release/Hamidun-Setup-Mac.dmg
```

Это **чисто онлайн-издание: офлайн не вшито вообще ничего, включая конфиг.**
`fetch:config` в цепочке `dist:mac` есть, но он лишь наполняет `vendor/` на машине сборщика,
а в mac-артефакт `vendor/` не едет ни по какому пути: `extraResources` с `vendor` прописан
только у `build.win`, у `build.mac` его нет, `build.dmg.contents` кладёт лишь `.app`, ярлык
`/Applications` и `ПРОЧТИ…txt`. При установке `scripts/macos/config.sh` не найдёт
`HM_BUNDLED_CONFIG` и склонирует пак с GitHub.

Без секретов Apple в окружении сборка выйдет с ad-hoc подписью (`tools/mac-adhoc-sign.js`) —
раздавать такой артефакт нельзя, он только для локальной проверки.

## Полное офлайн-издание: четыре шага, последний пропускать нельзя

Порядок ровно такой, как в `build-mac.yml`. Ошибка ровно одна и всегда одна и та же:
остановиться после `electron-builder` и решить, что dmg готов.

1. `npm run fetch:config` — конфиг-пак в `vendor/config-pack/` + штамп коммита.
2. `bash tools/fetch-vendor-mac.sh` — universal-бинари, wheels, Chromium в `vendor/`.
   Он же ставит в `config.json` маркер `offlineEdition:true`.
3. `npx electron-builder --mac --universal --publish never` — с `CSC_LINK`,
   `CSC_KEY_PASSWORD`, `APPLE_API_KEY*`, `APPLE_TEAM_ID` в окружении.
   На выходе **подписанный и нотаризованный `.app`** в `release/mac-universal/`
   и промежуточный dmg **без vendor**.
4. **Финальный dmg собирает `hdiutil`**, а не electron-builder: стейджинг =
   нотаризованный `.app` + папка `vendor` рядом с ним + `ПРОЧТИ…txt` + симлинк
   `/Applications`, затем `hdiutil create -srcfolder` и `codesign` образа Developer ID.

**Почему vendor лежит рядом, а не внутри `.app`.** Нотаризация ругается на неподписанные
Mach-O внутри вложенных архивов (`.so` в `.whl`), поэтому офлайн-ресурсы в бандл не кладут.
`vendorRoot()` в `src/main.js` первым делом ищет сиблинг-папку — то есть корень
смонтированного тома.

**Почему нельзя обойтись `build.dmg.contents`.** `computeAssetSize` (dmg-builder) считает
том только под `.app` плюс 10% — лишние гигабайты vendor дают `ENOSPC`.

**Что будет, если пропустить шаг 4.** `offlineEdition:true` уже стоит, а vendor рядом с `.app`
нет → `vendorBlockInfo()` (`src/main.js`) отдаёт жёсткий стоп, и пользователь упирается в
блокирующий экран ещё до кнопки «Установить», без единого намёка, что виноват способ сборки.

## Что входит в Mac-версию

Ни в одном издании vendor не лежит ВНУТРИ `.app` — только рядом, на томе dmg.

| Издание | Чем собрано | Что рядом с `.app` на томе |
|---|---|---|
| Полное офлайн | `build-mac.yml` | весь `vendor`: конфиг-пак, приложения, wheels, Chromium |
| Лёгкое (lite) | `build-mac-lite.yml` | только `checksums.json`, `uv` (обе арх.) и курс — остальное, включая конфиг, докачивается с S3 |
| Локальное онлайн | `npm run dist:mac` | ничего: всё из сети, конфиг клонируется с GitHub |

Скрипты `scripts/macos/*.sh` ставят компонент из `vendor/`, если он там есть, иначе идут в
прямую загрузку (Homebrew используется только как фолбэк для Claude CLI). Финальный экран
«Что дальше» и выбор паков — те же, что на Windows.

## Как запускать готовый dmg (единственная верная инструкция)

> Открыть `.dmg` и запустить «Hamidun Setup» **двойным кликом прямо в окне образа**.
> **Не перетаскивать в «Программы».**

Причина не в подписи, а в архитектуре: офлайн-vendor лежит в образе **рядом** с приложением.
Перетащил в «Программы» — vendor остался на образе, приложение его не находит и блокирует
установку. Ровно ту же инструкцию даёт сам установщик (стоп-экран «Запусти установщик из
окна DMG», `src/renderer/app.js`), файл `assets/mac/ПРОЧТИ ЕСЛИ ПИШЕТ ПОВРЕЖДЕНО.txt` внутри
образа и сценарий приёмки `docs/TEST-SCENARIO.md` (шаги E1–E3.5).

Любая формулировка вида «перетащи в Программы, потом `xattr -cr /Applications/…`» —
устаревшая: она приводит пользователя ровно к тому стоп-экрану, от которого он и пришёл.

**Остаточный случай.** Если macOS всё же запустила приложение из карантинной копии
(App Translocation — путь вида `/private/var/folders/…/AppTranslocation/…`), сиблинг-vendor
отрывается. Приложение это определяет само и показывает стоп-экран с кнопкой «Исправить
автоматически»: она отмонтирует образ, снимет карантин **с самого `.dmg`** и откроет его
заново. Ручной фолбэк — та же одна строка из `ПРОЧТИ…txt`. Ключевое отличие от старой
инструкции: карантин снимается с **образа**, а приложение остаётся в образе.

## Подпись и нотаризация — включены

Apple Developer ID подключён, `package.json` → `build.mac` несёт `hardenedRuntime: true`,
`notarize: true` и entitlements; `tools/mac-adhoc-sign.js` сам отключается, когда в окружении
есть `CSC_LINK`. Оба mac-workflow'а подписывают и нотаризуют.

Нотаризован и застейплен **`.app`**. Сам dmg только подписан Developer ID — нотаризовать его
нельзя, внутри офлайн-vendor, на котором notary споткнётся. Пользователю этого не видно:
staple на `.app` снимает диалог «приложение повреждено».

Что для этого понадобилось и какие секреты лежат в репозитории — [MAC-SIGNING.md](MAC-SIGNING.md).
