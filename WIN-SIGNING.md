# Подпись Windows

С 05.10.2026 установщики Windows подписаны код-сертификатом Certum:
**CN=Zhemal Khamidun**, издатель Certum Code Signing 2021 CA, действует до
05.10.2027, отпечаток SHA-1 `0D519A2C48DF89680D004A0FA09F449573E9689F`.

Что это меняет у пользователя:

- в окне UAC вместо жёлтого «Издатель: неизвестно» — «Проверенный издатель:
  Zhemal Khamidun»;
- SmartScreen видит издателя. Репутация у нового сертификата копится по мере
  скачиваний, поэтому первое время синий экран «Windows защитила ваш компьютер»
  ещё может появляться — но уже с именем издателя, а не «неизвестный».

## Как устроено

Файла `.pfx` у сертификата нет и не будет: по правилам CA/Browser Forum
закрытый ключ живёт в облачном HSM Certum. До него signtool добирается через
**SimplySign Desktop** — программу, которая изображает смарт-карту. Отсюда два
ограничения:

- подписать можно только на машине, где SimplySign Desktop установлен и в него
  выполнен вход. Сессия держится около двух часов;
- на CI подписи нет (Certum обещает поддержку CI/CD в 2027). Windows-сборка
  и так локальная, это ничего не ломает.

Вход без телефона и без кликов по трею:

```
python ~/.claude/tools/simplysign_connect.py          # войти, если сессии нет
python ~/.claude/tools/simplysign_connect.py --status # когда был вход
python ~/.claude/tools/simplysign_connect.py --close  # отключиться
```

Коннектор берёт одноразовый код из `~/.claude/tools/simplysign_totp.py` (сид
TOTP — в `~/.claude/.credentials.master.env`, ключи `CERTUM_SIMPLYSIGN_*`) и
запускает `SimplySignDesktop.exe /autologin <почта> <код>`. Успех читает из
журнала программы: `Документы\SimplySignLog\SimplySign_<дата>_log.txt`.

## Подпись при сборке

`package.json` → `build.win.signtoolOptions.sign` = `tools/sign-win.js`.
electron-builder отдаёт хуку каждый исполняемый файл сборки, а хук подписывает
**ровно три своих файла по списку**: exe приложения (`Hamidun Setup.exe` прямо в
`win-*unpacked`), `elevate.exe` прямо в `resources` и итоговый portable
(`Hamidun-Setup-Windows[-Lite].exe`). Всё остальное пропускается со строкой в логе,
в том числе все .exe из `resources\vendor` (вшитые установщики Git, VS Code, Cursor,
Python, Handy, а также uv и скрепка): их SHA-256 закреплён в `vendor\checksums.json`,
и после подписи `Confirm-HmArtifact` останавливал бы установку каждого из них как
«файл подменён». Подписи самих вендоров остаются нетронутыми. Раньше хук держал
чёрный список по пути; при смене раскладки он молча подписал бы вендорский файл,
поэтому теперь работает список (`isOwn` в `tools/sign-win.js`), а имена из него
сверяет тест с `package.json`. Хук:

1. один раз за сборку входит через коннектор;
2. подписывает: `signtool sign /sha1 <отпечаток> /fd sha256 /tr http://time.certum.pl /td sha256`,
   при сбое повторяет, третья попытка — через запасной TSA DigiCert;
3. проверяет `signtool verify /pa`. Не подписалось — сборка падает.

Переключатели:

| Переменная | Что делает |
|---|---|
| `HM_WIN_SIGN=0` | собрать без подписи осознанно (пишется в лог) |
| `HM_WIN_SIGN=1` | подписывать даже на CI или не на Windows |
| `HM_WIN_CERT_SHA1` | другой отпечаток — после перевыпуска сертификата |
| `HM_SIGNTOOL` | путь к signtool.exe, если Windows SDK стоит не там |
| `HM_SIMPLYSIGN_CONNECT` | своя команда входа вместо коннектора |

## Проверки после сборки

Хук подписи в CI, не на Windows и при `HM_WIN_SIGN=0` пропускает подпись, а
electron-builder всё равно рапортует успех. Поэтому `npm run dist`, `dist:win` и
Windows-ветка `build-lite.js` заканчиваются тремя независимыми проверками, и любая
красная останавливает сборку:

1. `tools/verify-fuses.js` читает готовый exe побайтно и требует выключенные
   `RunAsNode`, `EnableNodeOptionsEnvironmentVariable` и
   `EnableNodeCliInspectArguments` (иначе процесс того же пользователя превратил бы
   подписанный exe с правами администратора в Node-интерпретатор);
2. `tools/verify-packed-vendor.js` сверяет упакованный `vendor` с `checksums.json`
   (код 0 — проверен хотя бы один файл и дефектов нет; 1 — расхождение, запись без
   хеша или пропавший обязательный файл; 2 — проверять нечего: пустого зелёного нет);
3. `tools/verify-signature.js`, последним: три своих файла имеют `Status = Valid`,
   отпечаток подписанта равен `CERT_SHA1` и есть метка времени. Пропуск только по
   `HM_WIN_SIGN=0` и громко («ПРОПУЩЕНО…»); CI и не-Windows без этого флага не пропускают.

`npm run dist` и `dist:win` зовут фетчер как `fetch:vendor -- -Release`: релизная
сборка без личного списка паттернов экспорт-фильтра Nomad останавливается так же, как
в CI (подробности: `docs/specs/obsluzhivanie-vendor.md`, пункт 17).

## Подписать готовый файл

```
python ~/.claude/tools/simplysign_connect.py
signtool sign /sha1 0D519A2C48DF89680D004A0FA09F449573E9689F /fd sha256 /tr http://time.certum.pl /td sha256 <файл.exe>
signtool verify /pa <файл.exe>
```

Подпись дописывается в конец файла и меняет только поля подписи в PE-заголовке
— проверено побайтово на обоих установщиках 05.10. Проверку целостности NSIS
она не ломает: подписанный и неподписанный Lite запускаются одинаково.

## Публикация

`tools/publish-dist.py` не выложит exe, если Windows не считает его подпись
действительной (`Get-AuthenticodeSignature` = Valid) или он подписан не нашим
сертификатом (то же проверяет `verify-signature.js` ещё на сборке, публикация
страхует второй раз). Выложить без подписи можно только осознанно — флагом
`--allow-unsigned`, и это видно в логе.

## Нельзя

- **Нажимать «Remove Certificate» в SimplySign Desktop.** Ключ удаляется
  безвозвратно, восстановить сертификат нельзя.
- Превышать 5000 подписей в месяц: Certum может заблокировать продукт до конца
  месяца. Сборка тратит три подписи.

## Перевыпуск (до 05.10.2027)

Если продлевать на ту же почту (`hamidunjemal@gmail.com`), новый сертификат сам
появится в той же учётке SimplySign. Поменяется отпечаток: обновить
`CERT_SHA1` в `tools/sign-win.js` (его же читает `publish-dist.py`). Новый
вход в приложение не нужен, если не меняли телефон или сид.

Потеряли доступ или сид утёк: панель SSLmentor → Order Details → SimplySign
APP → новая активация. Старый сид после этого не работает.
