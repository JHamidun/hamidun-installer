# Hamidun Setup

Установщик «в один клик» для полностью настроенного окружения Claude Code.
Галочками выбираешь компоненты → жмёшь «Установить» → на чистой машине появляется рабочий Cursor + Claude Code + конфиг Жемала.

Electron-приложение. Один продукт → две сборки: `Hamidun-Setup-Windows.exe` и `Hamidun-Setup-Mac.dmg`. Это **онлайн-установщик** (бутстрэппер): компоненты качаются с официальных источников на лету, поэтому сам установщик лёгкий и всегда ставит свежие версии.

## Компоненты (галочки)

| Группа | Компонент | Что делает |
|---|---|---|
| Редактор и Claude Code | Git, Node.js, Cursor, Claude Code CLI, Расширение Claude Code | базовый стек |
| Конфиг Жемала | Конфиг (.claude), Python-пакеты | клон [claude-code-config-pack](https://github.com/JHamidun/claude-code-config-pack) + зависимости |
| Живой помощник | Скрепка Claude (маскот) | 3D-скрепка поверх окон + кнопки разрешений (Windows) |

Зависимости разрешаются автоматически: «Конфиг» включает Git+Node, «Расширение» — Cursor, «Python-пакеты» — Конфиг.

## Разработка

```bash
cd C:\Vibecode\hamidun-installer
npm install
npm start            # запустить GUI локально
```

## Сборка дистрибутивов

```bash
npm run dist:win        # ПОЛНЫЙ ОФЛАЙН: тянет конфиг + всё ПО в vendor/ и вшивает (~1,4 ГБ exe)
npm run dist:win:lite   # ЛЁГКОЕ: вшиты uv, курс и checksums — остальное качается (~85 МБ)
npm run dist:mac        # macOS .dmg ОНЛАЙН-издание: НИЧЕГО не вшито, всё ставится из сети
npm run dist:mac:lite   # macOS лёгкое издание — только на маке, финальный dmg собирает CI
```

Windows-сборка даёт один файл `release/Hamidun-Setup-Windows.exe` — portable, сам запрашивает
админа. Lite-вариант — `release/Hamidun-Setup-Windows-Lite.exe`.

**Что именно вшито в lite** (`tools/build-lite.js`, списки `LITE_KEEP_WIN` / `LITE_KEEP_MAC`):
`checksums.json` (второй fail-closed гейт для докачек), `apps/uv` (uv не докачивается ниоткуда —
он bundled-only) и `course/vibecoding-course.zip`. **Конфиг в lite НЕ вшит** — он едет обычным
докачиваемым компонентом `config` из `remote-components.json`, вместе с Git, Node, Cursor,
VS Code, Claude CLI, скрепкой и Python-пакетами. Так что «вшит только конфиг» — это ровно
наоборот: конфиг единственное, чего в lite нет.

Полностью офлайновый **mac**-.dmg собирается **только на macOS-раннере** workflow'ом
`.github/workflows/build-mac.yml`, и `electron-builder --mac` там — не последний шаг, а
предпоследний. Он выдаёт подписанный и нотаризованный `.app` плюс промежуточный dmg **без
vendor**: офлайн-ресурсы внутрь бандла не кладут (нотаризация спотыкается о неподписанные
`.so` внутри вшитых `.whl`), поэтому vendor едет в образе **рядом** с `.app`, сиблингом.
Финальный shippable dmg собирает отдельный шаг `hdiutil` со стейджингом `.app` + `vendor` +
ярлык `/Applications`. Пропустишь его — получишь кирпич: `fetch-vendor-mac.sh` ставит в
`config.json` маркер `offlineEdition:true`, по которому приложение требует vendor рядом, а
рядом его нет → жёсткий стоп ещё до кнопки «Установить». Полный рецепт — в
[MAC-BUILD.md](MAC-BUILD.md); руками локально его не воспроизводят.
`dist:mac` `fetch-vendor-mac.sh` не запускает → выходит онлайн-издание (отсутствие vendor для
него норма, мягкое предупреждение вместо стопа). Учти: в mac-артефакт `vendor/` не попадает
вообще ни по какому пути — `extraResources` с `vendor` есть только у `build.win`. Поэтому
`dist:mac` не вшивает и конфиг, хотя `fetch:config` в цепочке есть: пак оседает в `vendor/`
на машине сборщика и там же остаётся. При установке `scripts/macos/config.sh` не найдёт
`HM_BUNDLED_CONFIG` и склонирует пак с GitHub.

Из-за сиблинг-vendor'а у Mac-версии всего один правильный сценарий запуска —
см. «[Как запускать Mac-версию](#как-запускать-mac-версию)» ниже.

**Офлайн-сборка** (`dist:win`; на macOS — `tools/fetch-vendor-mac.sh`) перед упаковкой качает в `vendor/`:
- `config-pack/` — свежий конфиг с GitHub (`tools/fetch-config.js`);
- `apps/` — установщики Git, Node, Cursor, Python 3.12 + скрепка (`claude-mascot/claude-mascot.exe`);
- `npm-cache/` — Claude Code CLI для офлайн `npm i -g`;
- `pywheels/` — Python-библиотеки (cp312 / win_amd64);
- `playwright-browsers/` — Chromium.

Скрипты ставят компонент из `vendor/`, если он там есть (офлайн), иначе winget/прямая загрузка (онлайн-фолбэк). Обновление версий = пересборка (`tools/fetch-*` тянут свежее).

### Размеры компонентов (после каждого `fetch:vendor`)

```bash
npm run sizes          # пересчитать размеры по РЕАЛЬНОМУ vendor и записать в components.json
npm run sizes:check    # ничего не писать; разошлось → exit 1 (для CI и pre-release)
```

Цифра, которую видит человек на карточке и в окне «Что попадёт на мой ПК», — это **вес
дистрибутива компонента внутри установщика**, а не место на диске после установки.
Руками её больше не пишут: поле `sizeHint` удалено, число живёт в `components.json` как
`sizeBytes.<платформа>` и считается `tools/sync-sizes.js` по содержимому `vendor/`.
Обновил vendor — прогони `npm run sizes`, иначе тест `размеры: … сходятся с vendor` упадёт.

Поле **платформенное**: один компонент едет разными артефактами (VS Code — 221,6 МиБ
`setup.exe` на Windows против 520 МиБ `.zip` на macOS), поэтому числа для macOS появляются
только после запуска `node tools/sync-sizes.js` **на маке** (после `tools/fetch-vendor-mac.sh`).
Без измерения число не подставляется вовсе — компонент показывает пометку `sizeNote`
(«скачивается во время установки» и т. п.), но не выдуманные мегабайты.

## Как запускать Mac-версию

Единственная верная инструкция. Она одна и та же в этом файле, в
[MAC-BUILD.md](MAC-BUILD.md), в [MAC-SIGNING.md](MAC-SIGNING.md), в
[docs/bridge-bot-spec.md](docs/bridge-bot-spec.md), в файле внутри dmg и в самом установщике:

> Открыть `.dmg` и запустить «Hamidun Setup» **двойным кликом прямо в окне образа**.
> **Не перетаскивать в «Программы»** — офлайн-файлы лежат в образе рядом с приложением,
> из «Программ» оно их не найдёт и заблокирует установку.

Это требование не про Gatekeeper: сборки подписаны Developer ID и нотаризованы, диалог
«приложение повреждено» ушёл. Дело в архитектуре — vendor не влезает внутрь `.app`, потому
что нотаризация спотыкается о неподписанные Mach-O во вложенных архивах.

Если macOS всё-таки запустила приложение из карантинной копии (App Translocation), оно само
покажет стоп-экран «Запусти установщик из окна DMG» с кнопкой «Исправить автоматически»:
та отмонтирует образ, снимет карантин **с `.dmg`** и откроет его заново. Ручной фолбэк —
однострочная команда из `assets/mac/ПРОЧТИ ЕСЛИ ПИШЕТ ПОВРЕЖДЕНО.txt`, она тоже снимает
карантин с образа, а не с приложения.

Формулировки в духе «перетащи в Программы, потом `xattr -cr "/Applications/…"`» —
устаревшие и ведут к кирпичу. Встретил такую в доке, у бота или в поддержке — это баг.

## Архитектура

- `src/main.js` — главный процесс: читает `config.json`/`components.json`, по IPC запускает скрипт компонента (`scripts/<os>/<id>.ps1|sh`), стримит вывод в UI.
- `src/preload.js` — безопасный мост (contextIsolation, без nodeIntegration).
- `src/renderer/` — UI в брендовой палитре Hamidun Academy (тёмно-синий, Inter Tight / Manrope / JetBrains Mono).
- `scripts/windows/*.ps1`, `scripts/macos/*.sh` — идемпотентные установщики, передача параметров через env `HM_*`.
- `server/` — референс enroll-сервиса «AI-моста» (SSH), см. `server/README.md`.
- `config.json` — параметры (URL конфиг-репо, bridge-эндпоинт, id расширения).

## AI-мост (SSH)

`config.json` → `bridge.enrollEndpoint` пока пуст — агент моста мягко простаивает, пока бот не выдаст доступ. Серверная часть: `server/enroll-ssh-server.js` (см. `server/README.md` и `docs/bridge-bot-spec.md`). Когда купишь сервер: подними сервис, впиши адрес, пересобери.

## Что НЕ автоматизируется

- **Вход в Claude Code** — каждый пользователь логинится в свою подписку Max/Pro (интерактивно, первый запуск). Установщик в конце предлагает запустить вход.

## Подпись кода: mac подписан, Windows пока нет

Платформы разъехались, и путать их дорого.

- **macOS — подписано и нотаризовано.** `package.json` → `build.mac` несёт
  `hardenedRuntime: true`, `notarize: true` и entitlements; оба mac-workflow'а
  (`build-mac.yml`, `build-mac-lite.yml`) подписывают Developer ID (`CSC_LINK`) и нотаризуют
  через `notarytool` с App Store Connect API-ключом, а потом делают staple. Нотаризован и
  застейплен именно `.app`; финальный dmg подписан Developer ID, но сам не нотаризуется —
  внутри него офлайн-vendor, на котором notary споткнулся бы. Диалога «приложение повреждено»
  и команд `xattr` для обычного пользователя больше нет.
- **Windows — НЕ подписано.** Сертификат Certum висит у удостоверяющего центра с 17 августа
  (`CA has sent the inquiry about the order`, см. [docs/SESSION-AUDIT.md](docs/SESSION-AUDIT.md)).
  Новичок видит SmartScreen «Windows защитила компьютер» → *Подробнее → Выполнить в любом
  случае*. Мы это объясняем, а не обходим. Детали и варианты — [WIN-SIGNING.md](WIN-SIGNING.md).

Подпись не отменяет правило запуска из окна dmg — оно про другое, см.
«[Как запускать Mac-версию](#как-запускать-mac-версию)» выше.

## Заметка по безопасности

`src/renderer/app.js` использует `innerHTML` только для данных из bundled `components.json` (доверенный источник). Пользовательский ввод — только инвайт-код, он идёт в `value`, не в разметку. XSS-вектора нет.
