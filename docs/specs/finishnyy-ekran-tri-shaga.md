- **Код:** `src/renderer/app.js:2022-2463`, `src/renderer/app.js:1911-1964`, `src/renderer/app.js:142-154`, `src/renderer/index.html:186-190`, `src/renderer/styles.css:269-289`, `src/renderer/finish-link.js`, `src/main.js:1880-1946`, `src/main.js:1765-1878`, `config.json`

## Что обещает человеку

Когда установка закончилась, человек не остаётся один на один со списком галочек. Экран говорит ровно три следующих действия — открыть редактор, написать первый запрос по-русски, спросить бота, если застрял, — и даёт одну заметную кнопку, которая эти три действия начинает: «▶ Открыть VS Code — начать здесь».

Позицией эта кнопка при этом не выделена. В шаблоне (`app.js:2274-2306`) выше неё идут блок «доступ к нейросети» (`app.js:2282`, собирается на `2235-2246` и пустым не бывает), блок курса (`app.js:2283`, при установленном курсе), чеклист проверки установки (`app.js:2284`, при непустом `checks`) и блоки провалов (`app.js:2285-2286`) — сама кнопка стоит минимум четвёртым блоком сверху (`app.js:2287-2293`). Ниже неё остаются только «Ещё инструменты» (`app.js:2295`) и поле ключей (`app.js:2305`). Переупорядочивания стилями нет: в `src/renderer/styles.css` не встречается ни `order:`, ни `column-reverse`/`row-reverse`, а `.next-steps` (`styles.css:270`) — обычный блок-контейнер со скроллом (`max-height: 46vh; overflow-y: auto`), так что кнопка может оказаться за пределами видимой области. Текст первого шага сам отсылает к ней словами «синяя кнопка ниже» (`app.js:2278`), а выделяет её только стиль `.btn-sm.ns-main` (`styles.css:284-288`).

Второе обещание — экран не врёт про доступность первого шага. Если редактор не установился, первый шаг подменяется на «Сначала доустанови редактор», а главная кнопка гасится и меняет подпись, вместо того чтобы предлагать нажать то, что ничего не откроет.

## Как работает

1. Прогон завершается — `finishInstall(res)` (`src/renderer/app.js:1911`) считает исход (`okAll` по `failed`, `depSkipped` и красным крестикам чеклиста), пишет заголовок в `#progress-title` / `#progress-sub`, меняет маскота, вызывает `renderNextSteps(...)` и снимает `hidden` с `#btn-finish`.
2. `renderNextSteps(failed, depSkipped, gracefulSkipped, checkFailed, fetchFailed, integrityFailed)` (`app.js:2022`) собирает **весь** HTML секции `#next-steps` одной строкой и присваивает её в `ns.innerHTML` (`app.js:2274`), затем снимает `hidden` (`app.js:2307`) и вешает обработчики на свежие узлы (`app.js:2310-2462`).
3. Ядро фичи — заголовок `<div class="ns-title">Что дальше — три простых шага</div>` и список `<ol class="ns-steps">` ровно из трёх `<li>` (`app.js:2275-2281`):
   - **шаг 1** — ветвление по `editorMissing`;
   - **шаг 2** — постоянный текст «Напиши первый запрос в панели Claude»;
   - **шаг 3** — переменная `step3` (`app.js:2186-2188`).
4. **Ветвление первого шага.** `const editorMissing = failed.includes('vscode')` (`app.js:2078`), имя берётся из `STATE.byId['vscode'].name` с фолбэком `'VS Code'` (`app.js:2079-2081`).
   - `editorMissing === false` → «**Открой VS Code** — синяя кнопка ниже…» и кнопка `<button id="ns-vscode" class="btn-sm primary ns-main">▶ Открыть VS Code — начать здесь</button>` (`app.js:2290`).
   - `editorMissing === true` → «**Сначала доустанови редактор** — <имя> не установился…» и кнопка `<button id="ns-vscode" class="btn-sm ns-main" disabled title="…">▶ Открыть VS Code — сначала доустанови редактор</button>` (`app.js:2277`, `app.js:2289`). Класс `primary` в этой ветке не ставится — кнопка теряет синюю заливку.
5. **Ветвление третьего шага.** `botUrl` строится чистой логикой из `src/renderer/finish-link.js`: `botStartPayload(failed, isWin, fin.botStartPayload || 'installed')` даёт `installed_win|installed_mac` при пустом `failed` и `failed_<первый-id>_win|_mac` иначе; `botUrl(links.bot || '', payload)` возвращает пустую строку, если в конфиге нет ссылки на бота. Есть `botUrl` → третий шаг зовёт бота-помощника; нет → «открой памятку „Что дальше“ ниже» (`app.js:2186-2188`).
6. **Главная кнопка.** Обработчик вешается безусловно (`app.js:2329-2346`): `ok = await window.installer.launchVsCode()`; при truthy — `sendOpenEditorTelemetry()`; при falsy — в родителя дописывается блок `.ns-vscode-err` с текстом «VS Code не открылся — похоже, он не установлен в этой сборке…» (дедуп по поиску существующего узла). Ссылка `#ns-cursor` в этом тексте упоминается только если `cursorSelected`.
7. **IPC-сторона.** `launch-vscode` → `launchVsCodeOn(~/HamidunStart)` (`src/main.js:1946`; сама функция объявлена на `1887` и занимает `1887-1944`). Windows: `Code.exe` из `%LOCALAPPDATA%\Programs\Microsoft VS Code` или Program Files → `winLaunchDeElevated`; нет VS Code → `Cursor.exe`; нет и его → `explorer.exe <папка>` с возвратом строки `'explorer'`. macOS: `open -a "Visual Studio Code"` → `open -a Cursor` → `open <папка>` с возвратом `'finder'`. `winLaunchDeElevated` (`src/main.js:1765-1878`) при недоступности `powershell.exe`/`schtasks.exe`/`whoami.exe` (`src/main.js:1786`) или незапертом staging-каталоге (`src/main.js:1791`) уходит в `folderFallback()` (`src/main.js:1768-1777`) и отдаёт его результат — `true` при наличии `folderArg` и `explorer.exe`, иначе `false`.
8. **Кнопка «Готово».** Обработчик `#btn-finish` (`app.js:142-154`): если чекбокс `#ns-autovscode` отмечен (дефолт — `finish.autoOpenCursorDefault`, в `config.json` = `true`), сначала `launchVsCode()`; успех → телеметрия и выход; провал → `$('#ns-vscode').click()` и `return` без `quit()`, чтобы окно не исчезло молча. Чекбокс не отмечен → сразу `window.installer.quit()`.
9. **Повтор.** `retryFailed(ids)` (`app.js:1891`) перед новым прогоном прячет `#next-steps` и `#btn-finish`, а по завершении снова зовёт `finishInstall` — экран пересобирается целиком.

Платформенных веток внутри текстов трёх шагов нет: `isWin` объявлен на `app.js:2032` и используется в функции только дважды — для разделителя и вида пути к файлу ключей (`app.js:2036-2037`) и для payload бота (`app.js:2095`).

## Инварианты

1. **Шагов ровно три, всегда.** Список `<ol class="ns-steps">` собирается из трёх `<li>`, ни один из которых не может схлопнуться в пустую строку: первый — тернарник по `editorMissing`, второй — литерал, третий — переменная `step3`, у которой обе ветки непустые (`app.js:2186-2188`, `2276-2281`).
2. **Текст первого шага и состояние главной кнопки решаются ОДНИМ условием.** Обе ветки читают одну и ту же `editorMissing` (`app.js:2078`, использована в `2277` и `2288`) — «доустанови редактор» в списке и `disabled` на кнопке не могут разойтись.
3. **`#ns-vscode` присутствует в DOM в обеих ветках.** В обеих ветках рендерится кнопка с этим id (`app.js:2289-2290`), а обработчик на `app.js:2329-2330` берёт её без null-проверки.
4. **Экран пересобирается целиком, обработчики не дублируются.** Секция получает новое содержимое через `ns.innerHTML = ...` (`app.js:2274`), после чего слушатели вешаются на новые узлы; повторные финиши после «Повторить неустановленное» проходят тот же путь (`app.js:1891-1909`).
5. **Финиш недоступен, пока идёт прогон.** `#btn-finish` в разметке создан с классом `hidden` (`src/renderer/index.html:190`), снимается только в конце `finishInstall` (`app.js:1963`) и возвращается обратно в `retryFailed` (`app.js:1900`).
6. **`open_editor` не уходит без truthy-ответа от запуска редактора.** Мест вызова `sendOpenEditorTelemetry` три — столько же названо и в комментарии рядом с функцией (`app.js:2010-2011`): главная кнопка (`app.js:2333`, под `if (ok)` от `launchVsCode`), «Готово» (`app.js:147`, там же) и «Открыть Cursor» (`app.js:2436`, под `if (ok)` от `launchCursor`). Ни одно из трёх не шлёт событие без truthy-ответа. Сам `sendOpenEditorTelemetry` защёлкивается флагом `STATE.telemetryEditorSent` (`app.js:2014-2015`), но защёлка — **на всю сессию окна, а не на прогон**: присваивания `false` этому флагу нет нигде в `app.js`, а `startInstall` перед новым прогоном обнуляет только `telemetrySent` и `telemetryStartSent` (`app.js:1873-1874`). Следствие обратное «на прогон»: второй полный прогон установки уже никогда не пришлёт `open_editor`, даже если редактор открыли впервые.
7. **Ссылка на бота строится только через `HMFinishLink`.** `app.js:2095-2096` не собирает URL руками; в `finish-link.js` payload санитизируется под `[A-Za-z0-9_-]`, клампится до 64 символов, а платформенный суффикс дописывается ПОСЛЕ клампа и потому не срезается.
8. **Кнопка Cursor не подменяет собой первый шаг.** Она рендерится только при `cursorSelected` и только внутри `<details>` «Ещё инструменты» (`app.js:2034`, `2298`), в трёх шагах не участвует.

## Что ломается, если инвариант нарушить

1. **Шагов не три.** Заголовок обещает «три простых шага», а список короче или длиннее — экран противоречит сам себе на первом же экране после установки; человек, которому этот список и есть вся инструкция, теряет либо шаг «открой редактор», либо шаг «спроси бота», то есть либо не начинает работу, либо не знает, куда идти за помощью.
2. **Текст и кнопка разошлись.** Возвращается ровно та поломка, ради которой ветка написана (комментарий `app.js:2073-2077`): экран говорит «Открой VS Code — синяя кнопка ниже», человек жмёт активную кнопку, ничего не происходит, и он решает, что сломан установщик, а не что редактора нет на диске.
3. **`#ns-vscode` пропал из разметки.** `$('#ns-vscode').addEventListener` выбросит `TypeError` на `null` — и всё, что вешается ПОСЛЕ него (сохранение ключа Nomad, кнопка курса, «Показать файл ключей», лог, памятка, `data-ext`-ссылки, «Повторить неустановленное»), не подключится вовсе. Финишный экран отрисуется, но по кликам умрёт всё, что вешается ниже `app.js:2330`. Уцелеет ровно одна кнопка — «Запустить Claude в терминале»: её обработчик вешается раньше (`app.js:2310-2311`), как и сам рендер разметки со снятием `hidden` (`app.js:2274`, `2307`).
4. **Обработчики продублировались.** После второго-третьего «Повторить неустановленное» один клик по «Открыть VS Code» откроет редактор несколько раз и пошлёт несколько событий; воронка посчитает одного человека за нескольких (защёлка `telemetryEditorSent` частично это гасит, но окна редактора — нет).
5. **Финиш виден во время прогона.** Человек нажмёт «Готово» на середине установки, окно закроется, часть компонентов останется недоустановленной — и он будет уверен, что установка завершилась успешно.
6. **`open_editor` шлётся без запуска редактора.** Бот-спутник считает, что человек пошёл работать, и перестаёт вести его по установке — молчит ровно тому, кто застрял.
7. **Payload собран мимо `HMFinishLink`.** Telegram обрежет `?start=` по 64 символам или отвергнет параметр с посторонними символами: кнопка «Спросить бота» откроет бота без контекста, и тот поздоровается как с новым пользователем вместо того, чтобы разбирать конкретную неудачу.
8. **Cursor подставлен как первый шаг.** Кнопка рисуется по факту ВЫБОРА компонента, а не по факту установки (комментарий `app.js:2430-2432`) — человек с невставшим Cursor получил бы «первый шаг» из мёртвой кнопки.

## Границы

- Фича отвечает за **текст трёх шагов и главную кнопку**, а не за весь финишный экран. В той же функции `renderNextSteps` рендерятся блоки, у которых свои спеки: чеклист проверки установки, карточка Nomad и поле ключа, блок курса-симулятора, мини-визард API-ключей, CTA-карточка бота, «Повторить неустановленное», памятка «Что дальше», лог для поддержки.
- Экран не проверяет, что редактор **работает**: `editorMissing` (`app.js:2078`) считается только по списку `failed` текущего прогона, а факт запуска берётся из ответа IPC `launch-vscode`. Детекция на экране при этом есть — она просто не спрашивается про редактор: `STATE.detected` заполняется из IPC `detect-state` (`app.js:224`), хендлер которого (`src/main.js:2758-2792`) отдаёт запись по КАЖДОМУ не-скрытому компоненту платформы, включая `vscode` (в `components.json` у него нет `hidden`), а `detectComponents` реально детектит и `vscode` (`src/main.js:2582-2594`), и `cursor` (`src/main.js:2574-2580`). В самой `renderNextSteps` `STATE.detected` уже используется — для Nomad (`app.js:2204`) и для курса (`app.js:2260`), но не для редактора.
- Cursor не считается заменой редактора для первого шага: `editorMissing` смотрит только на `vscode`. Человек, снявший VS Code и поставивший Cursor, получит первый шаг про VS Code (у него `failed` пуст, значит ветка «доустанови» не сработает) и главную кнопку, которую на Windows/macOS отрабатывает фолбэк `launchVsCodeOn` → Cursor.
- Имена компонентов (`STATE.byId[i].name`) подставляются в HTML и в атрибут `title` **без экранирования** — осознанная уступка: источник `components.json` считается доверенным конфигом (комментарий `app.js:2056-2061`). Ярлыки чеклиста, приходящие из вывода verify, наоборот, прогоняются через `escapeHtml` (`app.js:2159-2161`).
- Автоматическое открытие редактора по «Готово» — это отдельный чекбокс `#ns-autovscode`, значение по умолчанию берётся из `config.json` → `finish.autoOpenCursorDefault` (имя ключа историческое, поведение — VS Code).

## Риски и открытые вопросы

1. **Ветка `editorMissing` не покрыта тестом.** Оба процитированных теста проверяют только «нормальную» строку кнопки, причём разными регулярками: `test/run-tests.js:1569` — `id="ns-vscode" class="btn-sm primary ns-main"`, `test/run-tests.js:816` — `id="ns-vscode" class="btn-sm primary` (без `ns-main"`, что оговорено в самом assert). Обе матчатся на `app.js:2290` и продолжат матчиться, даже если ветку `editorMissing` (`app.js:2277`, `2289`) удалить целиком. Поиск по `test/run-tests.js` (`grep -a` по `editorMissing`, `доустанови`, `ns-main" disabled`) даёт ноль совпадений. Значит удаление или порча всей ветки «редактор не встал» — вместе с `disabled` и подменённым первым шагом — проходит зелёные тесты.
2. **`editorMissing` считается только по `failed` и не видит graceful skip.** Компонент `vscode` может завершиться кодом 120 («не входит в эту сборку»); тогда он попадает в `gracefulSkipped`, а не в `failed` — развилка в `app.js:1646-1651` (`if (res && res.skipped) { setStep(id,'skipped'); gracefulSkipped.push(id); bad.add(id); … }`), сам `exit 120` — в `scripts/windows/vscode.ps1:59-64` (ветка «офлайн-инсталлятор не вшит И VS Code не установлен»). По адресу `app.js:2088-2090` лежит не маршрутизация, а рендер строки `.ns-note` про пропущенное. Экран покажет обычный первый шаг «Открой VS Code — синяя кнопка ниже» с активной синей кнопкой, хотя редактор не устанавливался. Что `vscode.ps1` действительно так завершается, зафиксировано тестом «vscode.ps1: ставит ОБА расширения; no-vendor → exit 120; идемпотентно; тихая установка; fail-closed».
3. **Страховка «кнопка сама объяснит» на практике почти не срабатывает.** Подсказка `.ns-vscode-err` показывается только при falsy-ответе, а `launchVsCodeOn` при отсутствии любого редактора возвращает **строки** `'explorer'` (Windows, `src/main.js:1918`) и `'finder'` (macOS, `src/main.js:1940`), а `winLaunchDeElevated` в фолбэке отдаёт результат `folderFallback()` (`src/main.js:1768-1777`) — это `true`, если функции передали `folderArg` и на диске нашёлся `explorer.exe`, иначе `false`; в фолбэк она уходит в том числе при недоступности `powershell.exe`/`schtasks.exe`/`whoami.exe` (`src/main.js:1786`) и при незапертом staging-каталоге (`src/main.js:1791`). Renderer проверяет только truthy (`app.js:2332-2334`), поэтому вместо подсказки человек получает открытый Проводник/Finder, а телеметрия шлёт `open_editor: ok = true`, хотя редактор не открывался. То же в `#btn-finish` (`app.js:146-147`).
4. **`.click()` по `disabled`-кнопке — no-op.** В ветке `editorMissing` фолбэк «Готово» (`app.js:151`: `const cta = $('#ns-vscode'); if (cta) cta.click(); return;`) не может ничего показать: браузер не диспатчит click на отключённой кнопке, а `return` уже отменил `quit()`. Если `launchVsCode` вернёт falsy при отмеченном чекбоксе (см. п. 3 — путь редкий, но существует: не-директория `~/HamidunStart`, исключение в spawn), нажатие «Готово» не сделает **ничего видимого**: окно не закроется и подсказки не появится.
5. **Совет в ветке `editorMissing` — только для Windows.** Текст предлагает «запусти его правым кликом → «Запуск от имени администратора»» (`app.js:2277`) без платформенной развилки, хотя `isWin` в этой же функции уже вычислен (`app.js:2032`). На macOS совет неисполним.
6. **У `.btn-sm` нет стиля `:disabled`.** В `src/renderer/styles.css` есть `.btn:disabled` (219), `.step .step-retry:disabled` (249), `.card.disabled` (122) — но не `.btn-sm:disabled`. Погашенная главная кнопка отличается от активной только отсутствием класса `primary` и подписью; курсор и прозрачность не меняются, а `.btn-sm:hover` (278-279) продолжает подсвечивать её рамку при наведении.
7. **Открытый вопрос: связка «редактор не встал» и Cursor.** При упавшем `vscode` и успешно установленном Cursor первый шаг зовёт доустанавливать VS Code, хотя рабочий редактор у человека уже есть, а кнопка «Открыть Cursor» спрятана в свёрнутом `<details>`. Кодом это поведение подтверждается (`app.js:2078`, `2298`); намеренное оно или нет — по коду и комментариям не определяется.
