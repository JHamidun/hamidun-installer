## Что обещает человеку

Тому, кто уже привык к Cursor, установщик даёт поставить его тем же одним нажатием, что и всё остальное, — и при этом не навязывает Cursor новичку. Карточка «Cursor — редактор (опционально)» приходит со снятой галочкой (`components.json:56`), а рекомендованным редактором остаётся VS Code. Текст карточки честно предупреждает о двух вещах, из-за которых Cursor и убран из умолчания: «на старте может попросить оплатить подписку и иногда недоступен из России» (`components.json:55`).

Кто галочку поставил — получает установленный Cursor, панель Claude Code внутри него (Windows: `scripts/windows/extension.ps1`; macOS: `scripts/macos/extension.sh`), стартовый `settings.json` с автосохранением и шрифтом JetBrains Mono, если своего ещё нет, и кнопку «Открыть Cursor» на финальном экране. Оба редактора уживаются на одной машине: ни один из них не требует другого (`components.json:57`, `components.json:43`).

## Как работает

**1. Карточка и выбор.** `src/renderer/app.js:94` заполняет стартовый выбор прямой копией поля `default` (`STATE.selected[c.id] = !!c.default`), поэтому `"default": false` в `components.json:56` — единственный источник «галочка снята». Поля `platforms` у компонента нет, значит платформенный гейт `componentShownOnPlatform` (`src/main.js:601-604`) пропускает карточку и на win32, и на darwin. Поля `recommended` нет — бейджа «рекомендуется» карточка не рисует (`src/renderer/app.js:427` рисует бейдж по `c.recommended`, рядом с бейджем «уже установлено» на `:424`; это единственное вхождение `recommended` в `app.js`).

**2. Автоснятие по детекту.** `src/main.js:2566-2573` ищет Cursor: на Windows — `%LOCALAPPDATA%\Programs\cursor\Cursor.exe`, затем `%ProgramFiles%\cursor\Cursor.exe`; на macOS — `/Applications/Cursor.app`, затем `~/Applications/Cursor.app`. Нашёл — `src/renderer/app.js:230-235` снимает галочку (в обход `disableDependents`, напрямую `STATE.selected[id] = false`), карточка получает бейдж «уже установлено».

**3. Порядок установки.** `src/renderer/deps.js:26-39` — топологическая сортировка по `requires`. У `cursor` зависимостей нет, и `extension` его не требует, поэтому взаимный порядок «cursor раньше extension» держится не графом, а порядком ключей в `components.json` (объект `STATE.selected` заполняется в порядке обхода групп, `src/renderer/app.js:91-99`).

**4. Windows, три ветки (`scripts/windows/cursor.ps1`).** Условие ветвления — наличие вшитого артефакта, затем наличие winget:
- **Офлайн, вшитый:** `$env:HM_VENDOR\apps\cursor-setup.exe` существует (строки 34, 39-42) → `Confirm-HmArtifact $inst` (строка 83) сверяет SHA-256 и размер с `vendor/checksums.json` (`scripts/windows/_verify.ps1:64-106`), затем `Start-Process -FilePath $inst -ArgumentList '/S' -PassThru` (строка 103).
- **winget:** вшитого нет, но `winget` в PATH (строки 43-45) → `winget install -e --id Anysphere.Cursor --silent`. `$inst` остаётся `$null`, поэтому блок проверки подписи (строки 81-104) пропускается целиком.
- **Прямая загрузка:** ни того, ни другого (строки 46-74) → сначала создаётся Admins-only каталог `New-HmSecureStagingDir -Elevated $true` (строка 58); не создался — онлайн-фолбэк прерывается с `exit 1` (строки 60-63). Затем `Invoke-RestMethod` к `https://www.cursor.com/api/download?platform=win32-x64-user&releaseTrack=stable` (TimeoutSec 60) и `Invoke-WebRequest` за `downloadUrl` (TimeoutSec 600). Перед запуском — `Test-HmTrustedSigner -Path $inst` (строка 90); непустой ответ = причина отказа, кэш удаляется, `exit 1` (строки 91-96).

Дальше ветки сходятся: установщик запускается **без** `-Wait` (комментарий строки 78-80 объясняет: он сам стартует Cursor, и `-Wait` подвесил бы шаг), до 180 секунд ждём появления `Cursor.exe` (строка 105), гасим авто-запущенный процесс (строка 107), до ~60 секунд ждём выхода установщика и убираем Admins-only кэш (строки 112-119). Успех объявляется по `Test-Path $cexe` (строка 122), иначе `exit 1` с текстом про «Повторить неустановленное» (строки 123-124).

**5. macOS (`scripts/macos/cursor.sh`).** Веток две: вшитый `$HM_VENDOR/apps/cursor.dmg` (строки 9-10) → `verify_artifact "$DMG"` (строка 27, SHA-256 fail-closed, `scripts/macos/_lib.sh:219-246`); иначе — загрузка `darwin-$(arch_tag)` с таймаутами (строки 12-24), причём протухший `/tmp/cursor.dmg` от прерванного прогона сносится до загрузки (строка 22). Дальше обе ветки одинаковы: `hdiutil attach` в `/tmp/hm_cursor_mnt`, поиск `.app` (пусто → detach + `exit 1`, строки 39-43), и один вызов `admin_run /bin/sh -c "$HM_APP_INSTALL_SH" hm_app_install "$MNT/$APP" "$CURSOR_TEAM_ID" "$APP"` (строка 65). Внутри него под root (`scripts/macos/_lib.sh:319-328`): копия `.app` в root-owned staging, `codesign --verify --deep --strict -R "=anchor apple generic and certificate leaf[subject.OU] = \"$2\""`, `spctl --assess --type execute`, и только потом `cp` в `/Applications`. Team ID запинен: `CURSOR_TEAM_ID='VDXQ22DGB9'` (строка 63).

**6. Лёгкое (стриминговое) издание.** `remote-components.json:105-121` (win32) и `:314-330` (darwin) описывают докачку с двух зеркал, `installRelPath` = `scripts/windows/cursor.ps1` / `scripts/macos/cursor.sh`, ожидаемые SHA-256 артефактов внутри. Вшитый `apps/cursor-setup.exe` имеет приоритет над докачкой (`src/main.js:701-723`), а `cursor` входит в `SCRIPT_ONLINE_FALLBACK` (`src/main.js:742`) — сорванная докачка не роняет компонент жёстко, скрипту дают попробовать свой winget/прямую загрузку.

**7. Панель Claude в Cursor.** На Windows это делает отдельный компонент `extension`: `scripts/windows/extension.ps1` ставит расширение **только** в Cursor (заголовок файла, строки 1-4; в VS Code оба расширения ставит `vscode.ps1`). CLI ищется перебором четырёх путей (строки 155-160), установка идёт через `Invoke-HmDeElevated` (строка 137), факт подтверждается каталогом `~/.cursor/extensions` (`Test-HmExtInstalled`, строки 115-124), а не выводом бинаря. Если Cursor запущен пользователем — скрипт ждёт до 20 секунд и **не** убивает его (строки 95-101); крайняя мера с принудительным закрытием включается только если расширение так и не встало (строки 215-220). На macOS `scripts/macos/extension.sh:64-74` ставит и в Cursor, и в VS Code — в те, чьи CLI нашлись в `/Applications` или `~/Applications`.

**8. Финальный экран.** `src/renderer/app.js:2034` вычисляет `cursorSelected` из выбора компонента, и кнопка «Открыть Cursor» рисуется только при нём (строка 2298), внутри блока «Ещё инструменты». Клик ждёт результата `launchCursor()` и шлёт телеметрию `open_editor` только при `true` (строки 2433-2437). Сам запуск — `ipcMain.handle('launch-cursor')` (`src/main.js:1583-1599`): на Windows через `winLaunchDeElevated(cexe, startDir)`, на macOS через `/usr/bin/open -a Cursor`. Cursor также служит запасным редактором для кнопки «Открыть курс-симулятор», если VS Code не найден (`src/main.js:1894-1904` для Windows, `:1925-1930` для macOS).

## Инварианты

1. **Cursor выключен по умолчанию.** `components.json:56` — `"default": false`; стартовый выбор копирует это поле один в один (`src/renderer/app.js:94`).
2. **Cursor ни от чего не зависит и не является ничьей зависимостью.** `components.json:57` — `"requires": []`; `extension.requires` = `["vscode"]` (`components.json:88-90`); в `components.json` нет ни одного компонента с `cursor` в `requires` (проверено чтением всего файла).
3. **Вшитый установщик не запускается без совпадения SHA-256.** Windows — `Confirm-HmArtifact $inst` (`scripts/windows/cursor.ps1:83` → `scripts/windows/_verify.ps1:64-106`, при несовпадении хеша или размера `exit 1`). macOS — `verify_artifact "$DMG"` (`scripts/macos/cursor.sh:27` → `scripts/macos/_lib.sh:219-246`, `exit 1`).
4. **Онлайн-скачанный установщик Windows не запускается без валидной Authenticode-подписи**, чья цепочка ведёт в `LocalMachine\Root` и у листа есть EKU Code Signing: `Test-HmTrustedSigner -Path $inst` (`scripts/windows/cursor.ps1:90`; реализация `scripts/windows/_deelev.ps1:375-435`). Непустая строка-причина → `exit 1` (строки 91-96).
5. **Онлайн-загрузка Windows идёт только в Admins-only каталог.** `New-HmSecureStagingDir -Elevated $true` (`scripts/windows/cursor.ps1:58`); каталог не создался или не существует → онлайн-фолбэк прерывается `exit 1` (строки 60-63), никакой загрузки в `%TEMP%` нет.
6. **На macOS `.app` попадает в `/Applications` только после крипто-проверки на root-owned копии** — designated requirement с точным Team ID `VDXQ22DGB9` плюс `spctl --assess` (`scripts/macos/cursor.sh:63-69`, `scripts/macos/_lib.sh:319-328`). Это верно для обеих веток: и вшитого dmg, и скачанного. Провал `admin_run` → detach + `exit 1`.
7. **Успех объявляется по факту наличия приложения, а не по коду возврата установщика.** Windows — `Test-Path $cexe` (`scripts/windows/cursor.ps1:105, 122`), не появился за ~180 секунд → `exit 1`. macOS — `[ -d "/Applications/Cursor.app" ]` (`scripts/macos/cursor.sh:72-73`).
8. **Установщик Cursor запускается без `-Wait`, а его авто-запущенный Cursor гасится.** `Start-Process … -PassThru` без `-Wait` (`scripts/windows/cursor.ps1:103`), затем `Get-Process Cursor | Stop-Process -Force` (строка 107).
9. **Уже установленный Cursor не переустанавливается.** `scripts/windows/cursor.ps1:28-31` (при не-dry-run `exit 0`), `scripts/macos/cursor.sh:6` (`exit 0`), плюс автоснятие галочки по детекту (`src/renderer/app.js:230-235`).
10. **Cursor.exe никогда не запускается напрямую из elevated-процесса.** `winLaunchDeElevated(cexe, startDir)` в `ipcMain.handle('launch-cursor')` (`src/main.js:1583-1599`) и в фолбэке курс-лаунчера (`src/main.js:1900-1904`).
11. **Кнопка «Открыть Cursor» существует только при выбранном компоненте, а телеметрия — только при реально открытом окне.** `cursorSelected` (`src/renderer/app.js:2034`, `:2298`); `if (ok) sendOpenEditorTelemetry()` после `await launchCursor()` (`:2433-2437`).
12. **Установка расширения в Cursor идёт де-элевированно, а факт подтверждается файловой системой, не выводом бинаря.** `Invoke-HmDeElevated $cli @('--install-extension', …)` (`scripts/windows/extension.ps1:137`), `Test-HmExtInstalled` по `~/.cursor/extensions` (`:115-124`); при недоступной де-элевации — `DeElevFailed`, запуска под админом нет (`:138-141`).
13. **Запущенный пользователем Cursor не убивается ради установки расширения по умолчанию.** `scripts/windows/extension.ps1:95-101` — предупреждение и ожидание до 20 секунд; принудительное закрытие только как крайняя мера, если расширение не встало (`:215-220`).
14. **Отсутствие Cursor не превращает шаг «Расширение» в провал.** `scripts/windows/extension.ps1:224-227` — `exit 0` с объяснением.

## Что ломается, если инвариант нарушить

1. **Cursor включён по умолчанию** — новичок, который про Cursor не спрашивал, получает редактор, требующий подписки и не всегда открывающийся из России; при первом запуске он упирается в платёжный экран вместо работы. Ровно этого убегает текст `components.json:55`.
2. **Появилась взаимная зависимость с VS Code** — снятие одной галочки молча снимает вторую (`disableDependents`, `src/renderer/deps.js:15-23`), и человек, снявший Cursor, теряет рекомендованный редактор вместе с панелью Claude.
3. **Нет SHA-гейта на вшитом файле** — установщик Cursor размером ~200 МБ, подменённый в дистрибутиве или битый после копирования на флешку, запускается с правами администратора. Для пользователя это либо тихо сломанная установка, либо чужой код под админом.
4. **Нет гейта подписи на онлайн-пути** — процесс того же пользователя средней целостности подменяет скачанный `.exe` между загрузкой и запуском, и подмена исполняется уже под администратором.
5. **Загрузка в `%TEMP%`** — тот же сценарий подмены, но без всякой гонки: каталог пишется любым процессом пользователя.
6. **Нет проверки Team ID/нотаризации на macOS** — в `/Applications` под root копируется что угодно, что лежало в образе; на Mac это самый громкий класс последствий, потому что приложение получает права из системного каталога.
7. **Успех объявляется по exit code** — установщик Cursor вернул 0 и ничего не поставил; человек видит зелёную галочку, а редактора нет, и следующий шаг (расширение) молча не находит CLI.
8. **Запуск с `-Wait`** — шаг висит, пока человек не закроет окно Cursor, которое установщик открыл сам. Со стороны это бесконечный спиннер без объяснения (тот же баг описан для Claude Desktop в `scripts/windows/claude-desktop.ps1:259`).
9. **Переустановка поверх существующего** — повторный запуск установщика поверх рабочего Cursor, лишние минуты и риск сбить пользовательскую установку, которую ставили не мы.
10. **Прямой spawn `Cursor.exe` из elevated-процесса** — редактор стартует с правами администратора, и всё, что он потом запускает (терминал, задачи, расширения), тоже; плюс подменённый `Cursor.exe` в user-writable каталоге исполняется под админом.
11. **Кнопка рисуется всегда** — человек, не ставивший Cursor, жмёт «Открыть Cursor», ничего не происходит, а в телеметрию уходит «пошёл работать в редакторе» — воронка врёт про активацию.
12. **Установка расширения под админом или доверие выводу CLI** — либо привилегии утекают в user-writable `cursor.cmd`, либо установщик рапортует об установленной панели, которой нет: человек открывает Cursor и не находит обещанной кнопки Claude.
13. **Принудительное закрытие Cursor** — потеря несохранённой работы у того, кто в этот момент что-то писал.
14. **Шаг падает без Cursor** — красный экран и предложение «повторить неустановленное» у людей, которые Cursor осознанно не выбирали.

## Границы

- Компонент **не решает** ни подписку Cursor, ни гео-блокировку: об обеих карточка только предупреждает текстом (`components.json:55`). Никакого прокси, ключа или обхода здесь нет.
- Компонент **не переносит** настройки, темы и расширения из VS Code в Cursor. Кладётся ровно два артефакта, оба тем же скриптом `extension`. Первый — стартовый `settings.json` (autoSave + JetBrains Mono), и то **только если файла ещё нет** (`scripts/windows/extension.ps1:191-211`, `scripts/macos/extension.sh:91-109`). Второй — сам шрифт JetBrains Mono из вшитого `apps/JetBrainsMono-Regular.ttf`: на Windows файл копируется в `%LOCALAPPDATA%\Microsoft\Windows\Fonts` и регистрируется записью в `HKCU:\Software\Microsoft\Windows NT\CurrentVersion\Fonts` (`scripts/windows/extension.ps1:168-189`, строки 179-185), на macOS — `cp -f` в `~/Library/Fonts` (`scripts/macos/extension.sh:76-89`, строка 83). Без шрифта строка `"editor.fontFamily": "JetBrains Mono"` в сиде была бы пустышкой, так что это часть той же поставки, а не побочность. Целостность шрифта проверяется (`Test-HmArtifact`, `extension.ps1:173`; `verify_artifact_soft`, `extension.sh:78`), и при несовпадении SHA-256 шрифт просто не ставится — шаг из-за этого не падает. Ни сид, ни шрифт не обёрнуты проверкой наличия Cursor.
- **Удалить Cursor установщиком нельзя.** Кнопка «Удалить» рисуется только для `REMOVABLE = new Set(['course', 'uv', 'mascot', 'bridge'])` (`src/renderer/app.js`), а зашитый аллоулист целей удаления знает только `course`, `uv`, `bridge`, `mascot`, `nomad` (`src/uninstall-targets.js`). Cursor удаляется штатными средствами ОС.
- **Ветка winget не проходит проверок этого проекта.** При `$inst = $null` блок SHA/подписи (`scripts/windows/cursor.ps1:81-104`) не выполняется вовсе; доверие делегировано winget. Что именно проверяет winget — кодом проекта не подтверждено.
- **Издатель на Windows-онлайн-пути не запинен.** `Test-HmTrustedSigner` вызывается без `-ExpectedOrg` и `-ExpectedSubjectMatch` (`scripts/windows/cursor.ps1:90`), то есть проходит любая валидная подпись с корнем в машинном сторе и EKU Code Signing. Для сравнения, `scripts/windows/pydeps.ps1:94` пин делает. На macOS Team ID, наоборот, запинен жёстко.
- **`scripts/macos/cursor.sh:6` проверяет только `/Applications/Cursor.app`**, тогда как детектор в `src/main.js:2571` смотрит ещё и `~/Applications/Cursor.app`. Для `vscode.sh` двойная проверка сделана (это зафиксировано отдельным тестом), для `cursor.sh` — нет.
- **Автоматической установки Cursor CLI в PATH нет.** `scripts/windows/cursor.ps1:28` умеет распознать команду `cursor` в PATH, но сам её туда не кладёт; `Update-Path` (строки 5-24) собирает PATH только для текущего процесса и намеренно не читает HKCU.
- **Размеры в карточке — статические числа** `components.json:59-62` (win32 199597544, darwin 441615875), синхронизируются отдельным инструментом (`tools/sync-sizes.js:89-90, 117`), а не измеряются на лету.

## Риски и открытые вопросы

- **Панель Claude в Cursor теряется, если снять VS Code.** `extension.requires = ["vscode"]` (`components.json:88-90`), а `toggle` при выключении зовёт `disableDependents` (`src/renderer/app.js:331-333`, `src/renderer/deps.js:15-23`). Значит выбор «только Cursor, VS Code не нужен» снимает и компонент `extension` — а на Windows именно он единственный ставит панель в Cursor (`scripts/windows/extension.ps1:1-4`). Описание компонента при этом обещает «Панель Claude Code внутри VS Code (и Cursor, если стоит)» (`components.json:85`). Тест «components: extension требует vscode (не cursor) — дефолт-набор без cursor когерентен» закрепляет именно `requires: ["vscode"]`, то есть поведение намеренное; не подтверждено кодом, что сценарий «только Cursor» вообще предполагался рабочим.
- **`settings.json` для Cursor создаётся даже без Cursor.** В `scripts/windows/extension.ps1:191-211` и `scripts/macos/extension.sh:91-107` сид не обёрнут проверкой наличия редактора, а `Install-Into $null` тихо возвращает `$false` (`extension.ps1:127`). Человек, не выбиравший Cursor, получает каталог `%APPDATA%\Cursor\User\` (или `~/Library/Application Support/Cursor/User/`) с чужим файлом настроек. Последствие косметическое, но это мусор в профиле.
- **`HM_CURSOR_AUTOSTARTED` не выставляет никто.** Переменная читается в `scripts/windows/extension.ps1:89`, комментарий строки 83 сам говорит «если такой будет». Сплошной поиск по репозиторию (кроме `release/` и теста, который её удаляет из env) других вхождений не дал — ветка «мы сами запустили Cursor, гасить безопасно» на сегодня мёртвая.
- **Порядок «cursor раньше extension» держится не графом зависимостей.** `installOrder` (`src/renderer/deps.js:26-39`) сортирует топологически, но при отсутствии рёбер порядок задаётся порядком ключей `STATE.selected`, то есть порядком компонентов в `components.json`. Перестановка блоков в `components.json` может тихо переставить `extension` перед `cursor`, и панель в Cursor не встанет — установщик при этом отчитается успехом (`extension.ps1:224-227` считает отсутствие Cursor не провалом). Отдельного теста на этот порядок в `test/run-tests.js` я не нашёл.
- **Автоснятие по детекту обходит `disableDependents`.** `src/renderer/app.js:233` пишет `STATE.selected[id] = false` напрямую. Для `cursor` это безвредно (зависимых нет), но означает, что «снято детектом» и «снято рукой» — разные операции с разным побочным эффектом.
- **Пин Team ID `VDXQ22DGB9` — внешняя константа.** Комментарий `scripts/macos/cursor.sh:55-62` сам помечает это как `TODO-verify`: переподписание Cursor другим Team ID даст fail-closed стоп, и константу придётся обновлять руками. Сетевую достоверность самого значения я не проверял.
- **Ветка `$DRY` в `scripts/windows/cursor.ps1:28-31` намеренно не выходит при уже установленном Cursor** (`if (-not $DRY) { exit 0 }`) — при dry-run исполнение идёт дальше и выходит на строке 76. Комментария к этому нет; поведение восстановлено чтением, не документацией.
- **Тесты покрывают декларацию и форму, а не установку.** Почти все процитированные проверки читают `components.json`, исходники и делают статические регексп-проверки скриптов; единственный реальный прогон PowerShell рядом с этой фичей (`extension.ps1` в песочнице, `test/run-tests.js:5987`) проверяет сценарий «Cursor не установлен» и пропускается на машине с запущенным Cursor. Асимметрия по двум скриптам самого компонента: `cursor.sh` машинно проверяется — его синтаксис прогоняется через `bash -n` (`test/run-tests.js:897-904`, только на машине с bash), а текст читается регексп-тестом (`:1599`, `:1768`); `cursor.ps1` в `test/run-tests.js` не упомянут вовсе — ни прогона, ни `ParseFile` (в списке PowerShell-парсера на `:884` стоят `vscode.ps1`, `_deelev.ps1`, `extension.ps1`, `verify.ps1`, `claude-desktop.ps1`, `chatgpt-desktop.ps1`, `uv.ps1`, а `cursor.ps1` отсутствует), ни единой регексп-проверки. Функционального прогона установки нет ни для одного из двух.
