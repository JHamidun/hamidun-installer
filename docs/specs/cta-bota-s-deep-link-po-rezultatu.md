## Что обещает человеку

На финишном экране установщика есть заметная карточка с кнопкой в Telegram-бота: «Застрял или что-то непонятно? … Спросить бота @<хэндл>». Человеку не нужно объяснять боту, что у него сломалось: ссылка несёт это в себе. Если всё встало — бот получает `installed_win` / `installed_mac` и может вести дальше по первым шагам. Если что-то упало — бот получает `failed_<id первого нерешённого компонента>_win|_mac` (например `failed_cursor_win`) и с первого сообщения знает и платформу, и точку отказа.

Второе обещание — отсутствие «зашитого навсегда» бота: адрес бота берётся из `config.json` (`links.bot`), а не из кода экрана. Поменяли бота в конфиге — поменялись и ссылка, и подпись кнопки, и все упоминания хэндла в текстах финиша.

## Как работает

1. **Источник адреса.** `renderNextSteps()` (`src/renderer/app.js:2022`) читает `STATE.config.links` и `STATE.config.finish`. `STATE.config` целиком приходит из main через IPC `bootstrap` (`src/main.js:515-527`, `config: readJson('config.json', {})`) — то есть из вшитого в сборку `config.json`, renderer его не задаёт.
2. **Хэндл для текста.** `botHandle()` (`src/renderer/app.js:55-59`) достаёт хэндл регуляркой `/t\.me\/([A-Za-z0-9_]+)/i` из `links.bot` и возвращает `'@' + m[1]`. Совпадения нет (пустой/чужой URL) — возвращается нейтральное `'бота-помощника'`. Тот же хэндл подставляется в приветственный экран при `init()` (`src/renderer/app.js:102-103`, `#wc-bot-handle`) и в тексты про эскалацию на финише (`app.js:2054`, `2085`).
3. **Payload по результату.** `window.HMFinishLink.botStartPayload(failed, isWin, fin.botStartPayload || 'installed')` (`src/renderer/app.js:2095`). Логика — в `src/renderer/finish-link.js:20-32`:
   - `plat = isWin ? 'win' : 'mac'`, `suffix = '_' + plat`; `isWin` считается как `STATE.platform === 'win32'` (`app.js:2032`), `STATE.platform` = `process.platform` из bootstrap (`src/main.js:525`);
   - список падений фильтруется `filter(Boolean)`; **пусто** → `sanitizeId(okBase || 'installed').slice(0, MAX_PAYLOAD - suffix.length) + suffix`;
   - **не пусто** → `'failed_' + sanitizeId(list[0]).slice(0, 64 - 7 - suffix.length) + suffix`;
   - `sanitizeId` (`finish-link.js:14-16`) заменяет всё вне `[A-Za-z0-9_-]` на `-`; `MAX_PAYLOAD = 64` (`finish-link.js:11`).
4. **Что такое `failed`.** Массив приходит из `finishInstall(res)` (`app.js:1913`), а тот — из `runComponents`, который возвращает `failed: unresolved.filter(([, k]) => k !== 'dep').map(([i]) => i)` (`app.js:1749-1752`). `unresolved = Array.from(STATE.badEver)` — кумулятивная `Map` нерешённых проблем (`app.js:1559-1560`), куда компонент кладётся при провале (`app.js:1697`, виды `net` / `integrity` / `env` / `fail`) и удаляется, когда встал или осознанно пропущен (`app.js:1655`, `1660`). Значит «первый упавший» в payload — это первый по порядку вставки в `badEver` за все прогоны, а не обязательно первый упавший в последнем прогоне. Компоненты, снятые из-за упавшей зависимости (`dep`), в payload не попадают.
5. **URL.** `window.HMFinishLink.botUrl(links.bot || '', startPayload)` (`app.js:2096`); `botUrl` (`finish-link.js:34-37`) возвращает `''`, если пуста база или payload, иначе `botBase + '?start=' + encodeURIComponent(payload)`.
6. **Ветвление отрисовки.** `botUrl` непустой → рисуется карточка `.ns-bot` с кнопкой `<button type="button" class="ns-bot-btn" data-ext="${botUrl}">Спросить бота ${botH}</button>` (`app.js:2100-2109`, сама кнопка — `app.js:2107`), вставляемая в `#next-steps` после блока действий (`app.js:2294`). `botUrl` пустой → `botCta = ''`, карточки нет вовсе. Тем же условием переключается третий шаг инструкции (`app.js:2186-2188`): с ботом — «напиши боту-помощнику», без бота — «открой памятку „Что дальше“».
7. **Открытие.** Один общий обработчик `ns.querySelectorAll('[data-ext]')` (`app.js:2460`) шлёт `window.installer.openExternal(b.dataset.ext)`; IPC `open-external` в main (`src/main.js:1432-1444`) парсит URL через `new URL(String(url))` (`main.js:1435`) и пропускает только `http:`, `https:`, `mailto:`, `tg:` (`main.js:1436`), иначе возвращает `false` (`main.js:1441`) и ничего не открывает. Отдельного IPC у кнопки бота нет.
8. **Порядок загрузки.** `finish-link.js` подключается до `app.js` — теги идут `deps.js`, `finish-link.js`, `app.js` (`src/renderer/index.html:194-196`). Оба тега классические, без `defer`/`async`, поэтому выполняются по порядку и оба завершаются до `DOMContentLoaded`, с которого стартует единственная точка входа `init()` (`app.js:2488`). На верхнем уровне `app.js` обращений к `window.HMFinishLink` нет: все три (`app.js:1413`, `2095`, `2096`) лежат внутри функций. То есть сегодня сам порядок тегов на работу не влияет — он зафиксирован тестом как защита на будущее (см. инвариант 8).
9. **Значения по умолчанию в конфиге:** `finish.botStartPayload = "installed"` (`config.json:52`), `links.bot = "https://t.me/vibecodeguidebot"` (`config.json:59`).

Отдельная плашка на экране прогресса (`renderProgressBotBanner`, `app.js:1125-1138`) ведёт на **голый** `links.bot` без `?start=` — это другой элемент, не часть deep-link по результату.

## Инварианты

1. **Платформенный суффикс `_win`/`_mac` присутствует в payload всегда и никогда не обрезается** — режется только id/база, суффикс дописывается после `slice` (`finish-link.js:26-31`). Проверяется тестом «finish-link: payload <=64, платформенный суффикс НИКОГДА не срезается».
2. **Длина payload ≤ 64 символов** (лимит Telegram на параметр `start`) — `MAX_PAYLOAD = 64`, обе ветки считают место под префикс и суффикс (`finish-link.js:11, 26, 30-31`).
3. **В payload попадают только символы `[A-Za-z0-9_-]`** — `sanitizeId` применяется и к id упавшего компонента, и к базе успеха (`finish-link.js:14-16, 26, 31`).
4. **Есть хоть один нерешённый провал → payload начинается с `failed_`; провалов нет → payload начинается с базы успеха** (`finish-link.js:23-31`). `dep`-пропуски провалом не считаются (`app.js:1751`).
5. **Пустой `links.bot` в конфиге → нет ни ссылки, ни карточки бота**: `botUrl` возвращает `''` (`finish-link.js:35`), `botCta` становится пустой строкой (`app.js:2100`), третий шаг переключается на памятку (`app.js:2186-2188`).
6. **Адрес и хэндл бота в этой фиче берутся только из `config.json`** — `links.bot` для URL (`app.js:2096`) и `botHandle()` для подписи (`app.js:55-59`); литерала `@vibecodeguidebot` в коде карточки нет.
7. **Ссылка открывается только через main-IPC с allowlist схем** — renderer сам ничего не открывает, `open-external` пропускает лишь `http:/https:/mailto:/tg:` (`src/main.js:1437-1443`).
8. **`finish-link.js` загружается раньше `app.js`** (`src/renderer/index.html:194-196`); порядок закреплён проверкой в тесте «прогресс: полоса в ПРОЦЕНТАХ по прогону, проценты настоящие» (`test/run-tests.js:5765` — начало теста; сама проверка — `test/run-tests.js:5786-5788`: `const si = html.indexOf('<script src="finish-link.js">')`, `const ai = html.indexOf('<script src="app.js">')`, `assert(si !== -1 && ai !== -1 && si < ai, 'finish-link.js подключается ДО app.js')` — то есть требуется не только порядок, но и наличие ОБОИХ тегов). Сегодня инвариант ничего наблюдаемого не удерживает (см. п. 8 «Как работает»): это страховка на случай, если в `app.js` появится обращение к `window.HMFinishLink` на верхнем уровне.
9. **Логика payload живёт в одном месте и одинакова для приложения и тестов** — UMD-обёртка `finish-link.js:7-10`: renderer получает `window.HMFinishLink`, тест — `require(...)`.

## Что ломается, если инвариант нарушить

1. Суффикс срезан — бот не знает платформу и даёт инструкции не для той ОС (советует «Запуск от имени администратора» человеку на маке).
2. Payload длиннее 64 — Telegram обрежет или отбросит параметр `start`; бот получит обрывок вроде `failed_curs` или вообще ничего и начнёт с «расскажите, что у вас случилось» — то есть ровно с того, ради чего deep-link и делали.
3. В payload попал пробел/точка/кириллица — ссылка либо не откроет диалог с ботом, либо параметр не дойдёт; человек в момент паники видит «ничего не произошло».
4. Ветки перепутаны — при провале бот здоровается как с успешно установившимся («поздравляю, всё готово»), человек с нерабочим редактором получает поздравление вместо помощи.
5. Пустой конфиг, но карточка рисуется — кнопка «Спросить бота» ведёт в никуда: клик по `data-ext=""` уйдёт в `open-external`, `new URL('')` бросит исключение и вернёт `false`. Внешне — кнопка, которая молча ничего не делает.
6. Хэндл зашит в код — при смене бота установщик у уже скачавших людей продолжает звать в мёртвый или чужой аккаунт, и починить это можно только новой сборкой.
7. Ссылка открывается мимо allowlist — renderer получает возможность передать в `shell.openExternal` схему вроде `file:`/`ms-msdt:`, то есть запуск постороннего на машине человека под правами установщика.
8. `finish-link.js` не загрузился вовсе (файла нет в сборке) — `window.HMFinishLink` не определён, и первой падает НЕ карточка бота, а полоса прогресса: `setRunProgress` дёргает `runProgressPct` (`app.js:1413`) на каждом шаге прогона, задолго до финиша. Позже на том же `undefined` упал бы и `renderNextSteps` (`app.js:2095`). Простая перестановка `<script>`-тегов местами, при обоих присутствующих файлах, не ломает ничего наблюдаемого: теги классические, оба выполняются до `DOMContentLoaded`, а все обращения к `HMFinishLink` спрятаны внутри функций.
9. Логика скопирована во второе место — тесты продолжают проверять модуль, а на экран идёт другая (разъехавшаяся) копия; поломку увидит только живой человек.

## Границы

- Фича формирует **ссылку**, а не диалог: что бот сделает с `start`-payload, живёт на стороне бота и здесь не проверяется. Установщик не знает, распознан ли payload и ответил ли бот.
- В payload едет **только первый** нерешённый компонент. Полный список падений уходит отдельным каналом — телеметрией (`sendInstallTelemetry`, `app.js:1973-1993`, поля `failed`, `skipped`, `errors`), и только если человек не снял галочку согласия. Ссылка и телеметрия — независимые механизмы; при отключённой телеметрии бот увидит лишь одну точку отказа.
- Payload не содержит `uid` человека: привязку к Telegram-идентификатору делает main в телеметрии (`config.json:46` — комментарий про `uid` из имени скачанного файла), в deep-link она не добавляется.
- `dep`-пропуски (не встала зависимость) и `graceful skip` (exit 120, «не входит в сборку») в payload не отражаются никак — бот их не увидит.
- Карточка бота рисуется на финишном экране; на экране прогресса живёт другая плашка, и она ведёт на бота **без** payload (`app.js:1125-1138`).
- В модуле `finish-link.js` лежит ещё и `runProgressPct` — арифметика полосы прогресса. К deep-link она отношения не имеет, соседствует только ради тестируемости.
- Ссылка не проверяется на живость: недоступный или удалённый бот выглядит для человека так же, как рабочий.

## Риски и открытые вопросы

- **Тест «Задача 3» не проверяет то, что заявляет.** Утверждение `assert(/@vibecodeguidebot/.test(s), 'кнопка ведёт на @vibecodeguidebot')` (`test/run-tests.js:1565`) ищет литерал в исходнике `app.js`: `s = EG_APP()`, а `EG_APP` (`run-tests.js:1089`) читает весь файл `src/renderer/app.js` целиком как текст. Кнопка карточки литерала не содержит — подпись собирается как `Спросить бота ${botH}` (`app.js:2107`). Тест зелёный за счёт двух посторонних и независимых вхождений: **комментария** на `app.js:54` («без хардкода «@vibecodeguidebot» по коду») и **живой строки кода** на `app.js:724` — подсказки внутри модалки карантина macOS (`'<p style="font-size:12px;opacity:.82">Не получилось — пришли боту-помощнику скрин Терминала целиком: @vibecodeguidebot.</p>'`, аргумент вызова, `app.js:712-727`). Регулярка без якорей и без флага `g` даёт `true` при ЛЮБОМ из двух, поэтому удаления одного комментария на `app.js:54` НЕ хватит, чтобы тест покраснел — совпадение останется на `app.js:724`; покраснеет он только при снятии ОБОИХ вхождений. Тест держится на двух случайных якорях, и оба к кнопке карточки отношения не имеют. Заменить бота в конфиге — тест тоже останется зелёным при неверной кнопке: он грепает исходник `app.js` и на `config.json` не смотрит вовсе.
- **`botButtonLabel` — мёртвый экспорт.** Функция объявлена и экспортирована (`finish-link.js:40-44, 58`), но не вызывается нигде: поиск по репозиторию (без `node_modules` и `release/`) даёт только само объявление и строку экспорта. Тестов у неё тоже нет.
- **Текст третьего шага ссылается на несуществующую подпись.** `app.js:2187` говорит «(кнопка «Бот-помощник» ниже)», а реальная кнопка подписана «Спросить бота @…» (`app.js:2107`). Похоже, шаг писался под `botButtonLabel` («Бот-помощник: разобраться с ошибкой» / «Бот-помощник: что дальше?») и разошёлся с кодом.
- **Асимметрия экранирования.** В карточке финиша URL подставляется как `data-ext="${botUrl}"` без `escapeHtml` (`app.js:2107`), тогда как плашка прогресса делает `escapeHtml(botBase)` (`app.js:1134`). Практически данные доверенные (вшитый `config.json`, payload прошёл `sanitizeId` и `encodeURIComponent`), но кавычка в `links.bot` разорвала бы атрибут именно здесь. Тестом это не покрыто.
- **Хардкод хэндла в статике.** `src/renderer/index.html:67` содержит `@vibecodeguidebot` как начальный текст `#wc-bot-handle`; он перезаписывается `botHandle()` при `init()` (`app.js:102-103`). При пустом `links.bot` подпись станет «бота-помощника». Хардкод в `app.js:724` не перезаписывается ничем — при смене бота эта строка соврёт. Обе точки вне границ данной фичи, но опровергают формулировку инвентаря «хардкода нет» в масштабе репозитория.
- **Ссылка инвентаря `config.json:60` не совпадает с фактом.** В прочитанном `config.json` строка 59 — `"bot": "https://t.me/vibecodeguidebot"`, строка 60 — `"cabinet"`. В шапке этой спеки указаны фактические строки (52 и 59).
- **Не подтверждено кодом:** обрабатывает ли бот форматы `installed_*` / `failed_*` вообще — сторона бота в этом репозитории отсутствует, сверить контракт не с чем. Так же не подтверждено, что 64 символа — актуальный лимит Telegram: в коде это константа с комментарием, внешней проверки нет.
- Смены `data-ext`-обработчика на финише нет: он вешается один раз после `ns.innerHTML` (`app.js:2460`), а `renderNextSteps` вызывается заново после «Повторить неустановленное» — вместе с новым HTML вешаются и новые обработчики. Утечки старых слушателей не будет (узлы заменены), но payload после повтора пересчитывается по кумулятивной `badEver`, а не по последнему прогону — это поведение осознанное (`app.js:1743-1752`), однако нигде не задокументировано со стороны бота.
