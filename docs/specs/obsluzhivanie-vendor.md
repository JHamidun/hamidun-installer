## Что обещает человеку

Человек, который открыл установщик, видит на карточке компонента бейдж «~222 МБ» и такой же список в попапе «Что попадёт на мой ПК». Эта фича обещает, что цифра не выдумана: она посчитана по тем самым файлам, которые физически лежат в `vendor` и поедут внутрь установщика (`src/renderer/app.js:1166-1186`, `componentSizeBytes` и `sizeBadgeHtml`). Если посчитать было нечего, человек увидит не круглое правдоподобное число, а пустое место или словесную пометку `sizeNote` — «скачивается во время установки», «размер задаёт магазин приложений».

Второе обещание — установщик вообще существует и собирается. Офлайн-издание Windows упирается в потолок 32-битного makensis; офлайн-кеш npm растёт сам собой, потому что `npm install --cache` добавляет версии и никогда не удаляет старые. Чистка кеша и пересчёт манифеста `vendor/checksums.json` — это то, что держит сборку под потолком и держит манифест целостности совпадающим с диском, чтобы гейт на машине ученика не отбил вшитый артефакт как подменённый.

Оба обещания адресованы не ученику напрямую, а тому, кто выпускает релиз: сами три инструмента в дистрибутив не попадают — `package.json` → `build.files` содержит только `src/**/*`, а `extraResources` перечисляет `scripts`, `agent`, `config.json`, `components.json`, `remote-components.json`, `packs.json`, `assets/*` и каталог `vendor`. Каталога `tools` там нет.

## Как работает

Фича — это три независимых скрипта, каждый со своим входом и своим кодом возврата.

### 1. `tools/sync-sizes.js` — размеры компонентов

Единственный источник чисел в `components.json`.

1. `main()` (`:324`) разбирает аргументы: `--check`, `--json`, `--platform <win32|darwin>`, `--force`. Неизвестная платформа → `return 2`.
2. Гейт чужой платформы (`:339-345`): если запрошенная платформа не равна `process.platform` и нет `--force` — выход с кодом 2 и текстом «Часть путей vendor общая — измерение дало бы правдоподобные, но ЧУЖИЕ байты».
3. `computeSizes()` (`:247`) обходит все компоненты из `components.json`:
   - id есть в `NO_BUNDLED_PAYLOAD` (`:135-146`: `verify`, `bridge`, `claude-desktop`, `chatgpt-desktop`) → числа не будет вовсе, попадает в `skipped`, при отсутствии `sizeNote` заводится пометка;
   - иначе `measureComponent()` (`:191`) складывает размеры частей из `VENDOR_PARTS[platform][id]` (`:79-130`). Часть — это путь, каталог (считается рекурсивно через `sizeOf`, `:154`) либо glob-lite `{glob, pick:'max'}` для арх-вариантов одного артефакта: на mac едут обе арх, ставится ровно одна, поэтому суммировать нельзя — берётся больший;
   - результат `{missing}`, `{unmapped}` или `{timeout}` не даёт числа: такой id уходит в `skipped` и в `updates` не попадает.
4. Ветвление «чужая платформа с `--force`» (`:367-376`): из `updates` удаляются все id, кроме перечисленных в `PLATFORM_INDEPENDENT` (`:77`, сейчас там один `course` — закоммиченный `vendor/course/vibecoding-course.zip`).
5. `applySizes()` (`:287`) сносит легаси-поле `sizeHint` у всех компонентов, при необходимости проставляет `sizeNote` и пишет `c.sizeBytes[platform]` только для id из `updates`.
6. Исход:
   - `--check` и есть расхождения → сообщение в stderr и `return 1`, **до** `fs.writeFileSync` (`:428-433`);
   - расхождений нет и vendor не развёрнут → «ПРОПУЩЕНО: vendor не развёрнут — НИ ОДНО число не сверено», `return 0` (`:413-418`);
   - расхождений нет и vendor есть → «ОК: все сверенные числа совпали с vendor — файл не тронут»;
   - сериализация совпала с исходным текстом байт-в-байт → файл не переписывается (`:432`).

Куда это подключено: `npm run sizes` / `npm run sizes:check` (`package.json`), шаг «Проверка размеров компонентов (генератор жив и не врёт)» в `unit-tests.yml` на обеих ОС (`:131-132`, `:176-177` — на раннере vendor нет, шаг ловит сломанный генератор), шаг `npm run sizes` в `build-mac-lite.yml:175-176` (darwin-числа физически можно померить только там), и `checkSizes()` в `tools/release-check.js:104-124`, который считает тем же `computeSizes` и валит релиз блокером при расхождении.

### 2. `tools/regen-checksums.js` — манифест целостности без перекачки

Пересчитывает `vendor/checksums.json` по файлам, уже лежащим на диске.

1. Набор файлов (`:49-53`) повторяет `tools/fetch-vendor.ps1:516-547` дословно: всё непустое в `vendor/apps` рекурсивно (`walkFiles`, `:34`), плюс `course/vibecoding-course.zip`, `nomad-src.sha256`, `nomad-src/pyproject.toml`.
2. Пустой набор → `ОШИБКА: в vendor нечего хешировать` и `exit 2` (`:55-58`).
3. Сортировка по **базовому** имени файла (`:61`) — как `Sort-Object Name` в оригинале; ключ записи тоже базовое имя.
4. Формат собирается строкой вручную: `generatedAt`, `algorithm: sha256`, `files`, отступы и CRLF — чтобы очередной `npm run fetch:vendor` не давал шумный дифф (`:71-73`).
5. Сравнение с предыдущим манифестом идёт **только по полю `files`** (`:77-82`): `generatedAt` меняется всегда и о расхождении ничего не говорит. Совпало → «манифест уже соответствует диску — не трогаю», `exit 0`.
6. Разошлось → печатается построчный дифф `+ / - / ~`; с `--check` — `exit 1` без записи (`:103-106`), без него — запись файла.

Ветвление по платформам у этого скрипта отсутствует: он работает с тем, что лежит в `vendor` на текущей машине.

### 3. `tools/prune-npm-cache.js` — чистка офлайн-кеша npm

1. `readCache()` (`:122`) разбирает `_cacache/index-v5` построчно, различая архивы (`parseTarballKey`, ключ вида `…/<пакет>/-/<имя>-<версия>.tgz`) и packument'ы (`parsePackumentKey`).
2. `resolveKeep()` (`:179`) вычисляет, что оставить: читает блоб packument'а корневого пакета `@anthropic-ai/claude-code`, берёт `dist-tags.latest` и `optionalDependencies` **этой** версии — так же, как резолвит `npm install --offline` без пина. Отсюда набор платформенных пакетов (win/mac/linux), а не из зашитой константы. Ветки-страховки: версии из `dist-tags` нет в кеше архивом → берётся самая новая имеющаяся плюс громкая нота; packument не прочитан → тоже самая новая имеющаяся.
3. `planPrune()` (`:254`) строит план и **проверки безопасности**: если под удаление попали все версии пакета или у оставляемой версии нет блоба на диске — в `blockers`. Блобы под удаление — те, на которые после чистки не сошлётся ни одна строка индекса (включая висячие ревизии packument'ов).
4. `main()` (`:352`): нет кеша → сообщение и `return 0`; есть blockers → «ОТКАЗ — чистка НЕ выполнена, кеш не тронут» и `return 1`; `--dry-run`/`-n` → печать плана без изменений; иначе `applyPrune()`.
5. `applyPrune()` (`:316`) удаляет **сначала строки индекса, потом блобы**. Обратной ссылки «блоб → индекс» в cacache нет: осиротевшая строка индекса заставила бы `hm_npm_cache_has_tarball` соврать установщику «офлайн-копия есть», и `claude.sh` ушёл бы в офлайн-ветку вместо честного онлайн-фолбэка.

Подключение: вызывается последним шагом наполнения кеша в обоих fetch-скриптах — `fetch-vendor.ps1:85` (после `npm install '@anthropic-ai/claude-code'`) и `fetch-vendor-mac.sh:116` (после `npm cache add` обеих darwin-арх, иначе прунер не увидит, что их надо сохранить). Оба скрипта на ненулевой код возврата печатают предупреждение и **продолжают** (`fetch-vendor.ps1:86-88`, `fetch-vendor-mac.sh:117`). Отдельный ранний сигнал — `checkNpmCacheDupes()` в `tools/preflight-build.js:205-234`: уровень всегда `warn`, в подсказке названа точная команда `npm run prune:cache`. Ручной запуск — `npm run prune:cache` (`package.json`).

## Инварианты

1. **Число размера нельзя вписать в `components.json` мимо генератора.** `applySizes` удаляет поле `sizeHint` у любого компонента при каждом прогоне (`tools/sync-sizes.js:292-295`); тест дополнительно проверяет, что renderer его не читает.
2. **Число есть только у компонента с записью в карте vendor.** Компонент из `NO_BUNDLED_PAYLOAD` числа не получает вовсе (`tools/sync-sizes.js:258-263`), а компонент без числа не остаётся немым — у него есть `sizeNote`.
3. **`sizeBytes` — объект по платформам, целые положительные байты, ключа `all` не существует.** Держится тестами «размеры: sizeBytes — целые положительные байты под известные платформы» и картой `VENDOR_PARTS` (`tools/sync-sizes.js:79-130`); в коде рендерера число читается как `c.sizeBytes[STATE.platform]` (`src/renderer/app.js:1172`).
4. **Не измерил — не подставил.** `measureComponent` возвращает `{missing}` / `{unmapped}` / `{timeout}` вместо числа (`tools/sync-sizes.js:201-223`), и такой id не попадает в `updates`, а значит `applySizes` его не трогает. Отсутствующий vendor не стирает уже записанные числа (`:301`, `:401-404`).
5. **`--check` не пишет файл никогда.** Ветка `if (check) { … return 1; }` стоит перед `fs.writeFileSync` (`tools/sync-sizes.js:428-433`); в `--json` то же самое через `return (check && changes.length) ? 1 : 0` без записи (`:381-388`).
6. **Прогон без vendor не выдаётся за успешную сверку.** При `!res.present` печатается «ПРОПУЩЕНО: vendor не развёрнут — НИ ОДНО число не сверено» (`tools/sync-sizes.js:413-418`), а не «ОК».
7. **Чужую платформу без `--force` не меряем; с `--force` пишем только переносимые артефакты.** Гейт `tools/sync-sizes.js:339-345` (exit 2) и покомпонентный фильтр `:367-376` по `PLATFORM_INDEPENDENT` (`:77`). Тест «sync-sizes: чужую платформу пишем ТОЛЬКО для переносимых артефактов» дополнительно запрещает объявлять переносимым то, что кладёт `fetch-vendor`.
8. **Набор файлов и формат `checksums.json` у генератора и у `fetch-vendor.ps1` совпадают.** `tools/regen-checksums.js:49-73` против `tools/fetch-vendor.ps1:516-547`: те же три добавки к `vendor/apps`, та же сортировка по базовому имени, тот же ключ, те же поля `sha256`/`bytes`, CRLF.
9. **Расхождение манифеста считается только по `files`.** `filesOf()` сравнивает `JSON.parse(text).files`, `generatedAt` в сравнение не входит (`tools/regen-checksums.js:75-82`); `--check` при расхождении даёт exit 1 и ничего не пишет (`:103-106`).
10. **Прунер удаляет только архивы `.tgz`.** В `removeEntries` попадают исключительно записи из `cache.tarballs` (`tools/prune-npm-cache.js:261-284`); packument'ы, включая чужие платформы, в удаление не кладутся — закреплено тестом «прунер удаляет ТОЛЬКО архивы…».
11. **Оставляемый набор версий вычисляется из метаданных кеша, а не из зашитой платформы.** `resolveKeep` берёт `dist-tags.latest` + `optionalDependencies` этой версии (`tools/prune-npm-cache.js:201-233`); тест требует, чтобы в KEEP оказались `darwin-arm64`, `darwin-x64` и `win32-x64`, и запрещает константу платформы в исходнике.
12. **Порядок удаления — строка индекса, затем блоб.** `applyPrune` сначала переписывает/удаляет файлы индекса, потом блобы (`tools/prune-npm-cache.js:316-333`).
13. **Повреждённый кеш не чистится вообще.** Любой blocker → `return 1` без вызова `applyPrune` в обеих ветках вывода (`tools/prune-npm-cache.js:379-380` для `--json`, `:390-395` для обычной).
14. **Отказ прунера не роняет наполнение vendor.** Оба fetch-скрипта печатают «чистка кеша ОТКАЗАЛА (кеш не тронут)» и продолжают (`tools/fetch-vendor.ps1:86-88`, `tools/fetch-vendor-mac.sh:116-117`); предполётная проверка накопления тоже никогда не `fail`, только `warn` (`tools/preflight-build.js:220-233`).

## Что ломается, если инвариант нарушить

1. Возвращается исходный дефект: рукописная строка размера, которую никто не пересчитывает. Человек видит «~50 МБ» рядом с файлом установщика на 1,9 ГБ и решает, что его обманывают, — ровно там, где интерфейс снимает страх «а не вирус ли это».
2. У компонента, который ничего не приносит с собой (`claude-desktop`, `chatgpt-desktop`, `bridge`), появляется бейдж с числом. Человек планирует загрузку по этой цифре, а реальный объём задаёт сторонний магазин или сайт.
3. Одно число на две ОС физически неверно: VS Code едет как 221,6 МиБ `setup.exe` на Windows и как 520,1 МиБ `.zip` на macOS. Пользователь Mac увидит вдвое заниженную сумму и решит, что установка зависла, а не идёт.
4. Пропавший из vendor файл превращается в тихий ноль или в старое число: попап обещает то, чего в сборке уже нет, и установка падает на шаге, который человек считал оплаченным заранее.
5. `npm run sizes:check` в CI начинает молча править рабочее дерево. Гейт перестаёт быть гейтом: расхождение «чинится» само и уезжает в релиз незамеченным.
6. Зелёный `sizes:check` на машине без vendor читается как «числа проверены», хотя не проверено ни одно. Именно так дефект и доживает до продакшена — сигнал есть, утверждения за ним нет.
7. Windows-байты записываются в darwin-поле. Живой случай 29.08.2026: `--platform darwin --force` переписал три числа (`claude` 135→103 МиБ, `nomad` 165→110, `mascot` 202→279) — все правдоподобны, ни одно не верно, код возврата 0. Пользователь Mac получает выдуманные цифры и никаких признаков подлога.
8. Манифест, собранный по другому набору или в другом формате, разъедется с тем, что генерит `fetch-vendor.ps1`. На установке `Confirm-HmArtifact` не найдёт записи по имени файла — вшитый компонент будет отбит как неподтверждённый, и человек увидит отказ на пустом месте.
9. Если в сравнение попадёт `generatedAt`, `--check` будет падать после каждого прогона генератора: гейт кричит всегда, к нему привыкают и перестают читать — а настоящее расхождение проезжает вместе с шумом.
10. Удалённый packument ломает резолв `optionalDependencies` для чужих платформ: офлайн-установка Claude Code на этой ОС не соберёт дерево и уйдёт в отказ у ученика, при формально «почищенном» кеше.
11. Прунер, зашитый на `win32-x64`, на macOS вычистит `darwin-arm64` и `darwin-x64` — ровно то единственное, ради чего кеш там и нужен. Офлайн-издание для Mac перестаёт ставить Claude Code.
12. Обратный порядок оставляет строку индекса без блоба. `hm_npm_cache_has_tarball` (грепом по `index-v5`) соврёт «офлайн-копия есть», `claude.sh` уйдёт в офлайн-ветку вместо онлайн-фолбэка и упадёт с `ENOENT`/`EINTEGRITY` **на машине пользователя**.
13. Чистка уже противоречивого кеша оставляет одну версию, которой физически нет: 12 архивов удалены, тринадцатый недостижим — офлайн-установка отказывает у ученика, а не у сборщика.
14. Если отказ прунера будет ронять `fetch-vendor`, наполнение vendor встанет из-за проблемы, которая сборку не ломает; если наоборот сделать `checkNpmCacheDupes` блокером — релиз будет отбиваться за лишние 80 МиБ, при том что настоящий отказ по размеру выносит отдельный гейт `nsis-limit`.

## Границы

- **Ничего не качает.** `sync-sizes` меряет то, что уже лежит в `vendor`; `regen-checksums` не перекачивает артефакты (в этом и был смысл — раньше манифест обновляли только через `npm run fetch:vendor`); `prune` только удаляет. Восстановление после чистки — `npm run fetch:vendor`.
- **Размер докачки в lite-издании сюда не входит.** Он живёт в `remote-components.json` и приезжает в renderer как `bootstrap.remoteSizes`; второй копии в `components.json` нет сознательно (`tools/sync-sizes.js:21-23`, `src/renderer/app.js:1168-1171`). Кто именно записывает `sizeBytes` в `remote-components.json` — по прочитанному коду не подтверждено.
- **Не измеряется то, что качает сам компонент при первом запуске** (модель Handy, Chromium для Playwright, Python для Nomad) — это словами в `sizeNote`, числа там выдумывать запрещено.
- **darwin-числа берутся только на macOS.** На Windows гейт `:339-345` не даст их посчитать; практический путь — шаг `npm run sizes` в `build-mac-lite.yml:175-176` с коммитом `components.json` обратно в ветку.
- **`regen-checksums` фиксирует байты, лежащие на диске, и ничего не говорит об их подлинности.** Это генератор манифеста, а не проверка источника; сама проверка на установке — отдельная фича (гейт целостности, `scripts/windows/_verify.ps1`).
- **`prune` по умолчанию работает с `vendor/npm-cache`**, глобальный кеш пользователя не трогает (каталог задаётся `--cache`). Packument'ы не удаляются никогда, даже устаревшие по смыслу — удаляются только их висячие блобы.
- **Ни один из трёх инструментов не попадает к ученику.** `package.json` → `build.files` = `["src/**/*"]`, каталог `tools` не перечислен ни там, ни в `extraResources`. В дистрибутив едут результаты их работы: `components.json` и `vendor/checksums.json`.
- **Уступка по времени.** Обход каталогов на Windows упирается в антивирус, поэтому у `computeSizes` есть бюджет (`budgetMs`), и в тестах каталожные компоненты проверяются под ограничением (по умолчанию 8000 мс на компонент, полная сверка — `HM_SIZES_DEEP=1`). Что не успели — печатается как пропуск, а не как «ОК».

## Риски и открытые вопросы

- **У `tools/regen-checksums.js` нет ни одного теста и он нигде не вызывается автоматически.** Поиск по репозиторию даёт только четыре упоминания: `docs/INVENTORY.md`, `docs/specs/geyt-celostnosti-vshityh-artefaktov.md`, `docs/specs/_features.json` и сам файл. В `package.json` npm-скрипта под него нет (есть `sizes`, `sizes:check`, `prune:cache`, но не `checksums`), в `tools/release-check.js` и в workflow'ах он не упоминается. То есть единственный инструмент, который может разойтись с `fetch-vendor.ps1` по набору файлов и по формату, ничем не застрахован — расхождение обнаружится только отказом `Confirm-HmArtifact` на машине ученика.
- **Расхождение `regen-checksums.js` с `fetch-vendor.ps1` по фильтру пустых файлов.** PowerShell применяет `Where-Object { $_.Length -gt 0 }` только к рекурсии по `vendor/apps` и явно проверяет размер у курса, а `nomad-src.sha256` и `nomad-src/pyproject.toml` добавляет по одному лишь факту существования (`tools/fetch-vendor.ps1:524-535`). JS-версия применяет `size > 0` ко всем трём добавкам (`tools/regen-checksums.js:50-53`). Пустой `nomad-src.sha256` попал бы в манифест у одного генератора и не попал у другого. Практического случая в коде не видел.
- **Сравнение манифеста чувствительно к порядку ключей.** `filesOf()` сравнивает `JSON.stringify(...files)`, то есть порядок вставки; порядок задаётся `localeCompare(…, 'en')` в JS против `Sort-Object Name` в PowerShell. Совпадают ли эти два правила сортировки на всех именах из `vendor/apps` — не проверено ни тестом, ни прогоном; при расхождении `--check` сообщит о разошедшемся манифесте при идентичном наборе файлов.
- **`vendorPresent()` не ограничен бюджетом времени.** Он вызывает `measureComponent(id, platform, null)` (`tools/sync-sizes.js:230-237`) и возвращается на первом успешно измеренном компоненте. Порядок обхода — порядок ключей `VENDOR_PARTS`, где первым идёт файловый `git`; но если первые файловые артефакты отсутствуют, до успеха он дойдёт через каталог (`npm-cache`, `config-pack`). Замера не делал — потенциальная, не подтверждённая длительность.
- **`--force` у `sync-sizes` остаётся в интерфейсе, хотя его прежняя семантика признана опасной.** Сейчас он снимает только отказ, а покомпонентный фильтр всё равно оставит один `course`; сам комментарий в коде (`:351-366`) прямо говорит, что «`--force` сам по себе ничего не защищает». Открытый вопрос: нужен ли флаг вообще, раз единственный переносимый артефакт и так один.
- **Тесты прунера на реальном кеше молча вырождаются в no-op.** Три из пяти начинаются с `if (!cache.exists) return;` / `if (!versions.length) return;` (`test/run-tests.js:8863`, `:8877`, `:8888-8891`), то есть на чистом чекауте и в CI без `vendor` они зеленеют, ничего не проверив. Явного `SKIP` там, в отличие от размерных тестов, нет.
- **`sizes:check` в CI не сверяет ни одного числа** — это записано в самом workflow (`unit-tests.yml:125-130`): на раннере vendor не развёрнут, шаг ловит только сломанный генератор. Реальная сверка держится на локальном прогоне после `fetch:vendor`, на юнит-тестах при наличии vendor и на `release-check`.
