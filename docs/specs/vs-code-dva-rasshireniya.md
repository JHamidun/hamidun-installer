## Что обещает человеку

Человек получает установленный редактор VS Code и внутри него панель Claude Code — то есть возможность работать с ИИ-агентом кнопками в окне редактора, а не командами в терминале. Компонент помечен `recommended: true` и включён по умолчанию (`components.json:41-42`), то есть новичок получает его, ничего не выбирая. Установка идёт из вшитого в установщик дистрибутива, но офлайн она проходит **только на Windows**: на macOS перед копированием бандла обязателен `spctl --assess --type execute` (`scripts/macos/_lib.sh:350`, fail-closed — шаг падает при неуспехе), и сам скрипт называет плохую или ограниченную сеть одной из трёх причин провала (`scripts/macos/vscode.sh:71-73`).

Второе расширение — Codex (`openai.chatgpt`) — обещано слабее, и текст компонента это признаёт прямо: «панель Codex докачивается из интернета» (`components.json:39`). В офлайн-издании под Windows его в сборке нет вовсе (`package.json:124` исключает `apps/chatgpt.vsix`), поэтому без сети человек получает редактор и панель Claude, а Codex ставит позже сам. Обещание, за которое можно спросить: **на Windows** редактор и панель Claude встают офлайн, Codex — как получится с сетью. На macOS офлайн-обещания нет ни по редактору (сетевой гейт `spctl`), ни гарантированно по панели: vsix архитектурно-специфичен (`resolve_vsix "claude-code-$(arch_tag).vsix"`, `scripts/macos/vscode.sh:140`), и если файла под архитектуру этого Mac в сборке нет, панель едет из Marketplace (`vscode.sh:144-146`, `vscode.sh:125`).

## Как работает

Компонент запускается по имени: `scriptFor(id)` в `src/main.js:569-573` собирает путь `scripts/windows/vscode.ps1` (Windows) или `scripts/macos/vscode.sh` (macOS). Дальше пути расходятся.

### Windows — `scripts/windows/vscode.ps1`

1. Скрипт дот-сорсит `_verify.ps1` (вентиль целостности `Confirm-HmArtifact`) и `_deelev.ps1` (де-элевация `Invoke-HmDeElevated`). Загрузка `_deelev.ps1` попутно подметает осиротевшие задачи планировщика прошлых прерванных установок (`_deelev.ps1:695-701`).
2. `Update-Path` (строки 5-22) собирает PATH **только** из машинной ветки (`[Environment]::GetEnvironmentVariable('Path','Machine')`) плюс фиксированные каталоги; HKCU-PATH не читается никогда.
3. `Test-VsCodePresent` ищет `code.cmd` или `Code.exe` в `%LOCALAPPDATA%\Programs\Microsoft VS Code` и `%ProgramFiles%\Microsoft VS Code`. `$setup` — это `$env:HM_VENDOR\apps\vscode-setup.exe`, если файл есть.
4. Ветвление установки редактора (строки 56-90):
   - **редактор уже есть** → «доставлю только расширения», установка пропускается;
   - **нет вшитого установщика И редактора нет** → `exit 120` — осознанный пропуск, не ошибка;
   - **`HM_DRY_RUN`** → печатается план, ничего не делается;
   - **иначе** → `Confirm-HmArtifact $setup`, затем `Start-Process` с `/VERYSILENT /NORESTART /MERGETASKS=!runcode,addtopath -Wait`, повторный `Update-Path`, ожидание появления `Code.exe` до 60 секунд циклом по секунде, и печать `HM-RECEIPT path` с каталогом установки.
   Если `Code.exe` так и не появился, скрипт печатает предупреждение и **всё равно идёт ставить расширения** (строка 88).
5. Путь к CLI: сначала `Get-VsCodeCli` — читает ключи Uninstall в HKCU/HKLM/WOW6432Node, ищет `DisplayName -match 'Visual Studio Code'` и берёт `InstallLocation\bin\code.cmd`; если не нашлось — `Find-CodeCli` по фиксированным путям. Нет CLI и не dry-run → `exit 1` с инструкцией поставить расширения руками.
6. Если процесс `Code` запущен, печатается предупреждение, что установка расширений затянется (до 10 минут на каждое) и быстрее закрыть редактор.
7. `Get-Vsix` (строки 130-153) для `claude-code.vsix` и `chatgpt.vsix`: проверяет наличие в `HM_VENDOR\apps`, прогоняет `Confirm-HmArtifact`, затем **копирует** файл во временный `%TEMP%\hm-vsix-<guid>.vsix` и убеждается, что копия читается. Копия нужна потому, что в лёгком издании исходный vsix лежит в admins-only каталоге, а расширение ставится от имени пользователя. Не удалось скопировать — возвращается пустая строка, путь уйдёт в Marketplace.
8. `Install-ExtSafe` для `anthropic.claude-code`, затем для `openai.chatgpt`:
   - уже установлено (`Test-HmExtInstalled` по `~\.vscode\extensions` и `~\.vscode-oss\extensions`) → успех без действий;
   - иначе `Invoke-HmDeElevated $cli @('--install-extension', <vsix или extId>, '--force')`; `$null` означает, что де-элевация недоступна — тогда fail-closed: бинарь под админом не запускается, взводится `$script:DeElevFailed`;
   - результат подтверждается `Confirm-ExtInstalled` — шесть проверок каталога с паузой в секунду;
   - ретрай через Marketplace делается **только** если ставили из vsix и `$r.Gate -eq 'medium'` (то есть задача доказанно завершилась). При `Gate = 'unknown'` второй запуск не делается, чтобы не писать конкурентно в тот же каталог расширений.
9. Итог (строки 253-272): `exit 0`, если встали оба. Исключение: `$okClaude -and -not $okCodex -and -not $codexVsix` → тоже `exit 0` с предупреждением, что Codex не вошёл в сборку. Иначе `exit 1` со списком недостающего. Блок обёрнут в `try/finally`, в `finally` — `Remove-HmVsixTemps`.

Механика де-элевации (`_deelev.ps1:524-687`): создаётся одноразовая скрытая задача планировщика `HmDeElev_<guid>` с `RunLevel LeastPrivilege` и `ExecutionTimeLimit PT10M`; тело обёртки едет целиком в `-EncodedCommand`; XML задачи пишется в приватный каталог `%ProgramData%\HmDeElev-<hex>\w` с DACL «SYSTEM + Administrators» и удаляется сразу после `/Create`. Обёртка запускает целевой бинарь **только** если видит medium integrity (`S-1-16-8192`), иначе `exit 210`. Родитель ждёт до 630 секунд, читая «Last Result» задачи локаль-независимо (`schtasks /Query /HRESULT /FO CSV /NH /V`, поле №6), и раз в минуту печатает, что процесс жив.

### macOS — `scripts/macos/vscode.sh`

1. Приложение ищется в двух местах: `/Applications/Visual Studio Code.app` и `~/Applications/Visual Studio Code.app` (строки 13-17). Если нет ни одного, целью установки становится `/Applications`. CLI — `$APP/Contents/Resources/app/bin/code`.
2. Нет приложения и нет `$HM_VENDOR/apps/vscode.zip` → `exit 120`.
3. Иначе `verify_artifact "$ZIP"` (fail-closed SHA-256 против `vendor/checksums.json`, `_lib.sh:219-246`), затем проверка свободного места: нужно `размер_zip × 3 + 512 МБ`, считается **до** запроса пароля (строки 54-62).
4. Установка идёт одним вызовом `admin_run /bin/sh -c "$HM_VSCODE_INSTALL_SH" hm_vscode_install "$ZIP" "UBF8T346G9" "$APP"`. Скрипт `HM_VSCODE_INSTALL_SH` (`_lib.sh:336-352`) под root: фиксирует PATH, создаёт `mktemp -d /var/root/hm_vsc.XXXXXX`, копирует туда zip, распаковывает `ditto -x -k`, находит `*.app` на глубине до 2, проверяет `codesign --verify --deep --strict -R "=anchor apple generic and certificate leaf[subject.OU] = \"$2\""` и `spctl --assess --type execute`, копирует бандл в назначение и снимает карантин `xattr -dr com.apple.quarantine`. Сам `admin_run` (`_lib.sh:38-68`) запускает osascript через `env -i` с чистым окружением.
5. Провал этого шага → печатаются три различённые причины (закрыли окно пароля / Mac не подтвердил подпись у Apple / кончилось место) и `exit 1`.
6. Расширения: `resolve_vsix "claude-code-$(arch_tag).vsix"` и `resolve_vsix "chatgpt-$(arch_tag).vsix"` — то есть файлы **под конкретную архитектуру**, universal-варианта нет. Проверка «под нашу архитектуру нет, под другую есть» сделана **только для панели Claude**: вызов `hm_arch_note_missing` в файле ровно один — `vscode.sh:144`. Сама функция (`_lib.sh:97-109`) печатает только объяснение про архитектуру сборки и совет написать в бота поддержки; строку «Поставлю панель из интернет-магазина расширений — потребуется подключение» печатает `vscode.sh:145`, а не функция. Для `chatgpt-$(arch_tag).vsix` такой проверки нет нигде: при его отсутствии не печатается ничего, и `install_ext` (`vscode.sh:125`) молча уходит в Marketplace.
7. `install_ext` пробует сначала вшитый vsix, затем Marketplace по id. Факт установки проверяется `ext_present` — до трёх попыток разобрать вывод `--list-extensions` в нижнем регистре через `grep -Fx`.
8. Итог (строки 155-171): `exit 0`, если встало расширение Claude. Отсутствие Codex даёт именованное `ПРЕДУПРЕЖДЕНИЕ`, но не проваливает шаг. Если Claude не встал — `exit 1` с текстом, который отдельно поясняет, что сам редактор при этом установлен.

### Как компонент считается установленным

`src/main.js:2588-2595`: `out.vscode = { installed: !!appPresent && bothExts, … }` (присваивание — строка 2594), где `bothExts` (строка 2593) — оба расширения (`anthropic.claude-code` из `config.json:36` и `openai.chatgpt`) в папках `~/.vscode/extensions` или `~/.vscode-oss/extensions`. Проверка каталога (`dirHasChildStarting`, `src/main.js:2496-2502`) требует **подкаталог** вида `<extId>-<цифра>`, поэтому `anthropic.claude-code-helper-1.0` ложным срабатыванием не будет.

## Инварианты

1. **Вшитый `vscode-setup.exe` не запускается без совпадения SHA-256 (и размера, если он указан в манифесте) с `vendor/checksums.json`.** Держится в `scripts/windows/vscode.ps1:69` → `Confirm-HmArtifact` (`scripts/windows/_verify.ps1:64-104`); при несовпадении — `exit 1`.
2. **Вшитый `vscode.zip` на macOS проходит тот же вентиль до распаковки** — `verify_artifact "$ZIP"` (`scripts/macos/vscode.sh:34` → `_lib.sh:219-246`), при несовпадении `exit 1`.
3. **Ни один вшитый `.vsix` не ставится без подтверждённого SHA-256.** Windows: `Get-Vsix` вызывает `Confirm-HmArtifact` (`vscode.ps1:135`). macOS: `resolve_vsix` вызывает `verify_artifact` (`vscode.sh:110`).
4. **На macOS `.app` копируется в целевой каталог только после успешных `codesign -R` с Team ID `UBF8T346G9` и `spctl --assess`, и всё это — над root-owned staging внутри одного `admin_run`.** `scripts/macos/_lib.sh:336-352`; любой шаг падает — `set -e` и `|| exit 1` останавливают установку.
5. **Elevated-процесс никогда не исполняет user-writable CLI редактора напрямую.** Единственный путь — `Invoke-HmDeElevated` (`vscode.ps1:189, 201`); возврат `$null` трактуется как fail-closed (`vscode.ps1:190-194`).
6. **Обёртка де-элевации запускает целевой бинарь только при medium integrity.** `_deelev.ps1:572-575`: проверка `S-1-16-8192`, иначе `exit 210`, который родитель превращает в `Gate='refused'`.
7. **Факт установки расширения на Windows подтверждается каталогом на диске, а не выводом бинаря редактора.** `Test-HmExtInstalled` (`_deelev.ps1:59-72`) по `~\.vscode\extensions` и `~\.vscode-oss\extensions`, точный префикс `^<extId>-\d` и только каталоги.
8. **Повторный ретрай через Marketplace на Windows делается только при `Gate='medium'`.** `vscode.ps1:199-204`; при `unknown` второй задачи не создаётся.
9. **Отсутствие вшитого дистрибутива при отсутствующем редакторе даёт `exit 120`, а не `exit 1`.** `vscode.ps1:64`, `vscode.sh:29`. Код 120 в `src/main.js` означает «пропущено», а не «сломалось».
10. **Временные копии vsix убираются на любом выходе Windows-скрипта.** Блок расширений обёрнут в `try { … } finally { Remove-HmVsixTemps }` (`vscode.ps1:224, 273-275`).
11. **PATH для elevated-скрипта собирается без пользовательской ветки реестра.** `Update-Path` в `vscode.ps1:5-22` читает только `Path` уровня `Machine`.
12. **Успех Windows-шага требует обоих расширений — кроме случая, когда переменная `$codexVsix` пуста.** `vscode.ps1:253` и ветка `vscode.ps1:259-263`, условие которой — `if ($okClaude -and -not $okCodex -and -not $codexVsix)`. Гейт стоит на **пустой переменной**, а не на факте «vsix не вшит», а `Get-Vsix` (`vscode.ps1:130-153`) возвращает `''` в трёх случаях: не задан `$env:HM_VENDOR` (строка 131); файла нет (строка 133); файл **есть** и SHA-256 подтверждён (строка 135), но `Copy-Item` во временный файл или `OpenRead` упали — диск, антивирус, права (строки 149-152). В третьем случае `chatgpt.vsix` в сборке есть и Codex не встал, но скрипт всё равно печатает «Codex не вошёл в эту сборку» (строка 260) и делает `exit 0` (строка 262).
13. **Успех macOS-шага требует расширения Claude; Codex его не гейтит.** `vscode.sh:162` (`exit 0` по `EXT_OK_CLAUDE`) и `vscode.sh:159-161` (предупреждение вместо ошибки).
14. **Компонент считается установленным только при наличии приложения И обоих расширений.** `src/main.js:2593-2594` (`bothExts` и присваивание `out.vscode`); строки 2582-2586 — только комментарий об этом решении.

## Что ломается, если инвариант нарушить

1. Человек запускает под администратором подменённый `vscode-setup.exe` — то есть чужой код с полными правами на его машине под видом установки редактора.
2. То же на Mac: под root распаковывается и ставится в `/Applications` не тот архив, а человек считает, что поставил VS Code от Microsoft.
3. `.vsix` — это исполняемый код внутри редактора. Подменённый vsix получает доступ ко всему, что открыто в VS Code: исходники, токены в файлах, терминал.
4. В `/Applications` окажется бандл без действительной подписи Microsoft — например, собранный посреди установки процессом того же пользователя. Человек будет запускать его каждый день, считая это редактором.
5. Медиум-малварь того же пользователя заранее подкладывает свой `code.cmd`, и установщик выполняет его от администратора — обычное заражение превращается в полный захват машины.
6. Задача планировщика, случайно поднятая до high integrity, выполнит установку расширений с правами администратора — ровно тот сценарий, ради закрытия которого вся де-элевация и написана.
7. Установщик поверит выводу подменённого бинаря редактора и отчитается «расширение на месте», когда его нет. Человек нажмёт кнопку Claude и не найдёт панели, а установка при этом зелёная.
8. Две конкурентные задачи пишут в один каталог расширений одновременно — расширение может остаться полураспакованным, и панель не запустится, хотя обе установки «прошли».
9. Сборка без вшитого редактора красит компонент в ошибку, и человек, у которого всё остальное встало нормально, решает, что установка провалилась, и начинает её заново.
10. На каждой успешной установке в `%TEMP%` остаётся около 82 МБ мусора, который человек никогда не найдёт и не удалит.
11. Малварь, дописавшая свой каталог в пользовательский PATH, подсовывает свой `git`/`node` установщику, работающему с правами администратора.
12. На Windows человеку показывают зелёный шаг, хотя вшитый Codex не встал — он узнает об отсутствии панели только когда полезет её искать.
13. Человек на Mac без интернета получает красный компонент и уходит в повтор, хотя редактор и панель Claude у него уже стоят и работают.
14. Установщик снимает галочку с уже «установленного» VS Code и не доставляет недостающее расширение — сценарий «VS Code есть, панели нет» замолкает навсегда.

## Границы

- Компонент не ставит Cursor (`scripts/windows/cursor.ps1`, отдельный компонент `cursor`) и не ставит сам Claude Code CLI (компонент `claude`).
- Компонент `extension` («Расширение Claude Code») на Windows отвечает **только за Cursor**: `scripts/windows/extension.ps1:1-4` прямо говорит, что оба VS Code-расширения ставит `vscode.ps1`, а дубль убран сознательно.
- Codex в офлайн-издании под Windows не вшивается: `package.json:124` исключает `apps/chatgpt.vsix` из `win.extraResources`, обоснование — в `_buildNotes`, `package.json:34-53` (сам текст — строки 36-52; лимит 32-битного makensis на 2 ГБ, плюс продуктовое решение не добавлять 323 МиБ к скачиванию). Единственный путь установки Codex там — Marketplace, то есть интернет.
- На macOS `chatgpt-*.vsix` не входит в проверку полноты сборки: `tools/fetch-vendor-mac.sh:552-554` требует `vscode.zip` и оба `claude-code-*.vsix`, но не Codex.
- macOS-vsix архитектурно-специфичны (`claude-code-$(arch_tag).vsix`), universal-варианта у Marketplace нет — прямо сказано в комментарии `tools/fetch-vendor-mac.sh:134`.
- Скрипт не проверяет версию VS Code и не обновляет уже установленный редактор: наличие приложения означает «пропустить установку, доставить расширения».
- Скрипт не настраивает панель, не логинит в Claude и не открывает редактор после установки (`/MERGETASKS=!runcode` на Windows специально запрещает автозапуск).
- Проверочный шаг `verify.ps1` смотрит только расширение Claude и только если выбран компонент `extension` (`scripts/windows/verify.ps1:218-232`); `openai.chatgpt` он не проверяет вовсе.
- Установка через vendor на macOS всегда целится в `/Applications`; в `~/Applications` компонент только **обнаруживает** уже установленный редактор, но сам туда не ставит (`scripts/macos/vscode.sh:13-17`).

## Риски и открытые вопросы

- **Инвентарь противоречит коду.** Описание фичи в `_features.json` («Успех засчитывается только при обоих расширениях») верно лишь для Windows, и то с исключением: при отсутствующем `chatgpt.vsix` Windows завершается успехом с одной панелью Claude (`vscode.ps1:259-263`), а macOS **никогда** не гейтит успех по Codex (`vscode.sh:159-162`). Это ровно тот класс расхождения, ради которого заведён `tools/check-specs.js`.
- **Тест не покрывает ветку исключения.** Тест «P1 (vscode.ps1): успех только при обоих расширениях…» проверяет наличие строки `if ($okClaude -and $okCodex) { exit 0 }` и отсутствие старого `if ($okClaude) { exit 0 }`, но про ветку `vscode.ps1:259-263` не знает. Заголовок теста утверждает больше, чем тест проверяет.
- **Успешный шаг на macOS даёт незелёный детект.** `vscode.sh` завершается кодом 0 без Codex, а `detectComponents` требует оба расширения (`src/main.js:2593-2594`). При повторном запуске установщика компонент выглядит неустановленным, хотя шаг прошёл. В коде это осознанно (комментарий `src/main.js:2582-2586`), но для человека противоречиво.
- **Сообщение может соврать о причине.** `$codexVsix` пуст и когда vsix не вшит, и когда не удалось сделать читаемую временную копию (`vscode.ps1:149-152`). В обоих случаях печатается «Codex не вошёл в эту сборку» — во втором случае это неправда.
- **Идентификатор расширения задан в двух местах.** `vscode.ps1` и `vscode.sh` хардкодят `anthropic.claude-code`, а `src/main.js:2592`, `src/renderer/app.js:1283` и — транзитом через `HM_CLAUDE_EXT_ID` — `scripts/windows/verify.ps1:221` читают `config.json.claudeCodeExtensionId`. Сейчас значения совпадают (`config.json:36` = `anthropic.claude-code`), но изменение конфига разведёт установку и проверку.
- **`TODO-verify` в коде.** `scripts/macos/vscode.sh:48`: смена Microsoft Team ID приведёт к fail-closed остановке установки, и `VSCODE_TEAM_ID` придётся обновлять руками. Дата подтверждения Team ID в комментарии — 2026-07.
- **Ветка «редактор не подтвердил установку» продолжает работу.** `vscode.ps1:87-89` и `vscode.sh:82-84`: если приложение не появилось, скрипт всё равно идёт ставить расширения, и код выхода определяется уже только ими. Обработки «редактора нет, но расширение как-то встало» не предусмотрено.
- **`Gate='unknown'` даёт `exit 1` при, возможно, идущей установке.** `vscode.ps1:205-207` честно пишет об этом человеку, но компонент при этом красный, а установка может завершиться успешно через минуту.
- **Подход к подтверждению установки расходится между платформами.** На Windows вывод `--list-extensions` сознательно отвергнут как недоверенный сигнал (`vscode.ps1:158-160`), а на macOS `ext_present` (`vscode.sh:89-100`) построен именно на нём. Обоснования этой асимметрии в коде я не нашёл — не подтверждено кодом, намеренная ли это уступка.
- **Порог ожидания `Code.exe` — 60 секунд** (`vscode.ps1:82`); что происходит на машине, где Inno-установщик отработал медленнее, кодом не покрыто, кроме предупреждения и продолжения.
