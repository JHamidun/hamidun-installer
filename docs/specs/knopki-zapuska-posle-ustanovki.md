## Что обещает человеку

После установки человек не остаётся один на один с пустым рабочим столом и списком «что теперь набрать в терминале». На финальном экране есть кнопки, которые сами открывают рабочее место: главная — «▶ Открыть VS Code — начать здесь» (открывает папку проекта `~/HamidunStart` как воркспейс, а не безымянное окно), под раскрывающимся блоком «Ещё инструменты» — «Открыть Cursor» и «Запустить Claude в терминале (для продвинутых)», и отдельным блоком — «🎓 Открыть курс-симулятор», если курс реально стоит на машине.

Обещание, за которое можно спросить: клик по кнопке либо приводит к видимому результату (открылось окно редактора, открылась папка, открылось окно терминала с `claude`), либо на экране появляется текст с причиной и следующим шагом. Для кнопок «Открыть VS Code», «Запустить Claude в терминале» и «Открыть курс-симулятор» это подтверждается кодом: renderer ждёт результат IPC и на неуспехе дорисовывает подсказку (`src/renderer/app.js:2314-2324`, `2334-2345`, `2403-2426`). Для кнопки «Открыть Cursor» это НЕ так — см. «Риски».

## Как работает

**Разметка и условия показа кнопок** (`src/renderer/app.js:2258-2306`).
Главная кнопка `#ns-vscode` рисуется всегда, но при `editorMissing` — с атрибутом `disabled` и другой подписью (`2288-2290`). `#ns-cursor` рисуется только при `cursorSelected` (`2298`), `#ns-claude` — всегда (`2299`), блок курса с кнопкой `#ns-course` — только если `courseInstalled`, то есть курс встал в этой сессии (`STATE.installedEver.has('course')`) ИЛИ найден детекцией (`STATE.detected.course.installed`) (`2258-2260`). Там же чекбокс `#ns-autovscode` «Открыть VS Code на папке проекта при нажатии „Готово“», предустановленный из `fin.autoOpenCursorDefault` (`2306`); в `config.json` поле `finish.autoOpenCursorDefault` = `true`. Обработчик «Готово» (`142-154`) при отмеченном чекбоксе зовёт `launchVsCode()`, и если тот вернул ложь — не закрывает окно, а программно кликает по `#ns-vscode`, чтобы показать ту же подсказку.

**Мост renderer → main** (`src/preload.js:34-38`): `launchCursor`, `launchVsCode`, `launchCourse`, `openClaudeTerminal` — каждая вызывает `ipcRenderer.invoke` соответственно `'launch-cursor'`, `'launch-vscode'`, `'launch-course'`, `'open-claude-terminal'` **без единого аргумента**. Ни один путь из renderer'а в main не передаётся.

**VS Code на папке проекта** (`src/main.js:1938` → `launchVsCodeOn`, `1879-1936`).
Хендлер `'launch-vscode'` — однострочный делегат `launchVsCodeOn(path.join(os.homedir(), 'HamidunStart'))`, то есть `create` по умолчанию `true`. Функция сначала `fs.mkdirSync(dir, {recursive:true})` (ошибку не глушит вслепую), затем подтверждает `fs.statSync(dir).isDirectory()`, иначе `return false` (`1884-1886`). Дальше ветвление по платформе:

- **Windows** (`1887-1912`): `firstExisting` ищет `Code.exe` в `%USERPROFILE%\AppData\Local\Programs\Microsoft VS Code` и в `<ProgramFiles>\Microsoft VS Code` (`ProgramFiles` выводится из валидированного системного корня, `winPF()`, `src/main.js:2320`). Нашли — `winLaunchDeElevated(codeExe, dir)`. Не нашли — те же две локации для `Cursor.exe` (`1900-1904`), это запасной редактор. Нет ни одного — `spawnSync('explorer.exe', [dir])` и возврат **строки** `'explorer'` (`1907-1911`). Иначе `false`.
- **macOS** (`1913-1932`): `spawnSync('/usr/bin/open', ['-a', 'Visual Studio Code', dir])`, при `status === 0` → `true`; иначе то же с `Cursor`; иначе `open` на саму папку → строка `'finder'` или `false`. Здесь именно `spawnSync` — код возврата честный, а не fire-and-forget.

**Де-элевированный запуск на Windows** (`winLaunchDeElevated`, `src/main.js:1757-1870`). Установщик работает с правами администратора, поэтому редактор из него напрямую не спавнится. Основной путь: одноразовая задача планировщика с принципалом «текущий интерактивный пользователь», `InteractiveToken` + `RunLevel LeastPrivilege` (`1825-1826`); тело обёртки целиком уезжает в `-EncodedCommand` (`1811-1812`), транзиентный `task.xml` пишется в приватный high-integrity каталог из `winMakeSecureDir()` и удаляется сразу после `/Create` (`1782-1784`, `1849-1853`). Обёртка первыми строками ставит env-литералы `PSModulePath`/`Path`, затем сверяет integrity абсолютным `System32\whoami /groups` на SID `S-1-16-8192` (medium) и только при совпадении делает `Start-Process` редактора; путь папки идёт **одним** аргументом с вложенными кавычками (`1805-1810`). Коды: `0` — старт прошёл, `210` — gate не пройден, `211` — `Start-Process` бросил. Результат читается из «Last Result» задачи (`schtasks /Query /HRESULT /FO CSV /NH /V`, поле #6) неблокирующим опросом с шагом 400 мс и крайним сроком 30 с; значения `267009`/`267011` означают «ещё выполняется/не запускалась» (`1836-1846`, `1856-1869`). Любой отказ — в `folderFallback()`: абсолютный `%SystemRoot%\explorer.exe` **только на папку**, никогда на exe (`1760-1769`).

**Cursor** (`src/main.js:1583-1600`). Windows: создаётся и проверяется `~/HamidunStart`, затем ищется **единственный** путь `%USERPROFILE%\AppData\Local\Programs\cursor\Cursor.exe`; если он есть — `winLaunchDeElevated(cexe, startDir)`, если нет — управление доходит до финального `return false`. macOS: `spawn('/usr/bin/open', ['-a','Cursor'], {detached:true}).unref()` и **безусловный** `return true`.

**Папка курса** (`src/main.js:2003-2029`). Хендлер `'launch-course'` читает вшитый `config.json` → `course.targetDirDefault` (в репозитории это `%USERPROFILE%\HamidunCourse`) и резолвит его через `uninstallTargets.resolveCourseTarget(raw, os.homedir(), process.platform)` (`src/uninstall-targets.js:72-83`: на Windows раскрывается `%USERPROFILE%`, на macOS путь с `%` или `\` заменяется дефолтом `~/HamidunCourse`). Открывается подпапка `<target>/vibecoding-course` — именно там `CLAUDE.md` наставника. Две проверки перед запуском: каталог существует (иначе `{ok:false, reason:'no-dir'}`) и в нём есть `CLAUDE.md` (иначе `reason:'no-mentor'`). Затем `launchVsCodeOn(dir, {create:false})` — папку курса эта фича не создаёт никогда. Возврат: `true` → `{ok:true, how:'editor'}`; `'explorer'`/`'finder'` → `{ok:true, how:<то же>}`; всё прочее → `{ok:false, reason:'no-editor'}`. Renderer печатает под каждую причину свой текст (`src/renderer/app.js:2403-2426`) и понимает старый контракт «голый boolean» (`2390-2391`).

**Терминал с `claude`** (`src/main.js:2180-2248`).

- **Windows**: создаётся `~/HamidunStart`, туда пишется `claude-start.cmd` со строками: `@echo off`, `cd /d "%USERPROFILE%\HamidunStart"`, префикс PATH `%USERPROFILE%\.local\bin;%USERPROFILE%\AppData\Roaming\npm;%ProgramFiles%\nodejs`, `title Claude Code`, `where claude >nul 2>nul || (echo Claude Code не найден… & pause & exit /b 1)`, `claude`, `if errorlevel 1 pause` (`2204-2210`). Запуск — `spawn(<SystemRoot>\explorer.exe, [launcher], {detached:true, windowsHide:true})` → `true` (`2212-2215`). Если `explorer.exe` не найден — `return false` (`2216-2220`): под elevated-токеном `claude` не запускается никогда. Ошибка записи файла — тоже `false` (`2211`).
- **macOS**: `osascript` с двумя `-e` (`activate` + `do script "claude"`), обёрнутый в Promise; `true` только при коде выхода 0, таймаут 120 с → `false` (`2231-2244`). Большой таймаут — чтобы переждать системный диалог разрешения на управление Терминалом.

## Инварианты

1. **Ни один редактор не исполняется напрямую из elevated-процесса.** На Windows и VS Code, и Cursor стартуют только через `winLaunchDeElevated` (`src/main.js:1893`, `1904`, `1593`); фолбэк исполняет `explorer.exe` и передаёт ему **папку**, а не exe (`1760-1769`). Держится тестом «ИНВАРИАНТ: 0 прямых elevated editor-бинарь execution…».
2. **`true` от `winLaunchDeElevated` означает подтверждённый запуск.** Возврат `true` возможен только при `Last Result === '0'`; любое другое значение, отсутствие подтверждения или истёкшие 30 с уводят в `folderFallback()` (`src/main.js:1860-1866`).
3. **Путь папки доезжает до редактора одним аргументом.** В обёртке `-ArgumentList '"<папка>"'` — вложенные кавычки, поэтому пробел в имени пользователя не рвёт аргумент (`src/main.js:1809`).
4. **Редактору отдают только каталог.** После `mkdirSync` идёт `statSync(dir).isDirectory()`, и при несовпадении — `return false` до любого запуска (`src/main.js:1884-1886`).
5. **Кнопка курса ничего не создаёт и не открывает вслепую.** `launchVsCodeOn(dir, {create:false})` вызывается только после подтверждения, что `<target>/vibecoding-course` — каталог и в нём лежит `CLAUDE.md` (`src/main.js:2019-2023`).
6. **`claude` на Windows не может стартовать с правами администратора из этой кнопки.** Единственный путь запуска — через `explorer.exe`; при его недоступности хендлер честно возвращает `false` вместо прямого спавна (`src/main.js:2212-2220`).
7. **Renderer не задаёт цель запуска.** Все четыре `invoke` идут без аргументов (`src/preload.js:34-38`), а цели считаются в main из `os.homedir()` и вшитого `config.json` (`src/main.js:1589`, `1938`, `2005-2012`, `2183`).
8. **`.cmd`-лаунчер не бейкает абсолютные пути администратора.** В теле стоят `%USERPROFILE%` и `%ProgramFiles%`, раскрываемые в рантайме де-элевированным пользователем (`src/main.js:2204-2210`).
9. **Окно терминала не схлопывается молча.** Перед `claude` стоит `where claude` с сообщением и `pause`, а после — `if errorlevel 1 pause` (`src/main.js:2208-2210`).
10. **Кнопка курса различает три причины отказа.** `no-dir`, `no-mentor`, `no-editor` возвращаются раздельно (`src/main.js:2019-2028`) и печатаются тремя разными текстами (`src/renderer/app.js:2416-2426`).

## Что ломается, если инвариант нарушить

1. Первая сессия ученика идёт с правами администратора: любой файл, созданный Claude Code, получает admin-владельца; вдобавок medium-integrity процесс того же пользователя может подменить `Code.exe`/`Cursor.exe` в user-writable `%LOCALAPPDATA%` и получить исполнение под администратором.
2. Кнопка отчитывается «открыл», хотя окна нет. Человек ждёт редактор, ничего не появляется, подсказку он при этом не увидит (она рисуется только на `false`), а телеметрия зафиксирует «редактор открыт» — то есть и человек, и бот-помощник получают неверную картину.
3. У пользователя с пробелом в имени профиля (`C:\Users\John Doe`) редактор откроет не ту папку или откажется открывать: аргумент распадётся на два.
4. Редактор получает путь к файлу или к несуществующему объекту — вместо воркспейса открывается пустое окно/ошибка, и ученик не видит файлов проекта.
5. Кнопка «Открыть курс-симулятор» создала бы пустую папку `vibecoding-course` без `CLAUDE.md`. Ученик пишет «начать», отвечает ванильный Claude без наставника, и курс выглядит сломанным.
6. Вся первая сессия `claude` идёт под администратором с рабочим каталогом установщика (распаковка в `%TEMP%` у portable-сборки): файлы «пропадают», drag&drop в окно не работает из-за UIPI.
7. Renderer (не доверенный) смог бы назначить произвольную цель — elevated-процесс открыл бы чужой путь, включая UNC/WebDAV.
8. При запуске установщика «от имени другого администратора» лаунчер увёл бы ученика в чужой профиль: `cd` в `C:\Users\Admin\HamidunStart`, PATH от чужого пользователя — `claude` не нашёлся бы или работал бы не с теми файлами.
9. Окно терминала мигает и закрывается за долю секунды. Ученик видит вспышку и не знает ни что произошло, ни что делать.
10. Человек с целой папкой курса, но без редактора, получил бы совет «переустанови курс» — и потратил бы время впустую (ровно это и было до разделения причин, см. комментарий `src/main.js:2013-2017`).

## Границы

- Фича **ничего не устанавливает**: она только запускает уже установленное. Отсутствующий редактор или отсутствующий `claude` лечится повторным прогоном установщика — об этом говорят тексты подсказок, а не эти кнопки.
- Ни одна кнопка **не открывает панель-агент** и не использует URI вида `vscode://…/open` — это намеренно IDE-открытие папки (комментарий `src/main.js:1872-1875`, закреплено тестом «main.js: IPC launch-vscode открывает папку ~/HamidunStart (не агент-чат/URI)»).
- Кнопка «Открыть Cursor» рисуется по **выбору компонента** (`cursorSelected`), а не по факту установки (`src/renderer/app.js:2298` и комментарий `2430-2432`).
- Терминальная кнопка **не передаёт первый запрос** и не логинит в нейросеть — она лишь открывает окно с запущенным `claude`; вход и выбор доступа описаны отдельным блоком финального экрана.
- Поддерживаются только Windows и macOS: обе ветки закрыты `IS_WIN`/`IS_MAC` (`src/main.js:17-18`), на прочих платформах хендлеры доходят до `return false`.
- Соседние кнопки того же экрана — «Показать файл ключей» (`reveal-path`), «Открыть лог», памятка START-HERE, сохранение ключа Nomad — к этой фиче не относятся, хотя живут в том же блоке `ns-actions`.
- Уступка: на Windows `~/HamidunStart` создаётся кнопками (`create: true`, `src/main.js:1938`, `1589-1591`, `2184`) даже если установка туда ничего не клала, — чтобы редактор открыл реальный воркспейс, а не безымянное окно.

## Риски и открытые вопросы

1. **`launch-course` на Windows не дожидается промиса — и врёт о результате.** Хендлер объявлен синхронным (`src/main.js:2003`), а `launchVsCodeOn` на Windows при найденном редакторе возвращает `Promise` от `async function winLaunchDeElevated` (`1893`, `1904`, `1757`). Сравнения `r === true` и `r === 'explorer'` на промисе ложны (`2024-2027`), поэтому при **установленном** редакторе хендлер отдаёт `{ok:false, reason:'no-editor'}`, и ученик читает «Курс на месте, но не нашёлся редактор — ни VS Code, ни Cursor» (`src/renderer/app.js:2416-2419`), пока редактор в это время открывается. Корректно отрабатывает только ветка без единого редактора (`spawnSync` → строка `'explorer'`, `1907-1911`) и весь macOS (там все ветки синхронные). Тестом не покрыто.
2. **Тестов на `launch-course` и `open-claude-terminal` в `test/run-tests.js` нет вовсе.** Поиск по файлу даёт 0 вхождений строк `launch-course`, `launchCourse`, `ns-course`, `no-mentor`, `no-editor`, `open-claude-terminal`, `claude-start`, `where claude`, `ns-claude`. То есть непокрыты: три причины отказа курса, генерация `claude-start.cmd`, запрет прямого elevated-запуска `claude`, macOS-ветка `osascript`. Именно в непокрытом куске и сидит дефект №1. Инвентарь помечает фичу `tested: yes` — это верно лишь для VS Code-части.
3. **Заголовок теста «app.js: бейдж «рекомендуется» + финиш зовёт launchVsCode; Cursor-кнопка условная» (`test/run-tests.js:813`) относится к этой фиче, но процитировать его в шапке нельзя**: внутри него уже есть кавычки-ёлочки, а `tools/check-specs.js` вырезает заголовки регуляркой `«([^»]+)»` и получил бы обрезок. Он проверяет `launchVsCode()` на финише, класс `btn-sm primary` у `#ns-vscode`, условность Cursor-кнопки и наличие `#ns-autovscode`.
4. **`launch-cursor` на Windows ищет `Cursor.exe` только в одном месте** — `%USERPROFILE%\AppData\Local\Programs\cursor` (`src/main.js:1592`), тогда как `launchVsCodeOn` проверяет ещё и `<ProgramFiles>\cursor` (`1900-1903`). При системной установке Cursor кнопка вернёт `false`, а renderer на неуспех `#ns-cursor` **ничего не показывает** — обработчик только шлёт телеметрию на успех (`src/renderer/app.js:2433-2437`). Это ровно тот «пустой клик», против которого написаны подсказки у остальных кнопок.
5. **`launch-cursor` на macOS возвращает `true` безусловно** (`src/main.js:1595-1596`, fire-and-forget `spawn` + `return true`) — в отличие от `launchVsCodeOn`, где статус `open` проверяется (`1922-1930`). При отсутствующем Cursor уйдёт событие «редактор открыт» (`sendOpenEditorTelemetry`, `src/renderer/app.js:2436`), хотя ничего не открылось. Комментарий рядом с кнопкой (`2430-2432`) утверждает обратное: «Результат ЖДЁМ… слать „открыл редактор“ было бы враньём» — для macOS-ветки это утверждение не выполняется.
6. **Строковый `'explorer'` считается успехом на главной кнопке.** Когда редакторов нет, `launchVsCodeOn` возвращает `'explorer'` (`src/main.js:1910`), renderer видит truthy, шлёт телеметрию открытия редактора и не печатает ничего (`src/renderer/app.js:2332-2334`). Человек получает окно проводника вместо IDE без единого слова объяснения. В кнопке курса тот же исход объяснён текстом (`2407-2411`) — расхождение поведения между двумя кнопками.
7. **macOS-таймаут терминала — 120 с → `false`** (`src/main.js:2243`). Если пользователь думал над системным диалогом дольше двух минут, Терминал в итоге откроется, но подсказка «macOS не дал разрешение» уже будет напечатана.
8. `claude-start.cmd` перезаписывается при каждом клике в user-writable `~/HamidunStart` и запускается без проверки содержимого (`src/main.js:2211-2213`). Привилегий это не даёт (запуск идёт де-элевированно, от того же пользователя, который и может писать в файл), но и никакой верификации лаунчера перед запуском нет.
