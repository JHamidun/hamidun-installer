## Что обещает человеку

После установки человек не остаётся один на один с пустым рабочим столом и списком «что теперь набрать в терминале». На финальном экране есть кнопки, которые сами открывают рабочее место: главная — «▶ Открыть VS Code — начать здесь» (открывает папку проекта `~/HamidunStart` как воркспейс, а не безымянное окно, и сразу вкладкой — её `PROMPTS.md`: кнопка ✳ панели Claude в заголовке редактора видна только при открытом файле, без неё новичок панель не находит), под раскрывающимся блоком «Ещё инструменты» — «Открыть Cursor» и «Запустить Claude в терминале (для продвинутых)», и отдельным блоком — «🎓 Открыть курс-симулятор», если курс реально стоит на машине.

Обещание, за которое можно спросить: клик по кнопке либо приводит к видимому результату (открылось окно редактора, открылась папка, открылось окно терминала с `claude`), либо на экране появляется текст с причиной и следующим шагом. Для кнопок «Открыть VS Code», «Запустить Claude в терминале» и «Открыть курс-симулятор» это подтверждается кодом: renderer ждёт результат IPC и на неуспехе дорисовывает подсказку (`src/renderer/app.js:2535-2545`, `2334-2345`, `2403-2426`). Для кнопки «Открыть Cursor» это НЕ так — см. «Риски».

## Как работает

**Разметка и условия показа кнопок** (`src/renderer/app.js:2479-2527`).
Главная кнопка `#ns-vscode` рисуется всегда, но при `editorMissing` — с атрибутом `disabled` и другой подписью (`2288-2290`). `#ns-cursor` рисуется только при `cursorSelected` (`2298`), `#ns-claude` — всегда (`2299`), блок курса с кнопкой `#ns-course` — только если `courseInstalled`, то есть курс встал в этой сессии (`STATE.installedEver.has('course')`) ИЛИ найден детекцией (`STATE.detected.course.installed`) (`2258-2260`). Там же чекбокс `#ns-autovscode` «Открыть VS Code на папке проекта при нажатии „Готово“», предустановленный из `fin.autoOpenCursorDefault` (`2306`); в `config.json` поле `finish.autoOpenCursorDefault` = `true`. Обработчик «Готово» (`142-154`) при отмеченном чекбоксе зовёт `launchVsCode()`, и если тот вернул ложь — не закрывает окно, а программно кликает по `#ns-vscode` (`151`), рассчитывая показать ту же подсказку. **Страховка не работает ровно в том случае, ради которого написана**: при `editorMissing` эта же кнопка нарисована с атрибутом `disabled` (`2289`), а `HTMLElement.click()` на отключённом form control не диспатчит событие — слушатель `2330-2346`, который и дорисовывает `.ns-vscode-err`, не выполняется. Человек видит открытое окно установщика без единого слова объяснения (квитирования тоже не происходит: перед ним стоит `return`). Подсказка через этот путь появляется только тогда, когда кнопка НЕ `disabled`, то есть когда компонент `vscode` в этом прогоне не падал.

**Мост renderer → main** (`src/preload.js:34-36`, `38`): `launchCursor`, `launchVsCode`, `launchCourse`, `openClaudeTerminal` — каждая вызывает `ipcRenderer.invoke` соответственно `'launch-cursor'`, `'launch-vscode'`, `'launch-course'`, `'open-claude-terminal'` **без единого аргумента**. Ни один путь из renderer'а в main не передаётся. (Строка `37` того же блока — `nomadSetKey`, она аргумент передаёт, но к этой фиче не относится.)

**VS Code на папке проекта** (`src/main.js:2478` → `launchVsCodeOn`, `1887-1944`).
Хендлер `'launch-vscode'` — однострочный делегат `launchVsCodeOn(path.join(os.homedir(), 'HamidunStart'), { openFile: 'PROMPTS.md' })`, то есть `create` по умолчанию `true`. `openFile` — файл внутри папки, который редактор откроет вкладкой; уходит в запуск, только если это существующий ФАЙЛ (`deelevRoute.editorOpenFiles`, `src/deelev-route.js`: `statSync(...).isFile()`), иначе список пуст и открывается одна папка. Функция сначала `fs.mkdirSync(dir, {recursive:true})` (ошибку не глушит вслепую, `1889-1893`), затем подтверждает `fs.statSync(dir).isDirectory()`, иначе `return false` (`1894`). Дальше ветвление по платформе:

- **Windows** (`1895-1920`): `winVsCodeExe()` ищет `Code.exe` в `%LOCALAPPDATA%\Programs\Microsoft VS Code` и в `<ProgramFiles>\Microsoft VS Code` (`ProgramFiles` выводится из валидированного системного корня, `winPF()`), а затем рядом с `code.cmd` из свежего PATH (`<каталог>in\code.cmd` → `<каталог>\Code.exe`: установка VS Code в свою папку тоже находится; одиночный `code.cmd` без `Code.exe`, в том числе шим Cursor, не считается) — той же функцией редактор ищет детектор компонента и `vscode.ps1`. Только существование файла, под elevated-токеном ничего не запускается. Нашли — `winLaunchDeElevated(codeExe, dir, editorOpenFiles(dir, openFile))`: папка и, если есть, `PROMPTS.md`. Не нашли — те же две локации для `Cursor.exe` (`1908-1912`), это запасной редактор (запускается так же, с файлом). Нет ни одного — `spawnSync('explorer.exe', [dir])` и возврат **строки** `'explorer'` (`1915-1919`). Иначе `false`.
- **macOS** (`1921-1940`): `spawnSync('/usr/bin/open', ['-a', 'Visual Studio Code', dir, <dir>/PROMPTS.md])`, при `status === 0` → `true`; иначе то же с `Cursor`; иначе `open` на саму папку (без файла) → строка `'finder'` или `false`. Вторым аргументом идёт тот же `editorOpenFiles`, что и на Windows: `PROMPTS.md` только если он существует как файл, — кнопка ✳ панели Claude в заголовке редактора видна лишь при открытом файле. Здесь именно `spawnSync` — код возврата честный, а не fire-and-forget.

**Де-элевированный запуск на Windows** (`winLaunchDeElevated`, `src/main.js:1868-2094`). Установщик работает с правами администратора, поэтому редактор из него напрямую не спавнится. Основной путь: одноразовая задача планировщика с принципалом «пользователь ТОКЕНА этого процесса» — его SID читает `whoami /user /fo csv /nh` (абсолютный System32, доверенное окружение, `deelevRoute.parseWhoamiUserSid`), а не USERDOMAIN/USERNAME из окружения; SID не прочитан — задача не создаётся, идёт запасной путь, причина в `install.log`; `InteractiveToken` + `RunLevel LeastPrivilege` (`1833-1834`); тело обёртки целиком уезжает в `-EncodedCommand` (`1819-1820`), транзиентный `task.xml` пишется в приватный high-integrity каталог из `winMakeSecureDir()` и удаляется сразу после `/Create` (`1790-1792`, `1857-1861`). Обёртка первыми строками ставит env-литералы `PSModulePath`/`Path`, затем сверяет integrity абсолютным `System32\whoami /groups` на SID `S-1-16-8192` (medium) и только при совпадении делает `Start-Process` редактора; каждый путь — папка и, если есть, `PROMPTS.md` — идёт **отдельным** аргументом в своих вложенных кавычках (`deelevRoute.psArgList`: хвостовые `\` удваиваются, чтобы закрывающая кавычка не съелась; путь с `"`, переводом строки или NUL не выразить — тогда файл отбрасывается, а невыразимая папка сразу ведёт в `folderFallback()`). Запасной путь через токен оболочки передаёт те же аргументы. Коды: `0` — старт прошёл, `210` — gate не пройден, `211` — `Start-Process` бросил. Результат читается из «Last Result» задачи (`schtasks /Query /HRESULT /FO CSV /NH /V`, поле #6) неблокирующим опросом с шагом 400 мс и крайним сроком 30 с; значения `267009`/`267011` означают «ещё выполняется/не запускалась» (`1844-1854`, `1864-1877`). **Запасной путь (06.10).** Если задача доказанно ничего не запустила — сбой до `/Run` (нет системных программ, staging, XML, `/Create`, `/Run`), Last Result `210` или HRESULT планировщика вроде `0x80070005` (решает `deelevRoute.shellFallbackAllowed`, `src/deelev-route.js`), — тот же редактор запускается с проверенным medium-токеном оболочки Explorer: `winShellTokenLaunch` (`src/main.js:1943-2009`) дот-сорсит вшитый `_deelev.ps1` и зовёт `Invoke-HmAsShellUser -NoWait` (`CreateProcessWithTokenW`; уровень и владелец токена проверяются до запуска). Подтвердил запуск — `true`. У людей ровно этот случай давал «открывается только папка»: задача планировщика отказывала целиком. Остальные отказы (`211`, таймаут опроса, запасной путь не смог) — в `folderFallback()`: абсолютный `%SystemRoot%\explorer.exe` **только на папку**, никогда на exe; он возвращает `'explorer'`, а не `true` — вызывающий различает «редактор открыт» и «открыта папка». Каждый исход — строка `[launch] Открыть редактор: …` в `install.log` (путь, Gate, «Last Result» в hex, причина).

**Cursor** (`src/main.js:1983-2004`). Windows: создаётся и проверяется `~/HamidunStart`, затем ищется **единственный** путь `%USERPROFILE%\AppData\Local\Programs\cursor\Cursor.exe`; если он есть — `winLaunchDeElevated(cexe, startDir, editorOpenFiles(startDir, 'PROMPTS.md'))` (папка и `PROMPTS.md`, как у главной кнопки), если нет — управление доходит до финального `return false`. macOS: `spawn('/usr/bin/open', ['-a','Cursor'], {detached:true}).unref()` и **безусловный** `return true`.

**Папка курса** (`src/main.js:2492-2518`). Хендлер `'launch-course'` читает вшитый `config.json` → `course.targetDirDefault` (в репозитории это `%USERPROFILE%\HamidunCourse`) и резолвит его через `uninstallTargets.resolveCourseTarget(raw, os.homedir(), process.platform)` (`src/uninstall-targets.js:82-93`: на Windows раскрывается `%USERPROFILE%`, на macOS путь с `%` или `\` заменяется дефолтом `~/HamidunCourse`). Открывается подпапка `<target>/vibecoding-course` — именно там `CLAUDE.md` наставника. Две проверки перед запуском: каталог существует (иначе `{ok:false, reason:'no-dir'}`) и в нём есть `CLAUDE.md` (иначе `reason:'no-mentor'`). Затем `launchVsCodeOn(dir, {create:false})` — папку курса эта фича не создаёт никогда; файл здесь не передаётся, курс открывается одной папкой. Возврат: `true` → `{ok:true, how:'editor'}`; `'explorer'`/`'finder'` → `{ok:true, how:<то же>}`; всё прочее → `{ok:false, reason:'no-editor'}`. Renderer печатает под каждую причину свой текст (`src/renderer/app.js:2641-2669`) и понимает старый контракт «голый boolean» (`2390-2391`).

**Терминал с `claude`** (`src/main.js:2688-2757`).

- **Windows** (`winOpenClaudeTerminal`, `src/main.js`): создаётся `~/HamidunStart` (`mkdirSync`), затем окно открывает **токен оболочки** — `winShellTokenRun({ script: deelevRoute.CLAUDE_TERMINAL_SCRIPT, cwd: startDir, label: 'claude-terminal' })` → `Invoke-HmAsShellUser -CmdScript … -WorkingDirectory … -NoWait` (`scripts/windows/_deelev.ps1`). Файла-лаунчера больше нет. До 09.10.2026 сюда писался `claude-start.cmd` (запись из-под админа по пути в пользовательскую папку — её уводила заранее подложенная ссылка) и отдавался `explorer.exe`, а тот без живой оболочки исполнил бы файл сам, под админом, по ассоциациям из `HKCU`. Команда — одна фиксированная строка для `cmd.exe /d /e:on /v:off /s /c "…"` (`CLAUDE_TERMINAL_SCRIPT` в `src/deelev-route.js`), команды разделены « & »: `chcp 65001 >nul`, `title Claude Code`, `set "PATH=%USERPROFILE%\.local\bin;%USERPROFILE%\AppData\Roaming\npm;%ProgramFiles%\nodejs;%PATH%"`, `where claude >nul 2>nul || (echo Claude Code не найден… & echo. & pause & exit /b 1)`, `call claude`, `if errorlevel 1 pause`. `cd /d` в тексте нет: рабочая папка `~/HamidunStart` едет отдельным полем запуска (`lpCurrentDirectory`), и перед запуском примитив её проверяет (внутри профиля, ни одной ссылки ниже корня профиля, существует). `%USERPROFILE%` и `%ProgramFiles%` раскрывает сам `cmd` у ребёнка — под пользователем окна, а не под нашим токеном. `chcp 65001` стоит первой командой: кодовая страница окна — UTF-8 для русского текста ниже. Успех кнопки — `Gate='medium'` и код 0 (`cmd` не упал за 3 с, окно живёт); `refused` (оболочка не обычного уровня или другая учётная запись), `unavailable` (нет оболочки, не запущена служба «Вторичный вход», рабочая папка не прошла проверку), `unknown` и код ≠ 0 дают `false` — renderer покажет «Не удалось открыть терминал. Открой командную строку (Пуск → cmd) и набери claude.». Запасного запуска нет: ни через `explorer.exe`, ни под администратором. Исход (Gate, код, причина) — строкой `[launch] Войти в Claude: …` в `install.log`. Ответ приходит через ~3 с (`-NoWait` ждёт, не упало ли окно), поэтому пока запуск идёт, кнопка `#ns-claude` выключена (`src/renderer/app.js`), а `winOpenClaudeTerminal` отдаёт повторным нажатиям тот же идущий запуск (`_winTerminalBusy`, снимается на любом исходе) — второго окна нет.
- **macOS**: создаётся `~/HamidunStart` (как на Windows), затем `osascript` открывает в нём Terminal: `deelevRoute.claudeTerminalOsaArgs(startDir)` отдаёт скрипт `on run argv … set cmd to "cd " & quoted form of (item 1 of argv) & " && claude" … tell application "Terminal" … do script cmd … end run`, а путь едет ПОСЛЕДНИМ аргументом `osascript`, не в тексте скрипта — пробел, апостроф, кавычка или «$» в пути остаются одним словом для `cd` (`quoted form of` экранирует для оболочки, экранировать для AppleScript нечего). Папка не создалась или это не каталог — прежний сценарий, Terminal в домашней папке. Обёрнуто в Promise; `true` только при коде выхода 0, таймаут 120 с → `false`. Большой таймаут — чтобы переждать системный диалог разрешения на управление Терминалом. Живой запуск `osascript` в тестах недоступен (нет macOS): держится прогоном построения аргументов и проверкой исходника.

## Инварианты

1. **Ни один редактор не исполняется напрямую из elevated-процесса.** На Windows и VS Code, и Cursor стартуют только через `winLaunchDeElevated` (`src/main.js:2030`, `1912`, `1601`); фолбэк исполняет `explorer.exe` и передаёт ему **папку**, а не exe (`1768-1777`). Держится тестом «ИНВАРИАНТ: 0 прямых elevated editor-бинарь execution…». Учётку, в чьём сеансе стартует обёртка, определяет не окружение (USERDOMAIN/USERNAME лежат в HKCU\Volatile Environment и пишутся процессом того же пользователя), а токен: `<UserId>` — SID из `whoami /user` (проверено на настоящем планировщике: SID в `<UserId>` при `InteractiveToken` + `LeastPrivilege` принимается, задача идёт на medium).
2. **(до правки после 24.08) `true` от `winLaunchDeElevated` означал «редактор запущен ИЛИ открыт проводник на папке».** Сейчас `true` — только подтверждённый запуск редактора (Last Result `0` задачи или запуск запасным путём с medium-токеном оболочки), папка — `'explorer'`; ниже — описание прежнего поведения. Подтверждённым стартом редактора является только внутренний случай `Last Result === '0'`, но наружу он неотличим от отката: `return resolve(lr === '0' ? true : folderFallback())` (`src/main.js:2389`), а сам `folderFallback()` возвращает `true`, когда `explorer.exe` существует и `folderArg` задан (`1768-1777`) — то есть в нормальном случае. Через `done(folderFallback())` уходят все отказы: нет `ps`/`schtasks`/`whoami` (`1786`), не заперт staging (`1791`), не записался `task.xml` (`1858`), провал `/Create` (`1860`) и `/Run` (`1862`), истёкшие 30 с (`1873`). Значит при exit `210` (gate не пройден), `211` (`Start-Process` бросил) и по таймауту функция всё равно отдаёт `true`. Инвариант в этом виде **не держится**; тест «P0-D/P1-1 launch …» его не закрывает — он лишь grep'ает исходник на строку `lr === '0' ? true : folderFallback()` (`test/run-tests.js:1275`), семантику возвращаемого значения не проверяя.
3. **Каждый путь доезжает до редактора одним целым аргументом.** В обёртке `-ArgumentList '"<папка>"','"<папка>\PROMPTS.md"'` — у каждого пути свои вложенные кавычки (`deelevRoute.psArgList`), поэтому пробел, кириллица или апостроф в имени пользователя не рвут аргумент и не склеивают папку с файлом (`src/main.js:2299`). Проверено прогоном с настоящим `Start-Process`.
4. **Воркспейсом редактору отдают только каталог, вкладкой — только существующий файл.** После `mkdirSync` идёт `statSync(dir).isDirectory()`, и при несовпадении — `return false` до любого запуска (`src/main.js:2412`); `PROMPTS.md` добавляется вторым аргументом, только если `statSync(...).isFile()` (`deelevRoute.editorOpenFiles`).
5. **Кнопка курса ничего не создаёт и не открывает вслепую.** `launchVsCodeOn(dir, {create:false})` вызывается только после подтверждения, что `<target>/vibecoding-course` — каталог и в нём лежит `CLAUDE.md` (`src/main.js:2515-2519`).
6. **`claude` на Windows не может стартовать с правами администратора из этой кнопки.** Единственный путь запуска — токен оболочки (ровно medium и тот же пользователь, проверяется до запуска); на любом отказе хендлер возвращает `false` — без прямого спавна, без `explorer.exe` и без файла-лаунчера (`winOpenClaudeTerminal`, `src/main.js`). Держится тестами «U5 (прогон main.js с заглушками): …» и «U5 (статика): main.js — …» из шапки.
7. **Renderer не задаёт цель запуска.** Все четыре `invoke` идут без аргументов (`src/preload.js:34-36`, `38`), а цели считаются в main из `os.homedir()` и вшитого `config.json` (`src/main.js:1991`, `1946`, `2013-2020`, `2191`).
8. **Команда окна терминала не несёт абсолютных путей администратора.** В тексте стоят `%USERPROFILE%` и `%ProgramFiles%`, их раскрывает сам `cmd` у ребёнка под пользователем окна; в «чужой учётке» профиль администратора был бы другим, а запуск там отказывает ещё до окна (`refused`). Рабочая папка — отдельное проверяемое поле запуска, а не часть текста.
9. **Окно терминала не схлопывается молча.** Перед `claude` стоит `where claude` с сообщением и `pause`, а после — `if errorlevel 1 pause` (`src/main.js:2704-2706`); сам `claude` вызывается через `call`, иначе при npm-шиме `claude.cmd` строка с `pause` не исполняется. Держится прогоном настоящего `cmd.exe` с фейковым `claude.cmd` и мутантом без `call`.
10. **Кнопка курса различает три причины отказа.** `no-dir`, `no-mentor`, `no-editor` возвращаются раздельно (`src/main.js:2515-2524`) и печатаются тремя разными текстами (`src/renderer/app.js:2658-2669`).

## Что ломается, если инвариант нарушить

1. Первая сессия ученика идёт с правами администратора: любой файл, созданный Claude Code, получает admin-владельца; вдобавок medium-integrity процесс того же пользователя может подменить `Code.exe`/`Cursor.exe` в user-writable `%LOCALAPPDATA%` и получить исполнение под администратором.
2. Кнопка отчитывается «открыл», хотя редактора нет. **Это не гипотеза на случай регресса, а текущее поведение главной кнопки при ЛЮБОМ отказе де-элевации** (exit `210`/`211`, таймаут 30 с, сбой `schtasks`): наверх уходит голый `true` от `folderFallback()`, renderer шлёт `sendOpenEditorTelemetry()` (`src/renderer/app.js:2554`) и не печатает ни одной подсказки — она рисуется только на `!ok` (`2334`). Человек получает окно проводника вместо IDE без объяснений, а телеметрия и бот-помощник — «редактор открыт».
3. У пользователя с пробелом в имени профиля (`C:\Users\John Doe`) редактор откроет не ту папку или откажется открывать: аргумент распадётся на два.
4. Редактор получает путь к файлу или к несуществующему объекту — вместо воркспейса открывается пустое окно/ошибка, и ученик не видит файлов проекта. Несуществующий `PROMPTS.md` VS Code открыл бы новой пустой вкладкой — вместо памятки чистый лист.
5. Кнопка «Открыть курс-симулятор» создала бы пустую папку `vibecoding-course` без `CLAUDE.md`. Ученик пишет «начать», отвечает ванильный Claude без наставника, и курс выглядит сломанным.
6. Вся первая сессия `claude` идёт под администратором с рабочим каталогом установщика (распаковка в `%TEMP%` у portable-сборки): файлы «пропадают», drag&drop в окно не работает из-за UIPI.
7. Renderer (не доверенный) смог бы назначить произвольную цель — elevated-процесс открыл бы чужой путь, включая UNC/WebDAV.
8. При запуске установщика «от имени другого администратора» лаунчер увёл бы ученика в чужой профиль: `cd` в `C:\Users\Admin\HamidunStart`, PATH от чужого пользователя — `claude` не нашёлся бы или работал бы не с теми файлами.
9. Окно терминала мигает и закрывается за долю секунды. Ученик видит вспышку и не знает ни что произошло, ни что делать. Без `chcp 65001` окно не закрывается, но русский текст в нём нечитаем.
10. Человек с целой папкой курса, но без редактора, получил бы совет «переустанови курс» — и потратил бы время впустую (ровно это и было до разделения причин, см. комментарий `src/main.js:2509-2513`).

## Границы

- Фича **ничего не устанавливает**: она только запускает уже установленное. Отсутствующий редактор или отсутствующий `claude` лечится повторным прогоном установщика — об этом говорят тексты подсказок, а не эти кнопки.
- Ни одна кнопка **не открывает панель-агент** и не использует URI вида `vscode://…/open` — это намеренно IDE-открытие папки, плюс вкладка `PROMPTS.md`; панель Claude человек открывает сам кнопкой ✳, которая видна потому, что файл открыт (комментарий `src/main.js:2398-2401`, закреплено тестом «main.js: IPC launch-vscode открывает папку ~/HamidunStart (не агент-чат/URI)»).
- Кнопка «Открыть Cursor» рисуется по **выбору компонента** (`cursorSelected`), а не по факту установки (`src/renderer/app.js:2519` и комментарий `2430-2432`).
- Терминальная кнопка **не передаёт первый запрос** и не логинит в нейросеть — она лишь открывает окно с запущенным `claude`; вход и выбор доступа описаны отдельным блоком финального экрана.
- Поддерживаются только Windows и macOS: обе ветки закрыты `IS_WIN`/`IS_MAC` (`src/main.js:41-42`), на прочих платформах хендлеры доходят до `return false`.
- Соседние кнопки того же экрана — «Показать файл ключей» (`reveal-path`), «Открыть лог», памятка START-HERE, сохранение ключа Nomad — к этой фиче не относятся, хотя живут в том же блоке `ns-actions`.
- Уступка: на Windows `~/HamidunStart` создаётся кнопками (`create: true`, `src/main.js:2478`, `1597-1599`, `2192`) даже если установка туда ничего не клала, — чтобы редактор открыл реальный воркспейс, а не безымянное окно.

## Риски и открытые вопросы

1. **`launch-course` на Windows не дожидается промиса — и врёт о результате.** Хендлер объявлен синхронным (`src/main.js:2499`), а `launchVsCodeOn` на Windows при найденном редакторе возвращает `Promise` от `async function winLaunchDeElevated` (`1901`, `1912`, `1765`). Сравнения `r === true` и `r === 'explorer'` на промисе ложны (`2032-2035`), поэтому при **установленном** редакторе хендлер отдаёт `{ok:false, reason:'no-editor'}`, и ученик читает «Курс на месте, но не нашёлся редактор — ни VS Code, ни Cursor» (`src/renderer/app.js:2658-2661`), пока редактор в это время открывается. Корректно отрабатывает только ветка без единого редактора (`spawnSync` → строка `'explorer'`, `1915-1919`) и весь macOS (там все ветки синхронные). Тестом не покрыто.
2. **Тестов на `launch-course` в `test/run-tests.js` нет.** Непокрыты: три причины отказа курса и macOS-ветка `osascript` (только построение аргументов и проверка исходника). Windows-ветка `open-claude-terminal` с 09.10.2026 покрыта: обработчик исполняется с заглушками токена оболочки (нет записи файла, нет `spawn`, ответ `false` на каждый отказ), а команда окна — настоящим `cmd.exe` при враждебных именах профиля. Именно в непокрытом куске и сидит дефект №1. Инвентарь помечает фичу `tested: yes` — это верно для VS Code-части и терминала на Windows.
3. **Заголовок теста «app.js: бейдж «рекомендуется» + финиш зовёт launchVsCode; Cursor-кнопка условная» (`test/run-tests.js:830`) относится к этой фиче, но процитировать его в шапке нельзя**: внутри него уже есть кавычки-ёлочки, а `tools/check-specs.js` вырезает заголовки регуляркой `«([^»]+)»` и получил бы обрезок. Он проверяет `launchVsCode()` на финише, класс `btn-sm primary` у `#ns-vscode`, условность Cursor-кнопки и наличие `#ns-autovscode`.
4. **`launch-cursor` на Windows ищет `Cursor.exe` только в одном месте** — `%USERPROFILE%\AppData\Local\Programs\cursor` (`src/main.js:1998-1999`), тогда как `launchVsCodeOn` проверяет ещё и `<ProgramFiles>\cursor` (`1908-1912`). При системной установке Cursor кнопка вернёт `false`, а renderer на неуспех `#ns-cursor` **ничего не показывает** — обработчик только шлёт телеметрию на успех (`src/renderer/app.js:2681-2685`). Это ровно тот «пустой клик», против которого написаны подсказки у остальных кнопок.
5. **`launch-cursor` на macOS возвращает `true` безусловно** (`src/main.js:2000-2002`, fire-and-forget `spawn` + `return true`) — в отличие от `launchVsCodeOn`, где статус `open` проверяется (`1930-1932`). При отсутствующем Cursor уйдёт событие «редактор открыт» (`sendOpenEditorTelemetry`, `src/renderer/app.js:2684`), хотя ничего не открылось. Комментарий рядом с кнопкой (`2430-2432`) утверждает обратное: «Результат ЖДЁМ… слать „открыл редактор“ было бы враньём» — для macOS-ветки это утверждение не выполняется.
6. **Строковый `'explorer'` считается успехом на главной кнопке.** Когда редакторов нет, `launchVsCodeOn` возвращает `'explorer'` (`src/main.js:2443`), renderer видит truthy, шлёт телеметрию открытия редактора и не печатает ничего (`src/renderer/app.js:2553-2555`). Человек получает окно проводника вместо IDE без единого слова объяснения. В кнопке курса тот же исход объяснён текстом (`2407-2411`) — расхождение поведения между двумя кнопками.
7. **macOS-таймаут терминала — 120 с → `false`** (`src/main.js:2752`). Если пользователь думал над системным диалогом дольше двух минут, Терминал в итоге откроется, но подсказка «macOS не дал разрешение» уже будет напечатана.
8. **Живой запуск окна через `CreateProcessWithTokenW` автотестом не покрыт** (нужен `SeImpersonatePrivilege` администратора, а тесты идут без повышения): проверены строка запуска, рабочая папка и порядок проверок на подменённом системном слое, но не сам вызов Windows. Не проверено на живой машине: получает ли окно фокус поверх окна установщика; работает ли в нём Ctrl+C так же, как в окне, открытом Проводником (служба «Вторичный вход» неявно включает `CREATE_NEW_CONSOLE` и `CREATE_NEW_PROCESS_GROUP`); собирается ли окружение ребёнка (`PATH`, `ProgramFiles`) из профиля пользователя, как следует из документации при пустом `lpEnvironment`. Команда сама дополняет `PATH` каталогами `claude` и `node`, поэтому от последнего пункта зависит лишь полнота остального `PATH`. Прежний пункт про перезапись `claude-start.cmd` при каждом клике снят вместе с файлом.
9. **Нечётное число двойных кавычек в `%PATH%` ломает однострочную команду окна молча.** Прежний `claude-start.cmd` писал по одной команде на строку, и лишняя кавычка в `PATH` портила только строку с `set`; в одной строке `/c` она делает всё остальное частью аргумента `set`. Прогон настоящего `cmd.exe` с `PATH`, в котором есть `C:\a"b`: окно ничего не печатает и закрывается, код 0 — claude не запущен; с `C:\a"b&c` — «не является внутренней командой» и код 1. Парные кавычки, `^` и `(x86)` в `PATH` на запуск не влияют. Принято осознанно: порча системной переменной редкая, а правка с отложенным раскрытием (`!PATH!`) сломала бы имена профиля с «!», которые нормальны.
