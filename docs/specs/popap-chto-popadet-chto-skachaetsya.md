## Что обещает человеку

До того как отдать установщику права администратора, человек может нажать одну кнопку и увидеть полный список того, что появится на его компьютере: имя каждого компонента, его описание своими словами и вес. Список не рекламный и не выборочный — он собирается из того же `components.json`, по которому потом идёт установка, и показывает всё, что показано на экране выбора (кроме служебного скрытого шага проверки).

Второе обещание — про честность цифры. Число рядом с пунктом означает ровно одно и это проговорено словами в самом окне: в офлайн-издании — вес дистрибутива внутри уже скачанного файла установщика, в лёгком — сколько байт будет докачано с сервера. Там же сказано, что после установки программа займёт на диске больше, потому что установщик распаковывается. Где точного числа нет — на его месте не появляется ничего: строка обрывается на имени компонента, второй половины заголовка нет вовсе, и никакого прочерка или заглушки вместо цифры не рисуется (`src/renderer/app.js:922` при пустом `sizeText` не вставляет ни символа, ни элемента; у `.wi-size`/`.wi-name` в `src/renderer/styles.css:665-671` нет ни `content`, ни псевдоэлемента). Вместо правдоподобной выдумки человек получает отдельную фразу «мы её заранее не знаем — и не придумываем».

## Как работает

**Вход.** Две кнопки, обе вешают один обработчик `showWhatInstalls` (`src/renderer/app.js:125-134`): `#btn-wc-what` на приветственном экране (статичная подпись «Что именно установится?», `src/renderer/index.html:77`) и `#btn-what-installs` на экране выбора (`src/renderer/index.html:106`). Подпись второй кнопки перезаписывается в `init()` по изданию: `lite` → «📦 Что скачается на мой ПК?», иначе «📦 Что попадёт на мой ПК?». В статике лежит офлайн-вариант; тест отдельно запрещает статичной подписи обещать загрузку.

**Сборка строк** (`showWhatInstalls`, `src/renderer/app.js:913-934`). Обход `STATE.groups` → `g.components`; компоненты с `c.hidden` пропускаются (это `verify` в `components.json`). Для каждого:
- `componentSizeText(c)` даёт текст размера;
- если текст пустой — счётчик `unknown++`;
- имя (`escapeHtml(c.name)`), описание (`escapeHtml(c.desc || '')`) и размер вставляются в `<li>`;
- если `componentUnconfigured(c)` истинно (у компонента есть `needsConfig`, а соответствующий путь в `config.json` пуст — `src/renderer/app.js:400-405`), добавляется жёлтая строка `⚠ + unconfiguredNoteText(c)`. Это то же предупреждение, что и на карточке: в этом окне описание читают отдельно от карточки.

**Откуда берётся число** (`componentSizeBytes`, `src/renderer/app.js:1166-1174`) — две ветки по `STATE.edition`:
- `lite`: `STATE.remoteSizes[c.id]` — точный `sizeBytes` архива докачки. Карту строит main: `remoteSizesForRenderer()` (`src/main.js:657-668`) идёт по `loadRemoteMaps().compRemote` и берёт `remoteFetch.pickEntry(reg, rid, process.platform)` из `remote-components.json`; отдаётся в renderer через `bootstrap.remoteSizes` (`src/main.js:538`, принимается в `src/renderer/app.js:78`);
- иначе (офлайн): `c.sizeBytes[STATE.platform]` из `components.json`. Эти числа руками не пишут — их считает `tools/sync-sizes.js`, обходя реальный каталог `vendor/` по карте `VENDOR_PARTS[платформа][id]` (`tools/sync-sizes.js:79-130`).

Ни одна ветка не подставляет число «по аналогии»: в lite вшитый размер сознательно не показывается, потому что lite везёт лишь часть vendor и `components.json` не знает, какой именно кусок доехал (комментарий `src/renderer/app.js:1161-1165`).

**Развёрнутая подпись** (`componentSizeText`, `src/renderer/app.js:1201-1209`) склеивает через ` · `: `~<fmtBytesRu(байты)>` плюс слово «скачается» (lite) или «внутри установщика» (офлайн), затем `componentSizeNote(c)` — строку `sizeNote` из `components.json`, которая может быть платформенной (`{win32, darwin}`, `src/renderer/app.js:1192-1197`). Пример из `components.json`: у `pydeps` на win32 «+ браузер Chromium докачивается из интернета при установке», на darwin «браузер для автоматизации уже внутри». Если байт нет, но `sizeNote` есть (`bridge`, `claude-desktop`, `chatgpt-desktop`), текст непустой — прочерка не будет, будет пометка словами.

**Итог сверху** (`src/renderer/app.js:938-948`). Не более одного из двух блоков, и оба считаются по ВЫБРАННЫМ компонентам (`selectedIds()`, `src/renderer/app.js:349-351`), а не по всему списку:
- `downloadTotalBytes()` > 0 (только `lite`, `src/renderer/app.js:1213-1217`) → «**Скачается: ~X**» с оговоркой про докачку с сервера с проверкой целостности;
- иначе `bundledTotalBytes()` > 0 (только офлайн, `src/renderer/app.js:1223-1226`) → «**Внутри установщика: ~X**» с объяснением, почему сам файл установщика меньше суммы (внутри всё сжато).

Обе ветки условные (`if (dlBytes > 0) {…} else if (bundledBytes > 0) {…}`), третьей нет: при обеих суммах в нуле `totalLead` остаётся пустой строкой и блока сверху не будет вовсе. Ноль достижим двумя обычными путями, но **не** через пустой `selectedIds()`: этот список пустым не бывает никогда — в нём всегда лежит скрытый `verify`. Инициализация `STATE.selected[c.id] = !!c.default` идёт по ВСЕМ компонентам групп, скрытые не отфильтрованы (`src/renderer/app.js:91-99`), а у `verify` одновременно `"hidden": true` и `"default": true` (`components.json:98-105`). Снять его нечем: карточки в UI нет (`renderGroups` отбрасывает `c.hidden`, `src/renderer/app.js:371`), поэтому `toggle()` (`src/renderer/app.js:331-336`) по нему не вызывается; сброс по детекции скрытые явно пропускает (`if (STATE.detected[id].installed && c && !c.hidden && …)`, `src/renderer/app.js:232`); `disableDependents` (`src/renderer/deps.js:15-22`) гасит только тех, у кого `requires` содержит выключаемый id, а у `verify` `"requires": []` (`components.json:104`); «Удалить» показывается лишь для видимых карточек и только для `REMOVABLE = ['course','uv','mascot','bridge']` (`src/renderer/app.js:43,513`). Первый путь к нулю — человек снял все ВИДИМЫЕ галочки: в выбранных остаётся `['verify']`, и обе суммы всё равно 0, потому что у `verify` нет ни `sizeBytes` в `components.json`, ни записи в `remote-components.json`. Второй — в lite выбран только курс: записи `course` в `remote-components.json` нет (в реестре `uv, git, node, vscode, cursor, claude, mascot, nomad, config, pydeps, extension, handy`), а `bundledTotalBytes()` в lite возвращает 0 по построению.

**Пояснительные абзацы** (`src/renderer/app.js:949-961`). Строка `unit` зависит от издания; далее общая фраза «После установки программа занимает на диске больше: установщик распаковывается»; и только если `unknown > 0` — приписка «Там, где цифры нет, мы её заранее не знаем — и не придумываем».

**Показ.** `openModal({id:'what-installs', emoji:'📦', title: lite ? 'Что скачается на мой ПК' : 'Что попадёт на мой ПК', blocking:false, closeLabel:'Закрыть'})` (`src/renderer/app.js:878-902`). Неблокирующая модалка: закрывается кнопкой и кликом по затемнённому фону. Повторный клик по кнопке при уже открытом окне возвращает `null` и второго окна не создаёт (проверка `document.getElementById(id)` в начале `openModal`).

**Форматирование числа** (`fmtBytesRu`, `src/renderer/app.js:1142-1148`): до 1000 МиБ — целые «N МБ» с нижней отсечкой `Math.max(1, …)`, дальше — гигабайты с одним знаком после запятой: «N ГБ» или «N,N ГБ». Запятая появляется только при дробном результате — `String(Math.round((mb / 1024) * 10) / 10).replace('.', ',')` при целом числе не даёт точки, и заменять нечего. Самое крупное реальное число лёгкого издания, `claude` (1 051 595 315 Б ≈ 1002,9 МиБ, `remote-components.json`, platform win32), показывается как «1 ГБ» — без запятой; сумма всех win32-записей реестра (2 291 544 545 Б ≈ 2185,4 МиБ) — как «2,1 ГБ».

## Инварианты

1. **Число компонента приходит только из измеренного источника — рукописной строки не существует.** В офлайне это `c.sizeBytes[платформа]`, записанное `tools/sync-sizes.js` по реальному `vendor/`; в lite — `sizeBytes` архива из `remote-components.json` через `main.js:remoteSizesForRenderer`. Легаси-поле `sizeHint` удаляется из `components.json` самим генератором (`tools/sync-sizes.js:292-295`), а тест «размеры: рукописного sizeHint не осталось …» отдельно проверяет, что renderer его больше не читает.
2. **Компонент без вшитого артефакта не получает числа вовсе.** `tools/sync-sizes.js` fail-closed: не смог измерить — не подставляет (`measureComponent` → `{missing}` → `computeSizes` кладёт в `skipped`, `tools/sync-sizes.js:191-276`). Перечень «числа нет по построению» задан явно в `NO_BUNDLED_PAYLOAD` (`tools/sync-sizes.js:135-146`).
3. **Пустого места без объяснения в окне не бывает.** Либо число, либо `sizeNote` словами; если хоть у одного показанного пункта нет ни того ни другого, `unknown > 0` и в тексте появляется фраза «Там, где цифры нет, мы её заранее не знаем — и не придумываем» (`src/renderer/app.js:920-921,954`). Структурно это же держит тест «размеры: без числа компонент не остаётся немым — есть честная пометка».
4. **Единица измерения названа словами, а не оставлена на догадку.** В теле окна обязательно присутствует и `unit` («Цифра рядом с пунктом — …»), и фраза «После установки программа занимает на диске больше» (`src/renderer/app.js:949-960`).
5. **Заголовок окна и подпись кнопки соответствуют изданию.** `lite` → «Что скачается на мой ПК», офлайн → «Что попадёт на мой ПК» (`src/renderer/app.js:132,965`). Офлайн-установщик не качает ничего, поэтому обещать загрузку он не имеет права.
6. **Размер платформенный.** `sizeBytes` — объект по ключам платформ, «общего» ключа нет; читается `c.sizeBytes[STATE.platform]`. `tools/sync-sizes.js` отказывается мерить чужую ОС (`main`, `tools/sync-sizes.js:339-345`), а при `--force` пишет только `PLATFORM_INDEPENDENT` (сейчас единственный элемент — `course`, `tools/sync-sizes.js:77,367-376`).
7. **Итоговая сумма считается по выбранным компонентам и только из известных чисел.** Компоненты без числа в сумму не попадают, и подгонки итога нет (`downloadTotalBytes`/`bundledTotalBytes`, `src/renderer/app.js:1213-1226`).
8. **Взаимоисключение блоков итога.** `downloadTotalBytes()` возвращает 0 вне `lite`, `bundledTotalBytes()` — 0 в `lite`; ветвление `if/else if` в `showWhatInstalls` не может показать оба блока разом.
9. **Скрытые компоненты в окне не показываются.** `if (!c || c.hidden) return` (`src/renderer/app.js:919`) — служебный `verify` человек не видит и в списке.
10. **Всё, что пришло из конфигов, экранируется перед вставкой в `innerHTML`.** `c.name`, `c.desc`, текст размера, текст `unconfiguredNoteText(c)`, отформатированные суммы — через `escapeHtml` (`src/renderer/app.js:47-51`, использование — 922, 927, 930-931, 942, 945).
11. **Предупреждение «не настроен» дублируется в это окно, а не только на карточку.** `componentUnconfigured` вызывается и в `renderCard`, и в `showWhatInstalls`; это закреплено тестом «предупреждение показано в ОБОИХ местах: карточка и окно «что установится»».
12. **Повторное открытие не плодит окон.** `openModal` при существующем `#what-installs` возвращает `null` без побочных эффектов.

## Что ломается, если инвариант нарушить

1. Возвращается ровно тот дефект, ради которого написан `tools/sync-sizes.js`: строка «~110 МБ» рядом с реально 221,6 МиБ, «~50 МБ» рядом с 1,01 ГиБ. Человек видит сумму вдвое меньше веса скачанного им файла и делает вывод, что установщик что-то скрывает, — окно, снимающее страх «а не вирус ли это», страх усиливает.
2. Компонент, который на самом деле ничего не приносит из установщика (`bridge`, `claude-desktop`), получает правдоподобную цифру. Человек планирует место на диске и трафик по числу, которое никто не мерил.
3. Пункт в списке выглядит как строка без веса, и это читается как «здесь скрыли размер». Тот же эффект, что и у выдуманного числа, только с другой стороны — недоверие вместо ошибки.
4. Голое «~222 МБ» человек по привычке читает как «столько займёт на диске». Реальный след установленного VS Code кратно больше — на диске неожиданно кончается место, и виноват в этом, с его точки зрения, установщик.
5. Офлайн-издание с заголовком «Что скачается на мой ПК» обещает загрузку, которой не будет. Человек без интернета либо не запускает установку вовсе, либо ждёт качания и решает, что программа зависла.
6. Числа одной ОС попадают в другую: на macOS показывается вес windows-артефакта. Живой случай 29.08.2026 (описан в `tools/sync-sizes.js:351-366`): `--platform darwin --force` на Windows молча переписал три числа — claude 135→103 МиБ, nomad 165→110, mascot 202→279. Все правдоподобны, ни одно не верно, код возврата 0.
7. Итог перестаёт сходиться с суммой видимых строк: человек складывает пункты вручную (а в этом окне складывают именно затем, чтобы проверить), не сходится — доверие к остальным цифрам падает целиком.
8. Одновременные «Скачается: ~X» и «Внутри установщика: ~Y» — прямое противоречие в одном абзаце: непонятно, качает эта программа что-то или нет.
9. В списке появляется служебный `verify`, у которого нет ни размера, ни внятного для новичка смысла, — лишняя строка «непонятно что» в окне, задача которого прямо противоположная.
10. Кавычка или угловая скобка в имени/описании компонента ломает вёрстку окна; в худшем случае содержимое конфига исполняется как разметка. Список, который должен доказывать безопасность, сам становится каналом внедрения.
11. Человек прочитал описание компонента в этом окне, не увидел предупреждения «сервис не настроен», выбрал его — и получил установленный, но неработающий компонент, узнав об этом уже после выдачи прав администратора.
12. Несколько нажатий (обычное поведение, когда окно не сразу заметили) кладут друг на друга несколько модалок; закрытие верхней оставляет нижние, экран выглядит зависшим.

## Границы

- Окно **показывает весь список компонентов этой платформы, а не только выбранные**. Выбор влияет только на итоговую сумму сверху. Это осознанное расхождение: список отвечает на вопрос «что вообще бывает внутри», итог — «что будет у меня».
- Цифра **не является местом на диске после установки** и никогда им не станет: измеряется дистрибутив, а не распакованный результат. Об этом сказано словами в самом окне.
- В lite-издании **вес вшитой части не показывается совсем** — `componentSizeBytes` в ветке `lite` не читает `c.sizeBytes`. Компоненты, которых нет в реестре докачки (`course`, `uv` как bundled-only, `bridge`), останутся в lite без числа.
- **Размеры для macOS из Windows попадают в репозиторий только для переносимых артефактов.** Гейт «чужую ОС не меряем» (`tools/sync-sizes.js:339-345`) снимается флагом `--force` и покомпонентного запрета сам по себе не даёт; его даёт фильтр ниже: при `platform !== process.platform` из `res.updates` удаляются только те id, которых нет в `PLATFORM_INDEPENDENT` (`tools/sync-sizes.js:367-376`), а там единственный элемент — `course` (`tools/sync-sizes.js:77`). Значит с Windows в `sizeBytes.darwin` может быть записан именно и только `course` (`applySizes` пишет `c.sizeBytes[res.platform]`, `tools/sync-sizes.js:301-307`) — и там оно так и появилось: в `components.json:168-171` win32 и darwin у курса совпадают байт-в-байт (340969). Остальные darwin-числа снимаются на маке после `tools/fetch-vendor-mac.sh`.
- **Сверка чисел с vendor на чистой машине не выполняется** — vendor не коммитится. Тесты «размеры: файловые/каталожные компоненты … сходятся с vendor» в этом случае явно пропускаются (`SKIP`), а не зеленеют. Каталожные компоненты вдобавок идут под побюджетным ограничением времени (по умолчанию 8000 мс на компонент, полная сверка — `HM_SIZES_DEEP=1`).
- **Округление огрубляет мелкие пункты.** `fmtBytesRu` имеет нижнюю отсечку `Math.max(1, Math.round(mb))`, поэтому курс (`course`, 340 969 Б ≈ 0,33 МБ в `components.json`) показывается как «~1 МБ». Формально это завышение, но в сторону «не меньше, чем на самом деле».
- Подпись кнопки на **приветственном** экране (`#btn-wc-what`, «Что именно установится?») по изданию не меняется — она нейтральна и одинаково верна для обоих; переписывается только подпись `#btn-what-installs`.
- Окно **ничего не проверяет в момент открытия**: ни наличия файлов в vendor, ни доступности сервера докачки. Оно показывает то, что заявлено конфигами и посчитано на сборке.

## Риски и открытые вопросы

- **Заголовок модалки вставляется в `innerHTML` без экранирования** (`src/renderer/app.js:887`, комментарий на 876-877 объявляет `title` доверенным литералом). Для этой фичи риска нет — оба заголовка литералы, — но инвариант держится только соглашением в комментарии, машинной проверки на него не нашёл.
- **Согласованность «в окне ничего не выдумано» проверяется структурно, а не по отрендеренному DOM.** Тест «окно «что попадёт на мой ПК» …» ищет подстроки в исходнике `app.js` (`внутри установщика`, `занимает на диске больше`, оба заголовка). Переформулировка любой из этих фраз уронит тест, а перестановка их в недостижимую ветку — нет. Прогонов самого окна в `test/run-tests.js` по этой фиче я не нашёл; в `test/e2e-gui.js` селектор `#btn-what-installs` / `#what-installs` тоже не встречается.
- **Ветка lite числами не покрыта.** Все тесты блока размеров сверяют офлайн-путь (`components.json` ↔ `vendor/`). Что `bootstrap.remoteSizes` действительно совпал с `sizeBytes` записей `remote-components.json` для текущей платформы, отдельным тестом не подтверждено — не обнаружил.
- **`remoteSizesForRenderer` глушит любую ошибку** (`catch (e) { /* превью размеров не должно ломать bootstrap */ }`, `src/main.js:666`). Решение осознанное (bootstrap важнее превью), но последствие для окна тихое: при сломанном или неполном `remote-components.json` lite-издание покажет список вообще без чисел и без итога, а причина не будет видна нигде в UI.
- **`unknown` считает пункты, а фраза говорит о «цифре».** Компонент с `sizeNote`, но без байтов (`bridge`, `claude-desktop`, `chatgpt-desktop` в офлайне) в `unknown` не попадает, потому что `componentSizeText` вернул непустую строку. То есть приписка «где цифры нет — не придумываем» может не появиться в окне, где у трёх пунктов числа действительно нет, но есть пояснение словами. Расхождением кода и обещания это не назову — пункт не «нем», — но формулировка приписки шире реального условия её показа.
- **`sizeNote` для `handy` содержит числа, написанные руками** («+ модель распознавания ~257-705 МБ скачивается самой программой при первом запуске»), и генератор их не сверяет. Механика ровно обратна тому, на что похоже: `res.notes` наполняется исключительно из `NO_BUNDLED_PAYLOAD` (`tools/sync-sizes.js:258-261`), а `applySizes` трогает `sizeNote` только при `res.notes.has(c.id) && !c.sizeNote` (`tools/sync-sizes.js:296-300`). `handy` в `NO_BUNDLED_PAYLOAD` не входит — там только `verify`, `bridge`, `claude-desktop`, `chatgpt-desktop` (`tools/sync-sizes.js:135-146`), — потому что у него есть вшитый артефакт `apps/handy-setup.exe` (`tools/sync-sizes.js:111`) и измеренный `sizeBytes` (`{win32: 20946752, darwin: 21423161}`). Значит его пометку скрипт не пишет и не перечитывает вовсе. Место это не единственное: в то же окно под именем компонента вставляется его `desc` (`'<div class="wi-desc">' + escapeHtml(c.desc || '') + '</div>'`, `src/renderer/app.js:931`), а рукописные числа стоят и там — `components.json:183` у `nomad` («докачивает Python и библиотеки из интернета (~300 МБ)»), `components.json:272` и `:288` у `claude-desktop` и `chatgpt-desktop` («Скачивается онлайн … (~сотни МБ)»), `components.json:304` у `handy` («Parakeet TDT 0.6B v3, ~705 МБ»). `desc` генератор не трогает вовсе: `applySizes` работает ровно с тремя полями — `sizeHint`, `sizeNote`, `sizeBytes` (`tools/sync-sizes.js:287-310`). Единственная машинная проверка на «705 МБ»/«257 МБ» (`test/run-tests.js:8245`) идёт по тексту `scripts/windows/handy.ps1` (`const s = ps()`, `test/run-tests.js:8210,8237`), а не по `components.json`. Механика устаревания у этих чисел ровно та же, что у `sizeNote` у `handy`.
