## Что обещает человеку

На маке установщик может открыться в состоянии, когда кнопка «Установить» серая: macOS повесила на скачанный образ карантин и запускает приложение из защищённой копии (App Translocation), из-за чего лежащие рядом офлайн-компоненты недостижимы. Раньше единственным выходом была команда в Терминале — и живой случай показал, что там ошибаются: человек сохранил образ не в «Загрузки», команда с жёстко вбитым `~/Downloads` падала, и он упирался в тупик.

Фича обещает одно: на блокирующем экране есть кнопка «Исправить автоматически», после нажатия на которую от человека не требуется ни одной команды. Установщик сам находит файл образа (в том числе если тот лежит на Рабочем столе или в подпапке, и в том числе повторно скачанный «Hamidun-Setup-Mac (1).dmg»), снимает карантин, проверяет, что карантина действительно больше нет, закрывает своё окно и через несколько секунд открывается заново — уже из свежесмонтированного образа, где кнопка «Установить» активна. Если что-то из этого не вышло, человек видит причину текстом, а не пустой экран: команда для Терминала остаётся на экране как запасной путь.

## Как работает

**Условие появления кнопки.** Главный процесс при старте отдаёт renderer'у `vendorBlock` (`vendorBlockInfo`, `src/main.js:143-152`): блокировка возможна только при `process.platform === 'darwin' && app.isPackaged` и наступает либо при транслокации (`isTranslocated`, `src/main.js:58-64`, путь содержит `/AppTranslocation/`), либо при неполном vendor у офлайн-издания. В renderer `renderVendorBlock` (`app.js:703`) при `!vb.blocked` уходит в мягкий `renderVendorWarning` и никакого самолечения не рисует. При `blocked` он поднимает блокирующую модалку с кнопкой `mac-selfheal` и, отдельно, несмываемый баннер с кнопкой `mac-selfheal-banner` — баннер нужен потому, что модалку можно закрыть кнопкой «Понятно», после чего погашенная «Установить» осталась бы без объяснения. Обе кнопки привязываются через `bindMacSelfHeal` (`app.js:748-749`), затем вызывается `showPrevSelfHealFailure` (`app.js:750`).

**Клик по кнопке** (`bindMacSelfHeal`, `app.js:808-850`). Если модульный флаг `SELF_HEAL_BUSY` уже поднят — обработчик выходит молча. Иначе флаг поднимается, `setSelfHealButtonsBusy(true)` гасит ОБЕ кнопки и меняет их подпись на «Чиню…» (исходная сохраняется в `dataset.idleLabel`), в статус-строку пишется «Ищу образ и снимаю карантин…», после чего идёт `await window.installer.macSelfHeal()` (мост — `src/preload.js:45`, `ipcRenderer.invoke('mac-selfheal')`).

**Поиск образа** (`macFindOurDmg`, `src/main.js:3390-3435`). Кандидат принимается предикатом `okDmg` только если путь абсолютный, базовое имя совпадает с `/^Hamidun-Setup-Mac[A-Za-z0-9._ ()-]*\.dmg$/i`, и `fs.statSync(p).isFile()`. Источников два:
1. `execFileSync('/usr/bin/hdiutil', ['info'])` (timeout 15 000 мс) — из вывода берётся первая строка `image-path : …`, прошедшая `okDmg`. Это самый точный путь: смонтированный образ знает свой файл. Исключение проглатывается — образ мог быть уже отцеплен.
2. Обход файловой системы: `walk` по `~/Downloads`, `~/Desktop`, `~/Documents` с параметром глубины 2 (то есть сама папка и до двух уровней подпапок), пропуская скрытые каталоги и `Library|Applications|.Trash|node_modules|.git|Pictures|Music|Movies`, с потолком в 40 находок. Если не нашлось ничего — `walk(home, 1)`, то есть корень профиля и один уровень его подпапок.

Найденные сортируются по `mtimeMs` по убыванию, возвращается самый свежий; при пустом списке — `''`.

**Обработчик `mac-selfheal`** (`src/main.js:3437-3530`), ветвления по порядку:
- не darwin → `{ ok: false, error: 'not-darwin' }`;
- образ не найден → `{ ok: false, error: 'dmg-not-found' }`;
- `execFileSync('/usr/bin/xattr', ['-dr', 'com.apple.quarantine', dmg])` (timeout 20 000 мс), исключение проглатывается — атрибута могло и не быть;
- проверка факта: `execFileSync('/usr/bin/xattr', ['-p', 'com.apple.quarantine', dmg])` (timeout 10 000 мс). Код 0 означает, что атрибут ЕСТЬ, то есть снять не удалось → `{ ok: false, error: 'quarantine-not-cleared', dmg }`;
- запись хлебной крошки `~/Library/Application Support/HamidunSetup/selfheal.status` — JSON `{ result: 'started', at, dmg }`; ошибки записи проглатываются;
- `spawn('/bin/sh', ['-c', helper, 'hm-selfheal', dmg, String(process.pid), statusFile], { detached: true, stdio: 'ignore' })` + `child.unref()`; исключение → `{ ok: false, error: 'helper-failed', dmg }`;
- `setTimeout(() => app.quit(), 6000)` — выход инициирует ИМЕННО главный процесс;
- возврат `{ ok: true, dmg, handoff: true }`, что означает «карантин снят и починка запущена», а не «всё готово».

**Отцеплённый помощник** (текст `const helper`, `src/main.js:3468-3497`) исполняет хвост уже после нашего выхода, шагами:
1. ждёт смерти установщика — `kill -0 "$PID"` в цикле, до 240 итераций по 0,5 с (потолок 120 с);
2. `hdiutil detach "$v" -force` для каждого `/Volumes/Hamidun*`;
3. `hdiutil attach -nobrowse "$DMG"`, точка монтирования берётся ИЗ ВЫВОДА через `sed`/`tail -1`;
4. если `$MP` пуст или нет `"$MP/Hamidun Setup.app"` → в крошку `mount-failed`, `exit 1`;
5. `open -n -a "$MP/Hamidun Setup.app"`; при ненулевом коде → `relaunch-failed`, `exit 1`;
6. до 20 итераций по секунде ждёт, пока `pgrep -f "Hamidun Setup.app/Contents/MacOS"` увидит процесс: увидел → `ok`, `exit 0`; не увидел → `relaunch-not-seen`, `exit 1`.

**Возврат в renderer.** При `res.ok` защёлка `SELF_HEAL_BUSY` НЕ отпускается, и обработчик выходит, показав текст «Карантин снят. Сейчас закрою это окно…»; выход из приложения окно не инициирует. При отказе защёлка снимается, кнопки разблокируются, и по коду ошибки подбирается текст (`app.js:841-848`): `dmg-not-found` → «скачай установщик заново»; `volume-not-ready`/`open-failed` → «выполни команду ниже в Терминале»; всё остальное — общий текст с кодом в скобках.

**Крошка прошлой попытки.** `mac-selfheal-status` (`src/main.js:3535-3555`) читает файл, вычисляет возраст по `mtimeMs`, УДАЛЯЕТ файл, и если возраст больше 30 минут — возвращает пустой статус. Иначе берёт `raw.slice(0, 40)`, а при JSON-объекте — поле `result`. Renderer читает крошку безусловно при старте (`loadPrevSelfHealFailure`, вызов на `app.js:64`, до `bootstrap`), игнорирует `''`, `ok` и `started`, и раскладывает остальное в три текста: `mount-failed` → «не смогла открыть образ», `relaunch-not-seen` → «открыла образ, но установщик из него не запустился», иначе → «не смогла перезапустить установщик». Текст живёт в модульной переменной `PREV_SELFHEAL_TEXT`, поэтому переживает переоткрытие модалки кнопкой «Показать инструкцию».

**Запасной путь.** Под кнопкой в модалке и в баннере лежит однострочная команда для Терминала (`app.js:720`, `app.js:741`), которая ищет образ сама (`find ~ -maxdepth 4 -iname "Hamidun-Setup-Mac*.dmg"`), отцепляет все `/Volumes/Hamidun*`, снимает карантин и открывает образ. Тот же текст лежит в `assets/mac/ПРОЧТИ ЕСЛИ ПИШЕТ ПОВРЕЖДЕНО.txt` внутри образа, и тест сверяет обе копии на побайтовое совпадение.

## Инварианты

1. **Самолечение недоступно вне macOS.** `ipcMain.handle('mac-selfheal')` первым делом возвращает `not-darwin` (`src/main.js:3438`), `mac-selfheal-status` — пустой статус (`src/main.js:3536`). Кнопка не рисуется вовсе, пока `vendorBlock.blocked` ложно (`app.js:705`), а блокировка возможна только при `darwin && app.isPackaged` (`src/main.js:144`).
2. **Чинится только наш образ.** Любой путь проходит `okDmg`: абсолютный, обычный файл, имя по шаблону `^Hamidun-Setup-Mac[A-Za-z0-9._ ()-]*\.dmg$` (`src/main.js:3391-3397`, тот же шаблон повторно в обходе на `3422`).
3. **Ни один внешний вызов не собирается склейкой строк.** `hdiutil info`, `xattr -dr`, `xattr -p` идут через `execFileSync` с массивом аргументов (`src/main.js:3400`, `3446`, `3452`), путь к образу уходит помощнику позиционным аргументом `$1`, а не подстановкой в текст скрипта (`src/main.js:3513`).
4. **`ok` не отдаётся без подтверждения, что карантина больше нет.** После снятия идёт `xattr -p`, и код 0 (атрибут на месте) даёт отказ `quarantine-not-cleared` (`src/main.js:3449-3456`).
5. **Главный процесс не отцепляет том, с которого сам запущен.** Внутри обработчика нет ни одного `hdiutil detach`; отцепление живёт только в тексте помощника (`src/main.js:3474`), который запущен `detached: true` + `unref()` (`src/main.js:3513-3515`). Тест проверяет отсутствие `execFileSync(... hdiutil ... detach)` в коде обработчика.
6. **Помощник не трогает тома, пока установщик жив.** Цикл `kill -0 "$PID"` стоит СТРОГО до первого `hdiutil detach` (`src/main.js:3473-3474`); порядок закреплён `assertOrder` и поведенческим прогоном настоящим `sh`.
7. **Приложение запускается с тома ЭТОГО монтирования и новым экземпляром.** Точка монтирования берётся из вывода `hdiutil attach`, а не перебором `/Volumes/Hamidun*` (`src/main.js:3482`), запуск — `open -n -a "$MP/Hamidun Setup.app"` (`src/main.js:3486`).
8. **`ok` в крошку пишется только после того, как процесс реально увиден.** Код возврата `open` за успех не принимается: решает цикл `pgrep -f "Hamidun Setup.app/Contents/MacOS"` (`src/main.js:3490-3496`).
9. **Выход инициирует главный процесс, а не окно.** `setTimeout(app.quit, 6000)` стоит в обработчике (`src/main.js:3525`); успешная ветка renderer'а только пишет текст и возвращается (`app.js:829-837`).
10. **Одновременно идёт не больше одной починки, и после успеха вторая невозможна.** Общий на модуль флаг `SELF_HEAL_BUSY` (`app.js:793`) проверяется до вызова (`app.js:813`), снимается только в ветке отказа (`app.js:839`); `disabled` на кнопках — видимая часть, не защита.
11. **Отметка прошлой попытки живёт один раз и не старше получаса.** `mac-selfheal-status` удаляет файл при чтении и отбрасывает запись старше 30 минут (`src/main.js:3546-3548`).

## Что ломается, если инвариант нарушить

1. На Windows кнопка либо не появится вовсе, либо вызовет `xattr`/`hdiutil`, которых там нет: человек получит исключение вместо установки. В dev-сборке блокировка сработала бы там, где транслокация физически невозможна, — установщик стал бы кирпичом на ровном месте.
2. Без проверки имени и типа кнопка «Исправить автоматически» снимет карантин с произвольного файла, на который укажет вывод `hdiutil` или обход диска, — то есть станет инструментом снятия защиты Gatekeeper с чужого содержимого.
3. Склейка пути в shell-строку превращает имя файла в исполняемый код: образ, названный так, чтобы содержать подстановку, выполнится от имени пользователя. Практический случай безобиднее и всё равно ломает всё — имена вида «Hamidun-Setup-Mac (1).dmg» с пробелом и скобками просто не найдутся.
4. Человек увидит «Готово», окно закроется, и через несколько секунд откроется ровно тот же заблокированный установщик — с той же серой кнопкой и без единого объяснения. Именно так этот сценарий уже выглядел до появления проверки.
5. `hdiutil detach -force` выдёргивает backing store у собственного исполняемого файла: установщик умирает посреди починки, окно исчезает без свежего образа и без сообщения. Для человека это «нажал кнопку — программа пропала».
6. Пока установщик жив, он держит замок единственного экземпляра. Свежий экземпляр, запущенный помощником, закроется сам, и человек останется без окна вообще: старое закрылось, новое не открылось.
7. Том, который держит Finder, не отцепляется, и macOS монтирует «Hamidun Setup 1» рядом. Перебор `/Volumes/Hamidun*` берёт первый по алфавиту — СТАРЫЙ, всё ещё карантинный том, и человек снова получает экран блокировки при надписи «Готово». Без `open -n` macOS просто активирует уже запущенный экземпляр того же bundle id.
8. Самый вероятный тихий провал (свежий экземпляр закрылся сам) запишется в крошку как `ok`, и на следующем запуске человек не увидит причины — только исчезнувшее окно и повторную блокировку.
9. Модалка прямо просит закрыть окно. Если выход зависит от таймера в окне, закрывший его человек отменяет выход: процесс жив, замок держится, свежий установщик закрывается сам, и восстановиться уже нечем.
10. Второй клик (кнопки две — в модалке и в баннере) запускает вторую починку, которая `-force` отцепляет том, с которого в этот момент уже стартует новый установщик. Результат — установщик, убитый собственной кнопкой «Исправить».
11. Отказ полугодовой давности всплывёт при первом же следующем заблокированном запуске и отправит человека перекачивать заведомо исправный файл; без удаления файла тот же текст будет показываться бесконечно.

## Границы

- Фича чинит только ДОСТУП к установщику. Она не устанавливает ни одного компонента: после перезапуска человек проходит установку заново, обычным путём.
- Карантин снимается только с файла `.dmg`. С `.app`, перетащенного в «Программы», ничего не снимается — модалка прямо просит удалить его оттуда (`app.js:715`).
- Админ-прав не требуется и не запрашивается: образ — файл самого пользователя.
- Образ не докачивается. Если файла на диске нет, единственный ответ — `dmg-not-found` и просьба скачать установщик заново.
- `ok: true` (`handoff: true`) означает «карантин снят и починка запущена», а не «всё получилось»: attach, open и проверка запуска происходят уже после выхода приложения, и их исход виден только через крошку на следующем запуске.
- Поиск образа ограничен намеренно: имя по шаблону, `~/Downloads`, `~/Desktop`, `~/Documents` до двух уровней подпапок, при неудаче — корень профиля и один уровень его подпапок, потолок 40 находок, пропуск `Library`, `Applications`, `.Trash`, `node_modules`, `.git`, `Pictures`, `Music`, `Movies` и скрытых каталогов. Образ на внешнем диске, в `~/Library` или глубоко в произвольном каталоге кнопкой не найдётся.
- Помощник работает после выхода приложения и в `install.log` не пишет: его стандартные потоки — `stdio: 'ignore'`, единственный след — файл `selfheal.status` объёмом в одно слово.
- Текст ручной команды под кнопкой не является частью автоматики: это запасной путь, который остаётся на экране и при успехе.

## Риски и открытые вопросы

1. **Мёртвая ветка обработки ошибок в renderer.** `app.js:844` разбирает коды `volume-not-ready` и `open-failed`, но `src/main.js` не возвращает ни одного из них — реальный набор кодов сейчас `not-darwin`, `dmg-not-found`, `quarantine-not-cleared`, `helper-failed` (grep по `src/` подтверждает: эти две строки встречаются только в renderer). Последствие: самый содержательный отказ, `quarantine-not-cleared`, показывается человеку общим текстом «Автоматически не вышло (quarantine-not-cleared)» — с техническим кодом вместо объяснения, хотя специально написанный текст для этого случая рядом есть и не срабатывает.
2. **Крошка статуса и её показ не покрыты тестом.** Имя `mac-selfheal-status` в `test/run-tests.js` встречается трижды, и ни разу как проверка поведения: на `5578` строка `ipcMain.handle('mac-selfheal-status'` служит границей среза кода соседнего обработчика, на `6296` и `6310` это идентификатор элемента в песочнице теста про защёлку. Ни `mount-failed`, ни `relaunch-not-seen`, ни `loadPrevSelfHealFailure`/`showPrevSelfHealFailure`, ни 30-минутное окно свежести (`30 * 60 * 1000`) в тестах не встречаются вовсе — сплошной поиск по `test/run-tests.js` не даёт ни одного вхождения. Регресс в разборе крошки, в отсечке по возрасту или в удалении файла тесты не поймают, а проявится он у человека как исчезнувшее без объяснений окно или как совет перекачивать исправный файл.
3. **Гонка «прочитал и удалил» против записи помощника.** Renderer читает и удаляет `selfheal.status` безусловно в начале `init` (`app.js:64`), а помощник записывает финальный результат позже — уже после `open` и цикла `pgrep` (`src/main.js:3490-3496`). Свежий установщик, стартовавший быстро, успевает съесть отметку `started` и удалить файл до того, как помощник допишет исход. Тот же механизм даёт второй эффект: `showPrevSelfHealFailure` вызывается только внутри `renderVendorBlock` (`app.js:750`), поэтому отметка, прочитанная на НЕзаблокированном запуске, теряется молча и до человека не доедет.
4. **Автоматический поиск местами уже ручной команды.** Кнопка обходит `~/Downloads`, `~/Desktop`, `~/Documents` на два уровня подпапок и корень профиля на один (`src/main.js:3427-3428`), тогда как команда для Терминала ищет `find ~ -maxdepth 4` (`app.js:720`). Образ, лежащий, например, в `~/Projects/setup/mac/`, ручная команда найдёт, а кнопка — нет, и человек получит `dmg-not-found` с советом «скачай заново» при живом файле на диске.
5. **Ошибки записи крошки проглатываются** (`src/main.js:3503-3509`). Комментарий честно говорит «без крошки починка всё равно поедет», но следствие в том, что при недоступном `~/Library/Application Support/HamidunSetup` любой отказ помощника становится невидимым полностью: окно исчезает, новое не открывается, объяснения нет нигде.

Помощник умеет писать код `relaunch-failed` (`src/main.js:3486`), для которого в `loadPrevSelfHealFailure` отдельной ветки нет — он попадает в общий текст «не смогла перезапустить установщик» (`app.js:773`). По смыслу текст верен, расхождением это не является; отмечено, чтобы при добавлении новых кодов ветку не забыли.
