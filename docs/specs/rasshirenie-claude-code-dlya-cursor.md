## Что обещает человеку

Если на компьютере стоит Cursor, после установки внутри него появляется панель Claude Code — кнопка в редакторе вместо работы в терминале. Заодно ставится моноширинный шрифт JetBrains Mono (только для текущего пользователя, без прав администратора) и, если у Cursor ещё нет своего `settings.json`, создаётся стартовый: автосохранение и этот же шрифт в редакторе и терминале.

Обещание ограничено ровно этим. Отсутствие Cursor не считается ошибкой — шаг заканчивается `exit 0` (`extension.ps1:224-227`): панель Claude в VS Code ставит другой компонент. Но «ничего не делает» было бы неверно: ветка про ненайденный CLI (`extension.ps1:163`) только печатает сообщение, `exit` в ней нет, и управление идёт дальше. Ни блок шрифта (строки 168-189), ни блок `settings.json` (строки 191-211) с `$cursorCli` никак не связаны — их условия смотрят только на `HM_VENDOR\apps\JetBrainsMono-Regular.ttf` и на отсутствие файла настроек. Поэтому на машине без Cursor шаг всё равно ставит JetBrains Mono в профиль пользователя (`%LOCALAPPDATA%\Microsoft\Windows\Fonts` + запись в `HKCU`) и создаёт с нуля каталог `%APPDATA%\Cursor\User\` с `settings.json` — профиль редактора, которого на машине нет. Если Cursor стоит, но расширение не встало, человек получает не молчание, а конкретную инструкцию: открыть в Cursor панель расширений и найти `anthropic.claude-code` (`extension.ps1:229-234`, `exit 1`). Существующие настройки Cursor при этом не переписываются никогда.

## Как работает

**Что запускает шаг.** Компонент `extension` (`components.json:81-96`, `requires: ["vscode"]`) на Windows отображается в скрипт `scripts/windows/extension.ps1`, на macOS — в `scripts/macos/extension.sh` (`src/main.js:571-575`, `scriptFor`). Идентификатор расширения приходит из `config.json:36` (`claudeCodeExtensionId`) в переменной окружения `HM_CLAUDE_EXT_ID` (`src/renderer/app.js:1283`); скрипт читает её с запасным значением `anthropic.claude-code` (`extension.ps1:30`). Установщик собран с `requestedExecutionLevel: requireAdministrator` (`package.json:115`, единственное вхождение в файле), поэтому скрипт исполняется elevated — отсюда всё остальное устройство.

**Windows, `scripts/windows/extension.ps1`, по шагам:**

1. `Update-Path` (строки 8-28) собирает `$env:Path` заново: машинный PATH (`[Environment]::GetEnvironmentVariable('Path','Machine')`), `System32`, `%SystemRoot%`, `WindowsPowerShell\v1.0`, `OpenSSH`, `Program Files\Git\cmd`, `Git\bin`, `nodejs`, `Program Files (x86)\Git\cmd`. Пользовательский (HKCU) PATH не читается вовсе — комментарий называет причину: medium-процесс того же пользователя может дописать туда каталог с подложенным бинарём, а исполнился бы он под elevated-токеном.
2. Ветвление «есть вшитый vsix / нет». Если задан `HM_VENDOR` и существует `HM_VENDOR\apps\claude-code.vsix` — это офлайн-путь (строки 36-38). Вне `HM_DRY_RUN` файл проходит `Confirm-HmArtifact` (`_verify.ps1:64-104`): сверка SHA-256 и, если в манифесте есть поле `bytes`, размера с `vendor/checksums.json`; любое расхождение, отсутствие манифеста или незаданный `HM_VENDOR` — `exit 1`.
3. Читаемая копия (строки 58-73). Проверенный vsix копируется в пользовательский `%TEMP%` под именем `hm-claude-code-<guid>.vsix`, затем копия открывается `[System.IO.File]::OpenRead(...)` (строка 66). Доказательством читаемости для пользователя этот вызов НЕ является: он исполняется в самом скрипте, то есть elevated (комментарий строк 108-113), тогда как установка уходит в medium через `Invoke-HmDeElevated` (строки 137, 146) — открывает файл не тот субъект, ради которого копия и делается. Admins-only DACL элевированным токеном читается штатно, поэтому именно тот случай, который весь приём лечит, проверка не отличит. Читаемость для пользователя обеспечивает выбор места (`%TEMP%` с унаследованным DACL пользователя), а не `OpenRead`; комментарий строк 64-65 («к которому у пользователя нет доступа») содержит ту же неточность. Причина копии в комментарии (строки 40-47): в лёгком издании пак докачки распакован в admins-only каталог (`%ProgramData%\HmDeElev-*`, DACL только SYSTEM+Administrators), а расширение ставит редакторный CLI при medium integrity — прочитать оригинал он не может. Если копия не сделалась или не читается, `$vsix` обнуляется и остаётся путь Marketplace (строки 68-72).
4. Всё, что дальше, обёрнуто в один top-level `try` (строка 79) с `finally { Remove-HmVsixTemp }` (строки 235-238). `Remove-HmVsixTemp` объявлена ДО создания копии (строки 51-56) — в PowerShell иначе ранний выход упал бы «команда не найдена».
5. Открытый Cursor (строки 85-104, вне dry-run). Если процесс `Cursor` жив: при выставленном `HM_CURSOR_AUTOSTARTED` (не `'0'`) он считается нашим автозапуском и гасится `Stop-Process -Force`; иначе печатается предупреждение, скрипт ждёт до 20 секунд в цикле по одной секунде (строка 97) и НЕ убивает. Флаг `$userCursorSpared` ставится не во всей этой ветке, а отдельной проверкой ПОСЛЕ ожидания (строки 98-101): только если Cursor пережил все 20 секунд. Закрыл человек редактор вовремя — флаг остаётся `$false` (инициализация на строке 85), и крайняя мера, где `$userCursorSpared` обязателен (строка 215), не сработает вовсе.
6. Поиск CLI (строки 153-162): перебор четырёх путей в `%LOCALAPPDATA%\Programs\cursor` (`resources\app\bin\cursor.cmd`, `bin\cursor.cmd`, `cursor.cmd`, `Cursor.exe`), затем запасной `Get-Command cursor`.
7. `Install-Into` (строки 126-151). В dry-run печатает `WOULD (de-elevated): ...` и возвращает `$true`. Иначе: если `Test-HmExtInstalled` уже видит расширение в `~\.cursor\extensions` — «уже на месте». Иначе установка идёт через `Invoke-HmDeElevated $cli @('--install-extension', $target, '--force')` (`_deelev.ps1:524`) — одноразовая задача планировщика от имени текущего пользователя с `LeastPrivilege`, тело обёртки в `-EncodedCommand`, self-check integrity внутри обёртки. Возврат `$null` — fail-closed: ставится `$script:DeElevFailed`, бинарь под админом не запускается. Успех подтверждается только `Test-ExtPresent` (строки 117-124): до шести попыток с паузой в секунду, каждая — `Test-HmExtInstalled` по каталогу `~\.cursor\extensions` с матчем `^<extId>-<цифра>` (`_deelev.ps1:59-72`). Если ставили из vsix и он не подтвердился — второй заход тем же способом, но целью `$extId` (Marketplace).
8. Шрифт (строки 168-189). При наличии `HM_VENDOR\apps\JetBrainsMono-Regular.ttf` — мягкая проверка `Test-HmArtifact` (`_verify.ps1:108-118`, возвращает `$false` вместо `exit`): не совпал SHA-256 — шрифт просто не ставится, шаг живёт дальше. Совпал — копия в `%LOCALAPPDATA%\Microsoft\Windows\Fonts` и запись в `HKCU:\Software\Microsoft\Windows NT\CurrentVersion\Fonts`.
9. `settings.json` Cursor (строки 191-211): путь `%APPDATA%\Cursor\User\settings.json`. Файл есть — печатается «не трогаю» и ничего не пишется. Файла нет — создаётся с тремя ключами: `files.autoSave: afterDelay`, `editor.fontFamily` и `terminal.integrated.fontFamily` = `JetBrains Mono`.
10. Крайняя мера (строки 213-220): только если расширение так и не встало, не dry-run, был `$userCursorSpared` и Cursor всё ещё жив — печатается честное предупреждение про несохранённую работу, `Stop-Process -Force`, пауза 600 мс, повтор `Install-Into`.
11. Коды выхода (строки 222-234): `exit 0` при успехе; `exit 0`, если Cursor не найден вообще; иначе `exit 1` с одной из двух подсказок — про несработавшую де-элевацию (`$script:DeElevFailed`) или общей, где упомянуто, что Claude Code остаётся доступен командой `claude` в терминале.

**Установки в VS Code здесь нет.** Строки 165-166 фиксируют это прямым комментарием: оба VS Code-расширения ставит `vscode.ps1`, чтобы не было второго elevated-пути к user-writable `code.cmd`.

**macOS, `scripts/macos/extension.sh` — путь другой:** vsix арх-специфичный (`apps/claude-code-<arch>.vsix`, строки 11-13), проверка `verify_artifact`; отсутствие копии под архитектуру честно объявляется и уводит в Marketplace (строки 14-18). CLI ищется и в `/Applications`, и в `~/Applications` (`hm_cli`, строки 56-62). Установка идёт **и в Cursor, и в VS Code** (строки 64-74), успех считается по `--list-extensions` (`ext_present`, строки 24-35) — запускать редакторный CLI здесь допустимо, потому что весь путь неэлевированный. Шрифт кладётся в `~/Library/Fonts`, `settings.json` — в `~/Library/Application Support/Cursor/User/`. Выход `0`, если встало хотя бы в один редактор.

**Проверка на финише** — не в этом скрипте: `scripts/windows/verify.ps1:214-241` смотрит те же каталоги (`.vscode`, `.vscode-oss`, `.cursor`) по тому же регулярному выражению и печатает `CHECK ok/fail Расширение`, а `src/main.js:2513-2523` при старте установщика помечает компонент установленным, если расширение найдено в любом из трёх каталогов (`extDirs` — строки 2604-2608, `const found = extDirs.some(...)` — 2609, присваивание `out.extension` — 2610).

## Инварианты

1. **Вшитый vsix не устанавливается без совпадения SHA-256 с `vendor/checksums.json`.** Держится в `extension.ps1:38` (`Confirm-HmArtifact $vsix`) и `_verify.ps1:64-104` — при расхождении хэша, размера, отсутствии записи или манифеста — `exit 1`.
2. **Ни один редакторный бинарь не исполняется под администратором.** Единственный вызов установки — `Invoke-HmDeElevated` (`extension.ps1:137`, `146`); прямого `& $cli --install-extension` в файле нет (стережёт тест «ИНВАРИАНТ: 0 прямых elevated editor-бинарь execution …»).
3. **Недоступная де-элевация = отказ, а не откат к elevated-запуску.** `$null -eq $r` → `$script:DeElevFailed = $true` и `return $false` (`extension.ps1:138-142`, `147`).
4. **Факт установки подтверждается только файловой системой.** `Test-ExtPresent` → `Test-HmExtInstalled` по `~\.cursor\extensions`, имя каталога обязано матчить `^<extId>-<цифра>` (`extension.ps1:117-124`, `_deelev.ps1:59-72`). Ни exit-код CLI, ни его stdout доверием не являются; `--list-extensions` в файле не вызывается.
5. **Этот скрипт не ставит ничего в VS Code.** Ни переменной `$codeCli`, ни путей `.vscode*` в файле нет (`extension.ps1:165-166`).
6. **Копия vsix в `%TEMP%` убирается на любом выходе.** Один top-level `try` (строка 79) и `finally` с `Remove-HmVsixTemp` (строки 235-238); все `exit` лежат внутри него — это же и проверяет тест «extension.ps1: уборка vsix-темпа достижима перед КАЖДЫМ exit …».
7. **Cursor, открытый пользователем, не убивается до попытки установки.** Принудительное закрытие возможно ровно в двух местах: при `HM_CURSOR_AUTOSTARTED` (строки 89-93) и как крайняя мера ПОСЛЕ неудачи (строки 215-220).
8. **Существующий `settings.json` Cursor не изменяется.** Ветка `Test-Path $cursorSettings` печатает «не трогаю» и выходит из блока (`extension.ps1:192-195`); запись только в `else`.
9. **Шрифт с несовпавшим хэшем не ставится и не роняет шаг.** Мягкая `Test-HmArtifact` вместо fail-closed `Confirm-HmArtifact` (`extension.ps1:173-176`).
10. **Отсутствие Cursor — не провал.** `if (-not $cursorCli) { ... exit 0 }` (`extension.ps1:224-227`).
11. **PATH elevated-скрипта не содержит пользовательских каталогов.** `Update-Path` берёт только `Machine`-ветку и фиксированные админ-каталоги (`extension.ps1:8-27`).
12. **В `HM_DRY_RUN` сам `extension.ps1` ничего не пишет — но одно удаление в dry-run всё же происходит, и не в нём.** Проверка целостности, копия vsix, работа с процессом Cursor и запись файлов — все под `-not $DRY` (`extension.ps1:38`, `59`, `86`, `129-133`, `196`), это подтверждается. Однако дот-сорс `_deelev.ps1` (`extension.ps1:7`) выполняется безусловно и ДО того, как `$DRY` вообще определена (`extension.ps1:31`), а единственный top-level исполняемый блок этой библиотеки (`_deelev.ps1:695-701`) вызывает `Remove-HmOrphanTasks`, внутри которой стоит реальное удаление задачи планировщика — `$root.DeleteTask($name, 0)` (`_deelev.ps1:515`). Слова `HM_DRY_RUN` в `_deelev.ps1` нет ни разу: dry-run-гейта там не существует. Для контраста `_verify.ps1` побочных эффектов не имеет — в нём только объявления функций (`9`, `24`, `46`, `64`, `108`).

## Что ломается, если инвариант нарушить

1. Подменённый vsix — это код, который Cursor исполнит внутри себя: расширение с чужой начинкой получает доступ к файлам пользователя и терминалу редактора. Установщик выдал бы это за штатную панель Claude.
2. Elevated-запуск `cursor.cmd` из `%LOCALAPPDATA%` означает: любая программа, уже работающая под этим пользователем, может заранее подменить этот файл и получить права администратора — то есть установщик сам поднимает малварь до админа.
3. Откат «не вышло безопасно — запущу под админом» — это то же самое повышение прав, только замаскированное под заботу об удобстве.
4. Доверие exit-коду CLI даёт зелёную галочку без расширения: человек открывает Cursor, панели нет, а установщик уже отчитался «OK» — и искать причину он будет не там. Матч без цифры версии дал бы ложный PASS на соседнем каталоге вида `anthropic.claude-code-helper-1.0`.
5. Второй elevated-путь к user-writable `code.cmd` возвращает ровно ту дыру, ради закрытия которой установку в VS Code отсюда убрали (P0-A) — и вдобавок ставит одно расширение дважды.
6. Копия vsix — до 80 МБ. Пропущенная уборка означает десятки мегабайт мусора в `%TEMP%` после каждого прогона, включая повторные, где ничего не ставится.
7. Убитый Cursor — это потерянная несохранённая работа человека. Не «ошибка установки», а испорченный файл, который никто не восстановит.
8. Переписанный `settings.json` стирает настройки, которые человек делал руками: тему, шрифт, отступы, привязки клавиш. Установщик выглядит как программа, которая портит чужое.
9. Fail-closed на шрифте остановил бы всю установку панели из-за косметической мелочи: человек остаётся без Claude в редакторе, потому что не совпал хэш `.ttf`.
10. Если отсутствие Cursor считать провалом, дефолтный набор (Cursor выключен по умолчанию) всегда заканчивался бы красным шагом — человек видел бы ошибку там, где всё в порядке.
11. Пользовательский PATH в elevated-процессе — тот же сценарий, что и в пункте 2, только через подложенный `git`/`node`/`winget` вместо редактора.
12. Dry-run, который что-то пишет или убивает Cursor, перестаёт быть безопасной репетицией: тестовый прогон уносит несохранённую работу.

## Границы

- Не устанавливает сам Cursor — это компонент `cursor` (`scripts/windows/cursor.ps1`).
- Не устанавливает панель Claude в VS Code (Windows): это `vscode.ps1`. Не устанавливает панель Codex/ChatGPT никуда — в Cursor её не ставит ни один скрипт репозитория.
- В `components.json` компонент называется «Расширение Claude Code» с описанием «Панель Claude Code внутри VS Code (и Cursor, если стоит)» и требует `vscode`, а не `cursor` (`components.json:81-96`) — то есть карточка в UI шире, чем делает Windows-скрипт.
- Офлайн-путь работает, только если рядом лежит проверенный `HM_VENDOR\apps\claude-code.vsix`. Без него и без интернета Marketplace-заход не поможет — панель не встанет, шаг закончится `exit 1` с инструкцией поставить её вручную.
- Уступка ради успеха установки: при провале и открытом пользовательском Cursor скрипт закрывает его принудительно, о чём предупреждает текстом «сохранённая работа не пострадает; несохранённая — увы» (`extension.ps1:216`).
- Уступка ради читаемости: проверенный vsix копируется туда, где его может прочитать пользователь. Комментарий (строки 45-47) обосновывает это тем, что vsix и так исполняется редактором при medium integrity, а целостность подтверждена до копирования.
- Ветка «мы сами запустили Cursor» опирается на `HM_CURSOR_AUTOSTARTED`; присваивания этой переменной нет ни в одном файле репозитория — она только читается (`extension.ps1:89`, комментарий `extension.ps1:83`). Вхождения при этом есть и за пределами `extension.ps1`, и ни одно значение не выставляет: `test/run-tests.js:6052` (`delete env.HM_CURSOR_AUTOSTARTED` — тест чистит окружение песочницы), `release/win-unpacked/resources/scripts/windows/extension.ps1:83` и `:89` (сборочная копия того же скрипта), плюс упоминание в `docs/specs/cursor-opcionalno.md:87`. Комментарий это признаёт формулировкой «если такой будет», то есть ветка задел на будущее, а не действующий путь.
- Запасной поиск CLI через `Get-Command cursor` работает по PATH, собранному `Update-Path`, то есть только по машинной ветке. Cursor ставится per-user, и его PATH-запись обычно пользовательская — практически этот запасной путь помогает лишь при машинной установке. Тест на это не найден.
- Компонент считается уже установленным, если расширение найдено в `.cursor`, `.vscode` ИЛИ `.vscode-oss` (`src/main.js:2513-2523`), а установленное по умолчанию снимается с галки (`src/renderer/app.js:230-235`). Следствие: у человека с панелью Claude в VS Code и свежим Cursor компонент по умолчанию выключен, и Cursor панель не получит, пока галку не вернуть руками.

## Риски и открытые вопросы

1. **Ретрай на Marketplace не смотрит на `Gate`.** В `vscode.ps1:199` второй заход разрешён только при `$r.Gate -eq 'medium'` (задача доказанно завершилась), а при `Gate -eq 'unknown'` печатается «второй запуск НЕ делаю» (`vscode.ps1:205-206`) — иначе вторая задача пойдёт поверх ещё идущей первой в тот же каталог расширений. В `extension.ps1:144-149` такой проверки нет: ретрай запускается по одному лишь факту неподтверждённой аттестации. Для Cursor это тот же класс конкурентной записи, что описан в комментарии `vscode.ps1`.
2. **`Gate = 'refused'` и `Gate = 'unknown'` не считаются провалом де-элевации.** `Install-Into` проверяет только `$null -eq $r` (`extension.ps1:138`). Обёртка, отказавшаяся исполнять бинарь не при medium integrity, возвращает `Code = -1`, `Gate = 'refused'` (`_deelev.ps1:672`) — то есть непустой объект. Человек в этом случае получит общую подсказку про панель расширений, а не сообщение «не удалось безопасно (де-элевированно)», которое точнее описывает причину.
3. **`cursor.ps1:107` гасит Cursor безусловно** (`Get-Process Cursor | Stop-Process -Force`) сразу после установки редактора. Комментарий `extension.ps1:84` опирается на это («в штатном флоу cursor.ps1 уже закрыл свой авто-запуск»), но сам `cursor.ps1` не отличает наш автозапуск от пользовательского окна. Ветка «щадим пользовательский Cursor» в `extension.ps1` заботится о том, что соседний скрипт мог уже убить.
4. **Дубль установки на macOS.** `scripts/macos/extension.sh:71-74` ставит `anthropic.claude-code` и в VS Code, тогда как `scripts/macos/vscode.sh:150` ставит то же расширение туда же. На Windows такой дубль был убран (P0-A, `extension.ps1:165-166`), на macOS он остался. Эскалации там нет (весь путь неэлевированный), но одна и та же работа делается дважды, и статус компонента зависит от того, который скрипт отработал.
5. **Логика продублирована между `extension.ps1` и `vscode.ps1`.** `Test-ExtPresent` (`extension.ps1:117-124`) и `Confirm-ExtInstalled` (`vscode.ps1:167-173`) — один и тот же цикл из шести попыток; расхождение из пункта 1 возникло именно на этом дубле и повторится при следующей правке одного из файлов.
6. **Прогонный тест `extension.ps1` в песочнице пропускается**, если на машине запущен Cursor (`SKIP`, `test/run-tests.js:6036`; сам тест объявлен на строке 6030) — по честной причине: скрипт ждёт 20 секунд и может закрыть редактор. Значит, на машине разработчика с открытым Cursor реального прогона нет, остаётся только статическая проверка исходника.
7. **Ветки без покрытия тестом (по итогам грепа `test/run-tests.js`):** установка шрифта и запись в `HKCU\...\Fonts`, сид `settings.json` Cursor и защита существующего файла, крайняя мера с закрытием Cursor, перебор четырёх путей `cursorCli`. Тесты на них не найдены; статические проверки касаются де-элевации, аттестации, копии vsix и её уборки.
