## Что обещает человеку

Установщик перед первым кликом сам смотрит, что на машине уже стоит, и помечает такие компоненты бейджем «✓ уже установлено» — снимая с них галку. По умолчанию будет доустановлено только недостающее: то, что уже работает, не переставляется поверх. Кто хочет — включает компонент обратно руками или жмёт «Переустановить начисто».

Второе обещание — про честность отрицательного ответа. На Windows список того, что установлено, строится в том числе по системному PATH, а прочитать его иногда не удаётся (антивирус или политика блокируют системные команды). В этом случае человек видит не молчаливое «ничего не установлено», а красный баннер: список ниже может ошибаться, проверь по факту, прежде чем ставить заново.

## Как работает

**1. Запуск.** Renderer после первичного рендера зовёт `detectAndApply()` (`src/renderer/app.js:159`, тело — 215-243), та через `window.installer.detectState()` (`src/preload.js:10`) вызывает IPC-обработчик `detect-state` (`src/main.js:2750`). Пере-детекция повторяется после удаления компонента (`src/renderer/app.js:574`).

**2. Свежие кэши на проход.** `detectComponents()` начинается с `detResetCaches()` (`src/main.js:2541-2542`), который очищает только кэш владельцев файлов `_detOwnerCache`. Кэш системного PATH (`_detPathCache`) проход детекции НЕ трогает — он сбрасывается точечно, через `invalidatePathCache()` после завершения компонентного скрипта (`src/main.js:1315`) и после правки PATH при удалении (`src/main.js:3049`).

**3. Чтение PATH (только Windows).** `freshWindowsPath()` (`src/main.js:2079`) читает машинный `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment\Path` и пользовательский `HKCU\Environment\Path` ОДНИМ вызовом `regQueryManyDotNet`; при сбое делается ровно один ретрай (2090). К результату дописываются `~/.local/bin`, `~/AppData/Roaming/npm` и кастомный npm-префикс из `~/.npmrc` (`npmPrefixFromRc`, 2050-2069). Возвращается `{ path, partial }`, где `partial = true`, если хоть один из двух запросов не удался (2097, 2122). `freshWindowsPathCached()` (2145-2154) пишет `_lastPathReadOk = !r.partial` и кэширует ТОЛЬКО полный результат.

**4. Детекторы по компонентам** (`src/main.js:2546-2744`), каждый даёт `{ installed, detectedVersion }`:

- `git` — `resolveExecutable(['git.exe'] / ['git'])` + Program Files\Git; версия через `probeVersion(bin, ['--version'])`. Ветвление macOS: если найден `/usr/bin/git` и Xcode Command Line Tools отсутствуют (`xcodeCltPresent()`, 2529), это Apple-шим — его НЕ пробим и считаем git не установленным (2555-2557), потому что его запуск сам открывает системный диалог установки инструментов разработчика.
- `node` — `resolveExecutable` + `Program Files\nodejs`, версия по `-v`.
- `cursor` — существование `Cursor.exe` в `%LOCALAPPDATA%\Programs\cursor` или `Program Files\cursor`; на macOS — `Cursor.app` в `/Applications` или `~/Applications`.
- `vscode` — «установлен» только если есть И приложение (`Code.exe` / `Visual Studio Code.app`), И ОБА расширения именно в каталогах VS Code: `vsCodeHasExt(home, claudeExtId) && vsCodeHasExt(home, 'openai.chatgpt')` (2580-2586). `claudeExtId` берётся из `config.json` → `claudeCodeExtensionId`, дефолт `anthropic.claude-code`.
- `claude` — `findClaudeBinary()` (2505): на Windows `claude.cmd/.exe/claude` в npm-префиксе и `~/.local/bin`; на POSIX — `~/.local/bin`, `<prefix>/bin`, `/usr/local/bin`, `/opt/homebrew/bin`. Версия не пробится, `detectedVersion` всегда `''`.
- `extension` — подкаталог расширения в `~/.cursor/extensions`, `~/.vscode/extensions`, `~/.vscode-oss/extensions`.
- `config` — маркер завершённости `~/.claude/.hamidun-config-complete` ИЛИ легаси-пара `~/.claude/skills` + `~/.claude/settings.json` (2611-2614).
- `pydeps` — `python(3)` + успешный `import PIL, requests`. Три гейта до запуска: macOS-шим `/usr/bin/python3` без CLT не запускается (2629), `winSafeToExec(py)` (2633), а сам вызов идёт с `-E`, доверенным `detectSpawnEnv()` и `cwd` в System32 (2643-2648).
- `course` — `CLAUDE.md` или `.claude/skills/course-driver/SKILL.md` внутри `<HM_COURSE_TARGET|~/HamidunCourse>/vibecoding-course`.
- `nomad` — шимы `nmd` / `nomad-agent` / `nomad-acp` в `~/.local/bin`, ИЛИ каталог uv-тула `nomad-agent`, ИЛИ клон исходников с `pyproject.toml`. Голое имя `nomad` намеренно не ищется (2665-2668).
- `uv`, `bridge`, `mascot`, `claude-desktop`, `chatgpt-desktop` — по существованию известных путей; у `uv` дополнительно пробится `--version`.

**5. Сборка ответа** (`src/main.js:2755-2780`). Обходятся `COMPONENT_META`; скрытые (`comp.hidden`) и не показанные на этой платформе (`componentShownOnPlatform`) пропускаются. На каждый id отдаётся `installed` (живая детекция), `detectedVersion`, `installedVersion` (из манифеста `~/.hamidun-setup/installed.json`), `currentVersion` (из `components.json`), `updateAvailable = installed && manifest.isOutdated(installedVersion, currentVersion)` и `receipted = receipts.hasReceipt(home, id)`. Отдельным полем едет `pathReadOk`: на не-win32 всегда `true`, на Windows — `lastPathReadOk()`.

**6. Показ.** `detectAndApply()` кладёт состояние в `STATE.detected`, ставит `STATE.pathReadFailed = (r.pathReadOk === false)` и для каждого установленного не-скрытого компонента без активного repair выставляет `STATE.selected[id] = false` (`src/renderer/app.js:230-235`). Затем рисуются: карточка с бейджами «✓ уже установлено · <версия>» и «обновление доступно» (`renderCard`, 423-426), жёлтый баннер `#installed-banner` про аддитивную доустановку (246-262) и красный `#pathread-warn` — только если `STATE.pathReadFailed` (267-279). Весь блок обёрнут в `try` с `finally { STATE.detectDone = true; refreshDerived(); }` — кнопка установки разблокируется даже при сбое детекции.

## Инварианты

1. **Ответ на «установлен ли X?» даёт живая проверка, а не манифест.** `detectComponents` строит `out.*` только из `fs.existsSync` / `fs.readdirSync` / запуска бинаря (`src/main.js:2546-2744`); из манифеста в `detect-state` берётся ТОЛЬКО `installedVersion` для показа и сравнения (2760-2761). Модель доверия зафиксирована в шапке `src/install-manifest.js:7-13`.
2. **«Не смогли прочитать PATH» не выдаётся за «не установлено».** Признак живёт отдельным полем: `freshWindowsPath` возвращает `partial` (`src/main.js:2122`), `freshWindowsPathCached` пишет `_lastPathReadOk = !r.partial` (2148), `detect-state` отдаёт `pathReadOk` (2779-2780), renderer поднимает `#pathread-warn` (`src/renderer/app.js:229`, 267-279).
3. **Неполный PATH не кэшируется.** `if (!r.partial) _detPathCache = r.path;` (`src/main.js:2152`) — один сбой чтения реестра не замораживает огрызок на весь сеанс.
4. **Под elevated-токеном не запускается бинарь, который мог подменить medium-юзер.** `probeVersion` выходит с пустой версией, если `winSafeToExec(bin)` false (`src/main.js:2463`); тот же гейт стоит перед запуском python (2633). `winSafeToExec` (2411-2422) сначала канонизирует путь через `fs.realpathSync.native` (не смог — `false`), затем требует admin-owned корень (`winPathAdminOwned`) ИЛИ admin-owned файл с отсутствием write-прав у не-admin принципалов на файл и его родителя (`winFileAdminOwned`, 2360-2406).
5. **Детекционные спавны на Windows идут с доверенным окружением, а не с `process.env`.** `detectSpawnEnv()` (`src/main.js:2163-2178`) собирает `SystemRoot`/`PATH`/`PSModulePath` из валидированного системного корня и пропускает только профильные переменные; используется в `probeVersion` (2470), в проверке владельца (2399-2401) и в pydeps-пробе (2646).
6. **Расширение засчитывается только по подкаталогу `^<extId>-<цифра>` и только если это каталог.** `dirHasChildStarting` (`src/main.js:2488-2494`) — `withFileTypes: true` + `d.isDirectory()` + regex с экранированным id и обязательной цифрой.
7. **`vscode` считается установленным только при приложении И обоих расширениях в VS Code.** `installed: !!appPresent && bothExts` (`src/main.js:2586`), где `bothExts` требует Claude И `openai.chatgpt` именно в `.vscode`/`.vscode-oss` (`vsCodeHasExt`, 2498-2502).
8. **`config` считается установленным по маркеру завершённости, а не по наличию файлов.** `~/.claude/.hamidun-config-complete` (пишется скриптами только в конце успешной раскладки) либо легаси-пара `skills`+`settings.json` (`src/main.js:2611-2614`).
9. **Apple-шимы на macOS без Command Line Tools не запускаются.** `git`: `macShim` (`src/main.js:2555`); `python`: `pyShim` (2629); оба опираются на `xcodeCltPresent()`, который зовёт `xcode-select -p` — команду, которая, в отличие от `git` и `xcode-select --install`, диалог установки не открывает (2525-2537).
10. **Обнаруженное установленным по умолчанию снимается с галки, а не переустанавливается.** `STATE.selected[id] = false` для `installed && !hidden && !STATE.repair[id]` (`src/renderer/app.js:230-235`).
11. **Бейдж «обновление доступно» требует и подтверждённой установки, и строго меньшей записанной версии.** `!!d.installed && manifest.isOutdated(...)` (`src/main.js:2770`); `isOutdated` даёт `true` только при `compareVersions < 0` и пустых значениях возвращает `false` (`src/install-manifest.js:199-202`), а непарсимые версии (`1.0.1-rc`) дают `parseVersion → null → compareVersions → 0` (177-196).
12. **Кнопка «Удалить» предлагается только для того, что ставил установщик.** `receipted: receipts.hasReceipt(home, id)` (`src/main.js:2773`), карточка гейтит `removable = REMOVABLE.has(c.id) && det.receipted` (`src/renderer/app.js:513`).
13. **Сбой детекции не блокирует установку.** `detectAndApply` завершается блоком `finally { STATE.detectDone = true; refreshDerived(); }` (`src/renderer/app.js:239-242`), а `detect-state` при исключении возвращает `{ ok:false, error, state:{} }`, а не бросает (`src/main.js:2781-2783`).
14. **Скрытые и чужие по платформе компоненты в ответ детекции не попадают.** Пропуск по `comp.hidden` и `componentShownOnPlatform` (`src/main.js:2757-2758`).

## Что ломается, если инвариант нарушить

1. Отставший или повреждённый `installed.json` начинает решать за реальность: человек с рабочим Claude Code видит «не установлено» (или наоборот) и получает установку поверх живого — при этом манифест лежит в user-writable `~/.hamidun-setup` и его может подделать любой процесс того же пользователя.
2. На машине с корпоративным антивирусом весь список показывается «не установлено» без единого предупреждения — человек ставит заново уже работающие git/node/Claude и в лучшем случае теряет полчаса, в худшем ломает свою рабочую конфигурацию.
3. Один случайный таймаут чтения реестра ослепляет детекцию до конца сеанса: кнопка «перепроверить» перестаёт что-либо менять, потому что в кэше навсегда огрызок PATH.
4. Малварь того же пользователя кладёт `git.exe` в `~/AppData/Roaming/npm`, установщик запускает его на `--version` под правами администратора — и получает выполнение произвольного кода ещё до первого клика человека.
5. То же самое, но через переменные окружения: подложенный `PYTHONPATH`/`PYTHONSTARTUP` (или `PSModulePath` для powershell) заставляет интерпретатор импортировать чужой модуль под администратором прямо в фазе детекции.
6. Каталог `anthropic.claude-code-helper-1.0` или одноимённый ФАЙЛ засчитываются как установленное расширение: галка снимается, расширение не ставится, Claude Code в редакторе не появляется, и человек не понимает, почему «всё установлено», а работать нечем.
7. Сценарий «VS Code уже стоит, Codex нет» снова становится молчаливым: галка снимается, единственный доставщик Codex (`vscode.ps1`/`vscode.sh`) не запускается, человек остаётся без второго ассистента без всякого сообщения.
8. Оборванная на середине раскладка `~/.claude` (сон, перезагрузка, антивирус) выглядит завершённой: галка `config` снимается, повторный запуск ничего не доразворачивает, и человек живёт с половиной скиллов и без настроек.
9. Первое же открытие установщика на чистом маке выкидывает системный диалог «установить инструменты разработчика» — до единого клика, поверх окна, с непонятной человеку формулировкой; тестер уже упирался в это.
10. Установка перестаёт быть аддитивной: по умолчанию переставляется всё найденное, включая конфиг с личными скиллами и настройками, — обещание «твои скиллы и настройки в ~/.claude в безопасности» из жёлтого баннера становится ложью.
11. Ложный бейдж «обновление доступно» на всём подряд (в том числе при пустой записи или версии вида `1.0.1-rc`) — человек запускает переустановку без причины.
12. Кнопка «Удалить» появляется у чужого git/node/Cursor, который человек ставил сам задолго до установщика: удаление чужого софта чужим инсталлятором.
13. При любом исключении в детекции кнопка «Установить» остаётся выключенной навсегда — установщик мёртв, а причина на экране не названа.
14. В список выбора протекают компоненты, которых на этой ОС не существует (например, win32-only `uv` на macOS): человек их выбирает и упирается в отказ на этапе докачки.

## Границы

- Детекция отвечает на вопрос «присутствует ли», а НЕ «работает ли» и НЕ «подходит ли версия». Ни для одного компонента нет проверки минимальной версии: `out.git.installed = !!(bin && v)` — годится любой распознанный `git --version`.
- Версия показывается только там, где её удалось пробить: `git`, `node`, `uv`. У остальных, включая `claude`, `detectedVersion` — пустая строка по коду, поэтому бейдж «✓ уже установлено» у них без версии.
- Поиск идёт по известным путям и PATH; реестр Windows Uninstall, Homebrew-манифесты, winget-каталог и прочие реестры установленного не опрашиваются. Установка в нестандартный каталог, которого нет в PATH, не будет замечена.
- Program Files выводится из валидированного системного корня, а не из переменных окружения (`src/main.js:2310-2322`). Осознанная уступка, названная прямо в комментарии: у администратора, перенёсшего Program Files на другой диск, компонент может не задетектиться — предпочли безопасный ложно-отрицательный.
- `pydeps` заведомо допускает ложный негатив (комментарии 2616-2617, 2626-2628): при недоступном для запуска python пакеты не проверяются вовсе, а сама проверка сведена к двум представителям — `PIL` и `requests`.
- UNC-пути (`\\server\share`) в PATH при детекции пропускаются целиком (`src/main.js:2446`) — компонент, установленный на сетевой диск, невидим.
- `pathReadOk` — исключительно про Windows и исключительно про чтение PATH из реестра: на macOS он всегда `true` (2779), и никакой аналогичной честной пометки для других видов сбоя детекции нет.
- Признак «уже установлено» не различает, кто поставил компонент; для этого есть отдельный `receipted` (квитанции установщика), и именно он, а не `installed`, гейтит удаление.

## Риски и открытые вопросы

- **Ключевая часть фичи не покрыта тестом.** По `test/run-tests.js` нет ни одного совпадения на `pathReadOk`, `pathReadFailed`, `renderPathReadWarning`, `pathread-warn`, `renderInstalledBanner`, `installed-banner`. Обещанный «честный баннер» и авто-снятие галки не проверяются вовсе. Покрыт только источник флага — тест «freshWindowsPath: сбой чтения реестра → partial, огрызок не кэшируется», и он обёрнут в `if (process.platform === 'win32')` (`test/run-tests.js:7536`), то есть на macOS-раннере молча не выполняется. Инвентарь при этом помечает фичу `tested: yes`.
- **Сбой детекции целиком остаётся немым.** `detect-state` при исключении отдаёт `{ ok:false, state:{} }` (`src/main.js:2781-2783`), а `detectAndApply` на `!r.ok` просто делает `return` (`src/renderer/app.js:223`) — до `renderPathReadWarning` дело не доходит. Человек видит всё как «не установлено» без единого предупреждения: ровно тот сценарий, ради которого сделан баннер, но по другой ветке.
- **Цена честности при сбое чтения реестра.** Неполный PATH намеренно не кэшируется (2152), но `freshWindowsPathCached` всё равно возвращает огрызок, и каждый следующий `resolveExecutable` в проходе (`git`, `node`, `python`, `nomad`, `uv`) заново платит запуск интерпретатора с ретраем. То есть именно тот проход, в котором PATH не читается, оказывается самым медленным — при выключенной кнопке «Установить».
- **`_cltPresent` кэшируется на весь процесс** (`src/main.js:2528`) и НЕ сбрасывается `detResetCaches` (2142). Если человек на macOS поставит Command Line Tools, не закрывая установщик, повторная детекция продолжит считать `/usr/bin/git` и `/usr/bin/python3` шимами и показывать git/pydeps ненайденными.
