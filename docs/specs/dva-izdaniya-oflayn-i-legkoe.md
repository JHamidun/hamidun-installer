## Что обещает человеку

Один и тот же установщик раздаётся в двух видах, и человек выбирает по своей ситуации, а не
по знанию внутренностей. **Офлайн** — тяжёлый файл, внутри которого уже лежит всё ПО: скачал
один раз (на диске сейчас `release/Hamidun-Setup-Windows.exe` = 1 438 688 139 Б), принёс на
машину и ставишь, даже если интернет плохой или его нет вовсе. **Лёгкое** —
`release/Hamidun-Setup-Windows-Lite.exe` = 87 950 026 Б: качается за минуту, а тяжёлые куски
он докачивает во время установки и только те, которые человек отметил галочками.

Обещание, за которое можно спросить: в лёгком издании интерфейс не врёт про цифры. Возле
каждого компонента стоит точный размер того, что скачается (из вшитого реестра, не из
рукописной константы), внизу — «Скачается: ~X», и на кнопке то же число. Пока установщик не
проверил, что сервер загрузки отвечает, кнопка «Установить» неактивна — человек не начинает
установку, которая заведомо оборвётся на середине. И в обоих изданиях всё, что доехало из
сети, ставится только после совпадения sha256; не совпало — компонент не запускается.

## Как работает

**Издание — это два поля в `config.json` внутри артефакта, а не отдельная ветка кода.**
В коммите этих полей нет вовсе (тест «config.json в репозитории без сборочных маркеров»
читает `git show HEAD:config.json` и требует отсутствия и `edition`, и `offlineEdition`).
Поля появляются на сборке:

* `tools/fetch-vendor.ps1:618-642` (и симметрично `tools/fetch-vendor-mac.sh:701-724`) пишет
  `offlineEdition = true`, **только** если его же проверка полноты vendor прошла без пропусков
  (`$missing` пуст); иначе честно пишет `false` и печатает WARNING, но сборку не валит.
  Вставка текстовая — регексом после первой `{` (строка 637), поэтому в готовом артефакте ключ
  стоит строкой 2 (проверено на `release/win-unpacked/resources/config.json`).
* `tools/build-lite.js` в `main()` (шаг 1, строки 317-327) ставит `edition = 'lite'`,
  `offlineEdition = false` и `configRepoBranch = 'main'` (запасной клон-путь конфига; в
  комментарии там же сказано, что прежнее значение `'v38'` указывало на несуществующую ветку).
  Ключи дописываются `JSON.stringify`, поэтому в готовом lite-артефакте `edition` оказывается
  последним ключом файла — проверено на том же `release/win-unpacked/resources/config.json`
  (`"offlineEdition": false` строкой 2, `"edition": "lite"` в хвосте).

**Сборка офлайн-издания** — `npm run dist:win` (`package.json:17-21`): `assert:clean` →
`fetch:config` → `fetch:vendor` → `preflight` → `electron-builder --win`. Артефакт
`Hamidun-Setup-Windows.exe`, vendor вшивается через `build.win.extraResources` (`from: "vendor"`).

**Сборка лёгкого издания** — `npm run dist:win:lite` = `node tools/build-lite.js`
(`--mac` → `dist:mac:lite`). Ни `fetch:vendor`, ни `fetch:config` не запускаются: сборщик
работает по уже наполненному `vendor/`. Порядок шагов в `main()`:

1. бэкап `config.json` и `package.json` в память; вешаются слушатели `SIGINT`/`SIGTERM`
   (строки 313-315), чтобы Ctrl+C не оставил дерево мутированным;
2. мутация `config.json` (см. выше);
3. мутация `package.json` через `mutatePackage()` (258-286): на Windows `extraResources.from`
   переводится с `vendor` на `vendor-lite`, и имя артефакта ставится **и** в `build.win`,
   **и** в `build.portable` (target-specific перебивает общее); на macOS `extraResources` с
   vendor не добавляется сознательно — правится только пара имён `build.mac` / `build.dmg`;
4. `buildVendorLite()` (122-148) собирает каталог `vendor-lite/` по списку своей платформы:
   `LITE_KEEP_WIN` = `checksums.json` + `apps/uv` + `course/vibecoding-course.zip`;
   `LITE_KEEP_MAC` = `checksums.json` + `apps/uv-macos-*.tar.gz` (glob через `expandKeep`,
   `*` разрешена только в имени файла) + курс + `licenses` (помечен необязательным третьим
   элементом). Отсутствие обязательного элемента — исключение с подсказкой, чем наполнить vendor;
5. `assertRegistryMatchesChecksums()` (159-240) — гейт **до** долгой упаковки: сверяет
   `gatedFiles` каждой записи своей платформы из `remote-components.json` с тем самым
   `vendor-lite/checksums.json`, который уедет в артефакт; запись без поля `gatedFiles` —
   исключение; пустой `gatedFiles` — предупреждение со списком; дополнительно требует штамп
   `vendor/config-pack/.hamidun-config-pack.json` и, если задан `HM_CONFIG_REF`, совпадение
   коммита; ноль записей для платформы — исключение;
6. `npx electron-builder` с аргументами платформы (для mac — `--universal`);
7. size-assert: `findLiteArtifact()` ищет артефакт в `dist`, `release`, `dist/win-unpacked`,
   и при превышении потолка (`maxBytes`: 320 МиБ для win, 400 МиБ для mac) бросает исключение;
8. `finally` — восстановление из бэкапов: сначала `package.json`, потом `config.json`, потом
   удаление `vendor-lite`; каждый шаг независимо, сбой любого печатает точную команду ручного
   отката и ставит ненулевой `exitCode`.

Кросс-сборка mac-издания заблокирована: `hostPlatform: 'darwin'` проверяется в `main()`
(291-295) и снимается только `HM_LITE_FORCE_CROSS=1`, о чём печатается предупреждение
«артефакт НЕ раздавать» (301-305).

**Что делает рантайм.** `src/main.js` читает вшитый `config.json`: `isOfflineEdition()`
(89-92) и `isLiteEdition()` (98-101). Дальше издание разводит четыре вещи:

* **Кто считается remote.** `loadRemoteMaps()` (628-651): явные `remote` + `remoteId` из
  `components.json` берутся всегда; если издание lite — компонент дополнительно становится
  remote автоматически, когда его `id` есть в реестре (`id == remoteId`), кроме множества
  `BUNDLED_ONLY = {'uv'}`. В `components.json` сейчас нет ни одного явного `remote`-флага
  (проверено чтением файла), значит в офлайн-издании карта `compRemote` пуста, и докачка не
  включается ни для одного компонента.
* **Качать или нет.** В обработчике `run-component` (объявлен `ipcMain.handle('run-component', …)`
  на 875; блок докачки — 968-1086): `vendorHasArtifact` —
  существует ли основной артефакт компонента по карте `COMPONENT_VENDOR_ARTIFACT` в bundled
  vendor; `useBundled = vendorHasArtifact || isOfflineEdition()`. При `useBundled` печатается
  «[локально] … докачка не нужна» и сеть не трогается. Иначе `remoteFetch.pickEntry` выбирает
  запись под платформу, на win32 создаётся свежий Admins-only каталог, и
  `remoteFetch.fetchRemote` (`src/remote-fetch.js:897-1015`) качает с зеркал по возрастанию
  латентности с обязательной проверкой sha256. После успеха в staging копируется вшитый
  `checksums.json` (не удалось — компонент отклоняется со стадией `fetch`), `HM_VENDOR`
  указывает на staging, а конкретные пути резолвятся через `vendorPick()` (1109-1115): есть в
  staging — оттуда, иначе из bundled vendor. Отдельная ветка (1124-1134) докладывает вшитый
  `uv` в staging компонента `nomad`.
* **Что видит renderer.** `bootstrap` (513-559) отдаёт `edition: isLiteEdition() ? 'lite' : 'offline'`,
  карту `remoteSizes` (`remoteSizesForRenderer()`, 657-668 — точные `sizeBytes` из реестра) и
  `vendorAvailable: editionVendorPresent()`. `editionVendorPresent()` (122-132) для офлайна
  спрашивает про `config-pack`, а для lite — про `checksums.json` + `uv` + курс, потому что
  `config-pack` в lite отсутствует по построению. Жёсткий стоп `vendorBlockInfo()` (143-152)
  работает только на упакованном macOS: translocation блокирует всегда, неполный vendor —
  только у издания с `offlineEdition`.
* **Сеть до старта.** IPC `probe-remote` (676-694) в офлайн-издании сразу возвращает
  `{online:true, skipped:true}`; в lite пробует зеркала первой платформенной записи реестра
  (`probeMirror`, дедлайн 8 с). `src/renderer/app.js:169-186` держит `netProbeDone` и до его
  завершения кнопка «Установить» выключена (`refreshDerived`), но сам отрицательный ответ —
  мягкий жёлтый баннер с «Проверить снова», а не блокировка; ошибка самого IPC трактуется
  fail-open.

**Цифры в интерфейсе** тоже разводятся по изданию (`src/renderer/app.js:1166-1226`):
`componentSizeBytes()` в lite берёт размер докачки из `remoteSizes`, в офлайне — вшитый
`sizeBytes[платформа]` из `components.json`; подпись бейджа и заголовок попапа меняются
(«Что скачается на мой ПК» против «Что попадёт на мой ПК»); `downloadTotalBytes()` считает
сумму только в lite, `bundledTotalBytes()` — только в офлайне.

**Гейты вокруг изданий.** `tools/assert-clean.js:39-81` проверяет, что дерево не осталось
мутированным после lite-сборки (обе платформы разом, без ветвлений по `process.platform`), и
стоит первым шагом в `dist`, `dist:win`, `dist:mac`. `tools/preflight-build.js:390-413` при
`edition === 'lite'` сознательно пропускает гейт свежести конфиг-пака, потолок makensis и
проверку дублей npm-кеша — у lite свой size-assert. `tools/before-pack.js` вызывает тот же
preflight хуком `beforePack`, чтобы его нельзя было обойти прямым запуском electron-builder.

**macOS-специфика.** vendor в `.app` не вшивается (нотаризация спотыкается о неподписанные
Mach-O внутри вложенных архивов), поэтому он едет сиблингом рядом с `.app` на томе dmg, а
`vendorRoot()` (`src/main.js:34-43`) на упакованном darwin сначала ищет папку `vendor` на три
уровня выше `Resources`. Финальный lite-dmg собирает не electron-builder, а шаг «Assemble
final lite dmg» в `.github/workflows/build-mac-lite.yml:246-340`: он проверяет `lipo -archs`
на обе арх, читает вшитый `config.json` и падает, если там не `edition=lite` +
`offlineEdition=false`, собирает лёгкий vendor, требует в нём `checksums.json` и потолок
400 МБ, и только потом `hdiutil create`.

## Инварианты

1. **Офлайн-издание не ходит в сеть за компонентами.** `useBundled = vendorHasArtifact || isOfflineEdition()`
   (`src/main.js:989`), и при истине ветка 990-993 печатает «докачка не нужна» вместо
   `fetchRemote`. Плюс в офлайне `compRemote` пуста, потому что в `components.json` нет явных
   `remote`-флагов (проверено чтением файла).
2. **`uv` в lite никогда не докачивается.** `BUNDLED_ONLY = new Set(['uv'])` в `loadRemoteMaps`
   (`src/main.js:641`) исключает его из авто-remote; он вшит списком `LITE_KEEP_WIN` /
   `LITE_KEEP_MAC` (`tools/build-lite.js:45-60`). Тест
   «lite: тяжёлые компоненты авто-remote по реестру; uv bundled-only» под этим держит только
   данные про тяжёлые компоненты: его тело (`test/run-tests.js:281-290`) сверяет два списка id
   с реестром, а `uv` не фигурирует ни в одном ассерте — заголовок обещает больше, чем делает
   тело. Bundled-only-статус `uv` фиксирует другой тест — «release-check загружается и знает
   про законные исключения реестра (uv/course)» (`test/run-tests.js:8858-8863`), и проверяет он
   список `NO_REGISTRY_OK` в `tools/release-check.js`, а не `BUNDLED_ONLY` в `src/main.js`.
3. **Ни один докачанный архив не распаковывается без совпадения sha256 из реестра.**
   `fetchRemote` отвергает запись без валидного sha (`src/remote-fetch.js:911-916`) и удаляет
   файл при несовпадении, переходя к следующему зеркалу (989-996).
4. **Второй гейт целостности едет вместе со staging.** После успешной докачки в каталог
   staging копируется вшитый `checksums.json`; не скопировался — компонент отклоняется со
   стадией `fetch` (`src/main.js:1080-1085`).
5. **Лёгкий артефакт не превышает потолок своей платформы.** 320 МиБ win / 400 МиБ mac —
   `TARGETS[*].maxBytes` и проверка после сборки (`tools/build-lite.js:71,82,348-353`).
6. **Lite не собирается, если вшиваемый `checksums.json` разошёлся с опубликованными
   архивами или реестр пуст для платформы.** `assertRegistryMatchesChecksums()`
   (`tools/build-lite.js:159-240`) вызывается шагом 3b (338) — до `electron-builder`.
7. **Дерево возвращается в офлайн-состояние после lite-сборки, а офлайн-сборка не стартует
   на остатках.** `finally` (`tools/build-lite.js:368-387`) и гейт `assert:clean`
   (`tools/assert-clean.js:39-81`), стоящий первым в `dist` / `dist:win` / `dist:mac`
   (`package.json:17-21`).
8. **В коммите `config.json` нет ни `edition`, ни `offlineEdition`.** Держит тест
   «config.json в репозитории без сборочных маркеров» (читает `git show HEAD:config.json`).
9. **`offlineEdition = true` пишется только при полном vendor.** `$offlineVal` вычисляется из
   `$missing` (`tools/fetch-vendor.ps1:619`), симметрично `tools/fetch-vendor-mac.sh:701-724`.
10. **Признак «нужное рядом» проверяется по составу СВОЕГО издания.** `editionVendorPresent()`
    (`src/main.js:124-134`): офлайн — по `config-pack`, lite — по `checksums.json` + `uv` +
    курсу. Держат тесты «lite (macOS): том dmg БЕЗ config-pack считается «сиблинг на месте» —
    ложной плашки нет», «lite (macOS): .app перетащили в «Программы» → сиблинга нет → плашка
    ОБЯЗАНА гореть», «lite (macOS): неполный сиблинг (нет checksums.json / нет uv / нет
    курса) → плашка горит» и мутационный тест «МУТАЦИЯ: вернуть проверку config-pack в
    lite-ветку → тест краснеет (фикс не косметический)».
11. **Жёсткий стоп по неполному vendor распространяется только на офлайн-издание.**
    `if (!vendorComplete() && isOfflineEdition())` в `vendorBlockInfo()` (`src/main.js:150`);
    ровно эту строку сторожит тест «bootstrap отдаёт renderer editionVendorPresent, а не
    vendorAvailable; текст плашки верен для ОБОИХ изданий».
12. **В lite кнопка «Установить» не активируется, пока не отработала проба сервера докачки.**
    `STATE.netProbeDone` инициализируется как `STATE.edition !== 'lite'`
    (`src/renderer/app.js:80`) и входит в `btnInstall.disabled` в `refreshDerived()`.
13. **Показанная цифра размера соответствует изданию.** `componentSizeBytes()`
    (`src/renderer/app.js:1166-1173`) — в lite только из `remoteSizes`, иначе 0 (ничего не
    показываем); в офлайне только из `components.json`. Держит тест «окно «что попадёт на мой
    ПК»: единица измерения названа словами, заголовок честен в офлайне».
14. **В lite пути к файлам чужого компонента не теряются за staging.** `vendorPick()`
    (`src/main.js:1111-1117`) резолвит по факту существования: staging → bundled vendor.
15. **macOS lite-dmg не выпускается из не-lite `.app`.** Python-гейт в шаге «Assemble final
    lite dmg» падает, если во вшитом `config.json` не `edition=lite` и `offlineEdition=false`
    (`.github/workflows/build-mac-lite.yml:270-275`).

## Что ломается, если инвариант нарушить

1. Офлайн-издание, купленное ради «поставить без интернета», на машине без сети встанет на
   первом же тяжёлом компоненте — то есть перестанет быть тем, что человеку обещали.
2. `uv` — единственный менеджер окружения для Nomad и pydeps. Уйдя в докачку, он бы качался
   там, где для него нет записи-источника, а в ветке `nomad` установка свалилась бы в
   `irm https://astral.sh/uv/install.ps1 | iex` под админом (об этом прямо сказано в
   комментарии «LITE-ГОЧА №2 (nomad)» — `src/main.js:1118-1125`, URL на 1118) — то есть
   исполнение скачанного скрипта с правами
   администратора вместо байтов, лежащих внутри установщика.
3. Подменённый на зеркале архив был бы распакован и запущен под админскими правами — это
   компрометация машины ученика, а не «ошибка установки».
4. Без `checksums.json` в staging install-скрипты не смогли бы проверить артефакт по
   basename: остался бы один рубеж вместо двух, и порча/подмена внутри архива прошла бы дальше.
5. Лёгкое издание перестало бы быть лёгким молча: человек с телефонным интернетом качал бы
   вместо 84 МБ полтора гигабайта, не понимая почему.
6. У **каждого** пользователя lite докачка проходила бы, а второй гейт падал бы с «файл
   подменён» — то есть релизная ошибка выглядела бы как атака (ровно это и объясняет
   комментарий на 150-158 в `tools/build-lite.js`).
7. Следующая офлайн-сборка тихо собралась бы из `vendor-lite` и уехала под именем
   `…-Lite.exe`: получился бы файл, который называется офлайновым, но внутри почти пуст.
8. Маркер в коммите означал бы, что любая сборка с чистого чекаута объявляет себя офлайновой:
   на macOS такой артефакт сам себя блокирует модальным окном про карантин, а любой
   remote-компонент вместо докачки печатает «офлайн-издание — докачка не нужна».
9. Издание с неполным vendor заявляло бы офлайн-гарантию, которой у него нет: на macOS оно
   уходило бы в жёсткий блок, а на Windows — в отказ ставить то, чего внутри нет.
10. Ложная тревога в обратную сторону: маковод, запустивший `.app` правильно из окна dmg,
    видел бы плашку «файлы рядом не подхватятся» и либо бросал установку, либо переставал
    верить предупреждениям вообще.
11. Расширение блока на lite превратило бы легитимную лёгкую сборку в кирпич: у неё
    `config-pack` отсутствует по построению, и стоп срабатывал бы всегда.
12. Установка стартовала бы при недоступном сервере и обрывалась на середине первого тяжёлого
    компонента — худший из возможных моментов, потому что часть уже поставлена.
13. В окне «что попадёт на мой ПК» стояло бы выдуманное число. Для человека, который боится
    вируса и сверяет цифры с размером скачанного файла, выдуманная цифра страшнее отсутствующей.
14. `pydeps` в lite искал бы `requirements.txt` в чужом staging и падал с «сначала установите
    конфиг», а `nomad` не видел бы `nomad-src` — половина компонентов ломается на ровном месте.
15. Уехал бы dmg с офлайн-логикой и лёгким vendor: установщик считал бы, что всё вшито, и не
    качал бы ничего, хотя внутри только uv и курс.

## Границы

* Лёгкое издание **не** уменьшает то, что в итоге окажется на машине. Оно уменьшает только
  размер дистрибутива; распакованное ПО занимает столько же. В коде это сказано в комментарии
  над `componentSizeBytes` (`src/renderer/app.js:1157-1159`) и в подсказке бейджа
  офлайн-издания («на диске после установки будет больше», `src/renderer/app.js:1184`);
  lite-ветка того же тернарника (1183) говорит только «Столько скачается с сервера во время
  установки» и про место на диске молчит — человеку в lite эту границу интерфейс не проговаривает.
* В lite **не вшит конфиг-пак**: `LITE_KEEP_WIN` / `LITE_KEEP_MAC` — это `checksums.json`,
  `uv` и курс, и ничего больше. Конфиг едет обычным remote-компонентом (`config` в
  `remote-components.json`: win32 129 076 529 Б, darwin 132 113 970 Б). Подтверждено составом
  `release/win-unpacked/resources/vendor` — там ровно `apps`, `checksums.json`, `course`.
* `tools/build-lite.js` не наполняет vendor: он не запускает ни `fetch:vendor`, ни
  `fetch:config` и падает с подсказкой, если обязательного элемента в `vendor/` нет.
* На macOS vendor не попадает внутрь `.app` ни в каком издании. Промежуточный dmg от
  electron-builder в lite **не содержит** uv и курса — это состояние явно печатается в лог
  (`tools/build-lite.js:357-366`), финальный том собирает CI.
* Кросс-сборка mac-издания на не-macOS возможна только флагом `HM_LITE_FORCE_CROSS=1` и даёт
  артефакт без подписи и нотаризации — раздавать его нельзя (сказано в логе, 301-305).
* Гейт `assert:clean` стоит только в офлайн-скриптах (`dist`, `dist:win`, `dist:mac`).
  `dist:win:lite` и `dist:mac:lite` его не вызывают.
* Уступка в `assertRegistryMatchesChecksums`: записи с пустым `gatedFiles` не валят сборку, а
  печатаются предупреждением. Сейчас таких записей четыре — `claude` и `config` на обеих
  платформах (проверено по `remote-components.json`): у них `gatedFiles` = `{}`, потому что
  это компоненты-каталоги, представителя которых нет в `vendor/checksums.json`.
* Для `handy` в реестре есть записи обеих платформ (win32 20 927 084 Б, darwin 40 693 722 Б),
  и явных `remote`-флагов в `components.json` у него нет — значит в lite он попадает под
  авто-remote, а в офлайне управляется vendor-first-картой (`handy: 'apps/handy-setup.exe'`).

## Риски и открытые вопросы

* **Сам сборщик изданий не покрыт ни одним тестом.** Поиск по `test/run-tests.js` находит
  `build-lite.js` трижды: дважды в комментариях (строки 8041, 8042) и один раз в тексте живого
  `assert` (8862) в тесте «release-check загружается и знает про законные исключения реестра
  (uv/course)» — то есть проверяется факт из `LITE_KEEP_*`, а не код сборщика. `assert-clean.js`
  и `vendor-lite` не упоминаются вовсе. То есть size-assert, сверка реестра с вшитым
  манифестом, мутация `package.json`/`config.json` и восстановление в `finally` проверяются
  только живым прогоном сборки. Тесты, процитированные в шапке, покрывают рантайм-сторону
  (кто remote, что показывает renderer, когда горит плашка) — но не сборочную.
* **Устаревший комментарий про `prep-lite.js`.** `src/main.js:96-99` утверждает, что маркер
  `edition:'lite'` ставит `prep-lite.js`. Такого файла в `tools/` нет (проверено листингом);
  маркер ставит `tools/build-lite.js:319`.
* **Ветка «источник истины» в mac-workflow практически мертва.** Шаг «Assemble final lite
  dmg» сначала ищет каталог `vendor-lite` / `vendor-lite-mac`
  (`.github/workflows/build-mac-lite.yml:286-292`), но `tools/build-lite.js` удаляет
  `vendor-lite` в `finally` при любом исходе. При нормальной сборке отработает фолбэк,
  который собирает тот же минимум из `vendor/` собственным списком `cp` — то есть состав
  лёгкого vendor описан в двух местах и может разъехаться.
* **Пропуск size-assert не является ошибкой сборки.** Если артефакт не найден,
  `tools/build-lite.js:354-356` печатает «ВНИМАНИЕ» и продолжает с нулевым кодом возврата —
  то есть переименование артефакта отключает потолок молча.
* **E2E-прогоны имитируют lite правкой `config.json`, а не сборкой.** `.github/workflows/e2e-win.yml`
  на строках 79-88, 211-220 и 329-333 выставляет `edition=lite` / `offlineEdition=false`
  прямо в дереве. Это проверяет рантайм-путь докачки, но не путь упаковки (`vendor-lite`,
  мутация `package.json`, size-assert, восстановление).
* **Грязное дерево переживает lite-сборку.** `tools/build-lite.js` восстанавливает те байты,
  которые прочитал в начале (`cfgBak` / `pkgBak`), а `assert:clean` в lite-скриптах не
  вызывается — значит остатки от прошлой прерванной lite-сборки не будут ни замечены, ни
  вычищены; поймает их только следующая офлайн-сборка.
* **Не подтверждено кодом:** что `offlineEdition` вообще проставляется у macOS-издания,
  собираемого командой `npm run dist:mac` — в этом скрипте (`package.json:20`) нет
  `fetch:vendor`, а маркер пишет только фетчер. В CI `.github/workflows/build-mac.yml:83`
  `tools/fetch-vendor-mac.sh` запускается отдельным шагом, но полный порядок шагов этого
  workflow я не читал.
