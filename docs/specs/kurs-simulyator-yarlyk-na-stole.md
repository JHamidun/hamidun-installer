## Что обещает человеку

После установки на рабочем столе появляется ярлык «Курс вайбкодинг (Claude Code)». Открыл — из папки курса запускается агент (`claude`, а если его нет — `codex`), пишешь ему слово «начать», и дальше он ведёт по миссиям сам. Курс целиком офлайновый: его содержимое лежит вшитым архивом внутри установщика (`vendor/course/vibecoding-course.zip`, 340 969 байт), интернета для прохождения не требуется. В архиве 133 файла: `CLAUDE.md` и `AGENTS.md` наставника, три навыка (`course-driver`, `course-check`, `course-role`), команда `.claude/commands/начать.md` и 11 папок в `tracks/` — девять ролевых (`analyst`, `designer`, `founder`, `hr`, `marketer`, `ops`, `product`, `project`, `sales`) плюс `_core` и `advanced`. Это ровно то, что обещает карточка компонента: «9 ролей + общий уровень 2» (`components.json:161`).

Второе обещание, за которое можно спросить отдельно: повторная установка не съедает твою работу. Прогресс (`.course/state.json`, `.course/identity.json`, `.claude/settings.local.json`) в архив действительно не входит — проверено листингом `vendor/course/vibecoding-course.zip`: этих имён в нём нет, есть только `.course/state.example.json`. С песочницей тоньше: запись `sandbox/README.md` в архиве **есть**, а оба распаковщика перезаписывают одноимённые файлы (`Expand-Archive -Force` — `course.ps1:86`, `/usr/bin/ditto -x -k` — `course.sh:79`), то есть при повторной установке именно этот файл затирается версией из архива; всё остальное, что ученик положил в `sandbox/`, остаётся. Комментарии в самих скриптах утверждают обратное («`sandbox/` … в архив не входят» — `course.ps1:65`, `course.ps1:71`, `course.sh:50`); это ошибка комментария, а не кода. От удаления защищено и то, и другое: ни `sandbox`, ни эти три файла не входят в перечень сносимого (`scripts/windows/course.ps1:72`, `scripts/macos/course.sh:55`) и перечислены в `preserve` (`src/uninstall-targets.js:129-134`).

## Как работает

Главный процесс подбирает скрипт по id компонента: `scripts/<windows|macos>/course.<ps1|sh>` (`src/main.js:569-573`). Компонент включён по умолчанию и требует `claude` (`components.json:163-166`), то есть Claude Code ставится раньше в топологическом порядке.

### Общая последовательность (обе платформы)

1. **Поиск архива.** `$env:HM_VENDOR\course\vibecoding-course.zip` (`course.ps1:31`) / `${HM_VENDOR}/course/vibecoding-course.zip` (`course.sh:7`). Архива нет — печатается «Курс-симулятор не вошёл в эту сборку… — пропускаю» и `exit 120` (`course.ps1:32-36`, `course.sh:12-16`). Код 120 — это `EXIT_SKIP` (`src/install-receipts.js:33`), при нём маркер установки не пишется (`shouldRecordInstall`, там же строки 36-38), поэтому фантомной кнопки «Удалить» не возникает. В dry-run на этом же месте выход 0.
2. **Целевая папка.** `HM_COURSE_TARGET`, иначе `%USERPROFILE%\HamidunCourse` (`course.ps1:39`) / `$HOME/HamidunCourse` (`course.sh:18`). На macOS есть отдельная защита: если в переменную прилетел Windows-путь (символы `%` или `\`), берётся дефолт (`course.sh:23-25`). Курс распаковывается в `<target>/vibecoding-course/` — верхняя папка лежит внутри самого zip (проверено списком архива: единственный элемент верхнего уровня — `vibecoding-course`).
3. **Dry-run.** При `HM_DRY_RUN` печатается набор строк «WOULD» (распаковка, глобальные навыки, маяк, ярлык) и `exit 0` — дисковых проверок в превью нет вовсе (`course.ps1:42-53`, `course.sh:28-38`).
4. **Целостность.** `Confirm-HmArtifact $zip` (`course.ps1:59`) / `verify_artifact "$ZIP"` (`course.sh:44`). Сверяется SHA-256 и, на Windows, ещё и размер против `vendor/checksums.json` (`scripts/windows/_verify.ps1:83-102`, `scripts/macos/_lib.sh:228-244`). Нет манифеста, нет записи для имени, не совпал хеш — `exit 1` до распаковки.
5. **Обновление поверх.** Если `<courseDir>/CLAUDE.md` уже есть, сносятся ровно четыре подпапки из архива: `tracks`, `.claude/skills`, `.claude/commands`, `.course/knowledge` (`course.ps1:72`, `course.sh:55`). Если снос не удался (папка занята / нет прав) — печатается объяснение и `exit 1`: домешивать новое к старому скрипт отказывается.
6. **Распаковка.** Windows: `Expand-Archive -Force` в try/catch, при исключении — `exit 1` (`course.ps1:85-90`). macOS: **сначала `/usr/bin/ditto -x -k`**, и только если он не справился — `/usr/bin/unzip -o -q`, обязательно со `</dev/null` (`course.sh:79-93`). Причина в комментарии `course.sh:67-78`: в архиве есть файл `.claude/commands/начать.md` (проверено — это единственное кириллическое имя в zip), Info-ZIP 6.0 на macOS не понимает его UTF-8-флаг, падает и **задаёт вопрос** «write error (disk full?). Continue?» — без stdin процесс висит вечно, а человек видит бесконечный спиннер. Если не смогли обе распаковки, macOS-ветка печатает свободное место (`df -k`), отдельно сообщает, что архив при этом целый, и даёт три шага (`course.sh:82-91`), затем `exit 1`.
7. **Проверка результата.** Нет `<courseDir>/CLAUDE.md` — «Курс распаковался неожиданно» и `exit 1` (`course.ps1:91-94`, `course.sh:94-97`). Успех печатает путь и строку `HM-RECEIPT path <courseDir>` (`course.ps1:96-97`, `course.sh:99-100`).
8. **Маяк завершения** — только если задан `HM_COURSE_BEACON_URL` **и** существует `<courseDir>/.course/config.yaml`. В yaml вписывается (или заменяется) блок `completion_beacon` с `enabled: true`, `url` и `secret`; значения экранируются по `\` и `"`. Windows делает это .NET-чтением/записью строго в UTF-8 без BOM (`course.ps1:107-135`, причина в комментарии 119-120: `Get-Content -Raw` в PS 5.1 читает UTF-8-без-BOM как ANSI и делает мохибейк из кириллицы). macOS правит файл через `/usr/bin/perl`, а не `python3` — на чистом Mac без Command Line Tools bare `python3` открывает GUI-диалог посреди установки (`course.sh:103-106`). Сам секрет не печатается никогда — только «с подписью» / «БЕЗ подписи».
9. **Глобальный наставник** — только при `HM_COURSE_GLOBAL='1'`. Каждая папка из `<courseDir>/.claude/skills` копируется в `~/.claude/skills`, предварительно снеся одноимённую; не удалось снести — сообщение и флаг неудачи, при котором финальное «установлены» не печатается (`course.ps1:138-161`, `course.sh:144-163`). Затем в `~/.claude/CLAUDE.md` идемпотентно вписывается блок между маркерами `# >>> vibecoding-course >>>` и `# <<< vibecoding-course <<<`; исходный файл бэкапится **один раз** в `CLAUDE.md.bak-course` (`course.ps1:178-180`, `course.sh:168-170`). На Windows чтение идёт строгим UTF-8 (`throwOnInvalidBytes`) с откатом на системную кодировку, чтобы не превратить чужую кириллицу в `U+FFFD` (`course.ps1:169-177`).
10. **Ярлык.**
    * **Windows** (`course.ps1:194-244`): рядом с курсом пишется `Запустить курс.cmd` — `chcp 65001`, `cd /d "%~dp0"`, затем `where claude` → `claude`, иначе `where codex` → `codex`, иначе три строки объяснения и `pause`. Файл пишется без BOM (cmd.exe спотыкается о BOM). Ярлык `.lnk` создаётся через COM `WScript.Shell`, `TargetPath` — сам `.cmd`, а не `cmd.exe /c "<путь>"` (у `/c` своё правило кавычек, и путь с пробелом «Запустить курс.cmd» разъезжается), `IconLocation` — `shell32.dll,13`. Весь блок в try/catch: не создался — «не критично».
    * **macOS** (`course.sh:188-205`): на рабочий стол пишется `<имя>.command` с `export PATH="$HOME/.local/bin:/opt/homebrew/bin:/usr/local/bin:$PATH"` (Terminal не сорсит профили и без этой строки `claude` не нашёлся бы), `cd` в папку курса и цепочкой `~/.local/bin/claude` → `claude` → `~/.local/bin/codex` → `codex`, иначе сообщение и `open .`. Затем `chmod +x`.
    Почему в обоих лаунчерах есть Codex: курс лежит и в `CLAUDE.md`, и в `AGENTS.md` (оба файла реально есть в архиве), то есть читается обоими агентами одинаково (`course.ps1:209-211`, `course.sh:199-201`).
11. **Предупреждение про claude** (только Windows, `course.ps1:246-255`): если `Get-Command claude` пуст и в `~/.local/bin` нет `claude.exe`/`claude.cmd`/`claude`, печатается «ВНИМАНИЕ: команда claude не найдена — ярлык курса заработает после установки Claude Code».
12. **Финал.** «OK: курс-симулятор установлен. Открой ярлык «…» (или папку …) и напиши агенту «начать»» и `exit 0`. Слово «начать» выбрано не случайно: ровно так называется команда `.claude/commands/начать.md` в архиве (`course.ps1:257-261`).

### Что делает приложение вокруг скрипта

* **Маяк.** `HM_COURSE_BEACON_URL` и `HM_COURSE_BEACON_SECRET` кладёт в childEnv только main, читая вшитый `config.json` (`src/main.js:1149-1151`). Через renderer такие ключи не пускают: allowlist `RENDERER_ENV_ALLOW` перечисляет ключи явным списком, и `HM_COURSE_TARGET` там нет намеренно (`src/install-env.js:12-28`).
* **Детект «курс уже стоит».** Ищутся `<target>/vibecoding-course/CLAUDE.md` либо `.claude/skills/course-driver/SKILL.md` (`src/main.js:2655-2664`).
* **Кнопка «Открыть курс-симулятор»** на финальном экране (`src/renderer/app.js:2258-2270` → `src/preload.js:36` → `ipcMain.handle('launch-course')`, `src/main.js:2003-2029`). Курс сам не открывается: блок показывается, только если курс встал в этой сессии или найден на машине. Обработчик резолвит путь тем же `resolveCourseTarget`, что и деинсталлятор, и различает три причины отказа — `no-dir`, `no-mentor`, `no-editor`, — под каждую renderer печатает свой текст (`src/renderer/app.js:2414-2426`). Успех с оговоркой (`how: 'explorer'|'finder'`) означает «папку открыл проводник, наставник подхватится только из редактора».
* **Удаление.** План целей строится в `src/uninstall-targets.js:107-137`: контент архива, ярлык на рабочем столе (`.lnk` на Windows, `.command` на macOS), затем родительские каталоги — но только если пусты. Прогресс ученика в `preserve`.
* **Сборка.** `tools/fetch-vendor.ps1:573-584` и `tools/fetch-vendor-mac.sh:589-598` валят сборку, если архива курса нет; `tools/fetch-vendor.ps1:516-546` вписывает его sha256 и размер в `vendor/checksums.json`.

## Инварианты

1. **Архив не распаковывается без совпадения SHA-256 (и, на Windows, размера) с `vendor/checksums.json`.** Держится: `course.ps1:59` → `scripts/windows/_verify.ps1:83-102`; `course.sh:44` → `scripts/macos/_lib.sh:231-244`. Любое из «нет манифеста / нет записи по имени / хеш не сошёлся» → `exit 1` до единой записи на диск.
2. **Отсутствие архива — это пропуск (`exit 120`), а не падение.** `course.ps1:35`, `course.sh:15`. Код 120 распознаётся как `EXIT_SKIP` (`src/install-receipts.js:33-34`), и маркер установки при нём не пишется (`src/install-receipts.js:36-38`).
3. **На macOS первым всегда пробуется `ditto`, а запасной `unzip` всегда получает stdin из `/dev/null`.** `course.sh:79-81`. Проверяется тестом «macOS: курс распаковывается ditto — unzip не понимает кириллицу в именах», в том числе порядком вызовов и наличием кириллического имени в реальном архиве.
4. **Установка объявляется успешной только при наличии `<courseDir>/CLAUDE.md` после распаковки.** `course.ps1:91-94`, `course.sh:94-97`.
5. **При обновлении сносятся ровно четыре подпапки архива и ни одна другая; неудача сноса останавливает установку.** `course.ps1:72-83`, `course.sh:55-65`.
6. **Прогресс ученика не удаляется ни при обновлении, ни при деинсталляции.** `sandbox/`, `.course/state.json`, `.course/identity.json`, `.claude/settings.local.json` не входят в перечень сносимого (пункт 5) и перечислены в `preserve` (`src/uninstall-targets.js:129-134`). Проверяется тестом «PRESERVE: деинсталляция курса — sandbox/state.json/identity.json/settings.local.json ЦЕЛЫ, контент курса удалён, ~/.claude цел».
7. **Значение секрета маяка не попадает в вывод установщика никогда** — печатается только «с подписью» / «БЕЗ подписи». `course.ps1:46-49` и `128-132`, `course.sh:32-35` и `131-136`.
8. **Адрес и секрет маяка приходят только из вшитого `config.json` через main; renderer их поставить не может.** `src/main.js:1149-1151` + явный список ключей `src/install-env.js:20-28`. Проверяется тестом «#4 allowlist: эмитимые HM_* сохраняются; неэмитимый HM_COURSE_TARGET отброшен».
9. **Ярлык — best-effort: его несоздание не роняет установку.** Windows-блок целиком в try/catch (`course.ps1:196-244`), macOS завершает цепочку `|| echo "Ярлык не создался (не критично)."` (`course.sh:205`).
10. **Имя ярлыка, которое пишет установщик, и имя, которое ищет деинсталлятор, совпадают.** Оба дефолта — литерал `Курс вайбкодинг (Claude Code)`: `course.ps1:195`, `course.sh:189`, а со стороны удаления `config.json:42` → `src/uninstall-targets.js:119`.
11. **План удаления курса не содержит ни одной цели внутри пользовательского `~/.claude`.** `src/uninstall-targets.js:108-128` строит пути только от `resolveCourseTarget` и рабочего стола; проверяется тестом «targets: course (win32) — контент курса из известных мест; ярлык из вшитого config; НИ одной цели в ~/.claude».
12. **Родительские каталоги удаляются только пустыми.** Тип цели `emptydir` для `.claude`, `.course`, `courseDir` и самого `target` (`src/uninstall-targets.js:125-128`).
13. **Кнопка «Открыть курс-симулятор» не создаёт пустую папку курса.** `launchVsCodeOn(dir, { create: false })` и три раздельные причины отказа (`src/main.js:2023-2028`).

## Что ломается, если инвариант нарушить

1. Подменённый архив курса — это исполняемый по смыслу контент: Claude Code читает `.claude/skills/*` как инструкции. Без SHA-гейта злоумышленник, дописавший zip в `vendor`, получает исполнение своих инструкций в агенте ученика.
2. Если пропуск вернуть кодом 0, main запишет маркер установки, на финальном экране появится кнопка «Удалить курс» — и деинсталляция пойдёт сносить `HamidunCourse`, которого установщик никогда не создавал, вместе с чужим содержимым, если человек держал там свои файлы. Если вернуть 1 — сборка без курса (lite) будет краснеть на каждой машине.
3. Возврат к `unzip` первым на macOS — это ровно тот живой случай, ради которого написан комментарий: установка зависает на неопределённо долгое время (в комментарии — 15 минут), человек видит спиннер и решает, что установщик сломан. Без `</dev/null` то же зависание возвращается и на запасном пути.
4. Без проверки `CLAUDE.md` человек получает «OK: курс установлен», нажимает ярлык, пишет «начать» — и разговаривает с ванильным агентом без наставника, не понимая, почему курс «не работает».
5. Без сноса старых папок наставник продолжит видеть уроки предыдущей версии вперемешку с новыми; при снятом гейте на неудачу сноса — то же самое, но молча.
6. Потеря `sandbox/` — это потеря проекта, который ученик писал своими руками; потеря `state.json` — сброс прогресса на ноль; потеря `settings.local.json` — заново выданные разрешения Claude Code на каждое действие.
7. Секрет в выводе установщика: журнал установки человек присылает в поддержку целиком (`course.ps1:46-47`), то есть общий секрет подписи маяка уходит третьим лицам вместе с логом.
8. Renderer работает под medium integrity. Пропусти он `HM_COURSE_BEACON_URL` — скомпрометированный renderer направит «прошёл курс» на свой адрес; пропусти `HM_COURSE_TARGET` — задаст путь раскладки для скрипта, который на Windows может исполняться с повышенными правами.
9. Падение из-за ярлыка означает: курс уже распакован и работает, но компонент помечен как неустановленный, а человек отправлен «повторять неустановленное» по кругу.
10. Разъехавшиеся имена: установщик кладёт `Курс вайбкодинг (Claude Code).lnk`, деинсталлятор ищет другое имя — ярлык остаётся на рабочем столе после удаления курса и ведёт в пустоту.
11. Цель внутри `~/.claude` — это удаление личных навыков, `settings.json` и `.credentials.master.env` пользователя при снятии курса.
12. Рекурсивное удаление родителя вместо `emptydir` снесёт `sandbox/` и прогресс, сохранённые пунктом 6, — защита прогресса держится именно на том, что непустой каталог не трогают.
13. Создание пустой папки по кнопке даст «курс на месте» там, где его нет: детект (`src/main.js:2661`) и следующая проверка `no-mentor` начнут расходиться с реальностью.

## Границы

* Курс **не** ходит в сеть ни за контентом, ни за обновлениями: единственный источник — вшитый zip. Компонента «докачать курс» не существует; в lite-издании архив всё равно обязан лежать рядом (`tools/build-lite.js:10`, тест «lite (macOS): неполный сиблинг (нет checksums.json / нет uv / нет курса) → плашка горит»).
* Курс **не** ставит Claude Code. На Windows он лишь предупреждает, что команды `claude` не видно (`course.ps1:246-255`); на macOS такого предупреждения нет вовсе — там несостыковка всплывает уже при нажатии на ярлык.
* Ярлык **не** открывает курс в редакторе: он запускает агента в консоли из папки курса. Открытие папки в VS Code/Cursor — это отдельная кнопка финального экрана (`src/main.js:2003-2029`), и она не создаёт папку, если её нет.
* Маяк завершения в текущих сборках уходит **без подписи**: `config.json:41` содержит пустой `beaconSecret`, и `_comment` в `config.json:38` прямо говорит, что заполнять его нечему. Академия помечает такой сигнал как недоказанный.
* Блок маяка не пишется, если в архиве не оказалось `.course/config.yaml`, и об этом **ничего не печатается** — ветка `if (Test-Path $cfgYaml)` / `if [ -f "$CFG" ]` не имеет else (`course.ps1:109`, `course.sh:109`). (В текущем архиве файл есть — проверено списком zip.)
* Глобальная установка наставника в `~/.claude` — опция, которую в текущем коде **никто не включает**: `HM_COURSE_GLOBAL` не задаётся нигде в `src/`, а ключ `course.globalInstall` из `config.json:40` не читается ни одним файлом репозитория (проверено поиском по `*.js`, `*.json`, `*.ps1`, `*.sh` вне `release/` и `node_modules/`).
* Деинсталляция курса намеренно не трогает `~/.claude` (инвариант 11). Следствие-уступка: если наставник когда-либо был поставлен глобально, его навыки и блок в `~/.claude/CLAUDE.md` после удаления курса остаются. Бэкап `CLAUDE.md.bak-course` тоже не убирается.
* Скрипты умеют читать `HM_COURSE_TARGET` и `HM_COURSE_SHORTCUT`, но приложение их не передаёт — фактически всегда работают дефолты (см. риски).

## Риски и открытые вопросы

1. **`vendor/checksums.json` в рабочем дереве не совпадает с лежащим рядом архивом.** Манифест: `sha256 5de67b9ae4b3ec5382595fb59aa5daae13c68b9893e270acb6f8a2880864a2e1`, `bytes 340706`. Фактический файл: `a3ccb5a353fd6d6efccf794116467f7a608465e8de1ddd70fb4af35d461961df`, `340969` байт (посчитано). Сборка, в которую попадёт текущий `checksums.json` без повторного прогона `tools/fetch-vendor.ps1:516-546`, получит на `Confirm-HmArtifact` несовпадение → `exit 1`, и курс **уронит установку кодом 1**, а не пропустится кодом 120. Косвенное подтверждение рассинхрона: `components.json:169-170` уже несёт актуальные `340969`, то есть размеры синхронизировали, а манифест — нет.
2. **`scripts/windows/course.ps1` не покрыт ни одним поведенческим тестом.** Единственное упоминание файла в `test/run-tests.js` — regex на строки `HM-RECEIPT` внутри теста «install-скрипты: легаси HM-RECEIPT эмиссии (фильтруются из UI-лога; целей удаления НЕ задают)» (строки 4689-4690). Ветки Windows-скрипта — обновление поверх, маяк, глобальные навыки, генерация `.cmd` и `.lnk`, предупреждение про `claude` — не проверяются ничем. Тест про `ditto` покрывает только macOS. Что это значит практически: правка `course.ps1` может сломать создание ярлыка или запись `completion_beacon`, и прогон тестов останется зелёным.
3. **`HM_COURSE_TARGET`, `HM_COURSE_SHORTCUT`, `HM_COURSE_GLOBAL` не выставляются нигде в `src/`** (поиск по репозиторию вне `release/`: переменные встречаются только в самих скриптах, в комментарии `src/install-env.js:13`, в детекте `src/main.js:2657` и в тестах). При этом `config.json` содержит `targetDirDefault` и `shortcutName`, которые **читает только сторона удаления и кнопки запуска** (`src/main.js:2005`, `3102-3103`). Сегодня пары сходятся лишь потому, что значения в `config.json` совпадают с дефолтами внутри скриптов. Поменяй `targetDirDefault` в `config.json` — установщик продолжит ставить в `%USERPROFILE%\HamidunCourse`, а «Открыть курс» и деинсталлятор пойдут по новому пути и не найдут ничего. Ни один тест эту связку не стережёт.
4. **Неудача глобальной установки навыков не влияет на код возврата.** Флаг `$skFail` / `skfail` гасит только финальное сообщение «установлены», скрипт всё равно доходит до `exit 0` (`course.ps1:146-160`, `course.sh:149-162`). Компонент будет отмечен успешным при частично не поставленном наставнике.
5. **Запись `~/.claude/CLAUDE.md` на Windows не обёрнута в try/catch** (`course.ps1:188-191`), тогда как macOS-вариант имеет явную ветку неудачи с сообщением (`course.sh:183-185`). Что именно произойдёт на Windows при исключении `[System.IO.File]::WriteAllText` (аварийная остановка скрипта и с каким кодом) — **не подтверждено кодом**: `$ErrorActionPreference = 'Continue'` стоит в строке 2, но поведение .NET-исключения при этом здесь не проверялось. Ветка достижима только при `HM_COURSE_GLOBAL='1'`, который сейчас никем не задаётся.
6. **Расхождение размеров компонента.** `components.json:168-171` объявляет `sizeBytes` 340 969 для обеих платформ; это точный размер архива без учёта распакованного содержимого — то есть цифра на экране выбора занижена относительно того, сколько курс займёт на диске после распаковки. Механизма, который считал бы распакованный объём, в прочитанном коде нет.
7. **`beaconSecret` пуст и заполняться ему нечем** — сказано прямо в `config.json:38`. Пока это так, штамп «прошёл курс» на стороне академии остаётся недоказанным сигналом; смысл поля `secret` в `.course/config.yaml` при этом сохраняется (записывается пустая строка), то есть отличить «секрета не было» от «секрет пустой» по файлу нельзя.
