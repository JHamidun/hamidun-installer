# ADR-008. Спеки проверяются машиной, иначе они со временем врут

**Статус:** принято · **Дата:** 2026-08-29 · **Область:** документация

## Контекст

Продукт дожил до релиза без единого документа об ожидаемом поведении: в реестре
фич колонка «Спека» была пустой у всех 61. Естественное решение — написать 61
документ. Прежде чем это делать, стоило посмотреть, как в этом проекте живут
документы, которые уже есть.

Посмотрели. Из 48 находок аудита **12 — противоречия документов коду**, и половина
высоких по тяжести была именно там:

* пять документов давали **три взаимоисключающие** инструкции по запуску на macOS;
* README описывал состав лёгкого издания **наоборот** (обещал вшитый конфиг —
  единственное, что как раз докачивается);
* рецепт офлайн-сборки mac из README давал нерабочий образ: пропущен последний шаг;
* документы утверждали «подписи нет», хотя Developer ID и нотаризация работали;
* модель угроз строила вводную на примере (`uv`), который ей противоречил, и
  застыла на состоянии четырёхнедельной давности, оставаясь единственным
  документом со штампом даты.

Ни один из них не помечен устаревшим. Все читались складно. Именно поэтому они
опасны: сложенный текст выглядит как знание.

Вывод, который отсюда следует: **шестьдесят одна вольная спека увеличила бы эту
поверхность, а не уменьшила.** Документ без способа проверки — это не актив, а
обязательство, которое никто не собирается обслуживать.

## Решение

У спеки фиксированная шапка, а `tools/check-specs.js` — обязательный гейт, который
держит её живой:

1. у каждой фичи из `docs/specs/_features.json` есть файл спеки;
2. нет спек-сирот (фичу убрали, документ остался);
3. `spec-id` внутри файла совпадает с именем файла;
4. каждый путь из «Код:» существует;
5. каждый заголовок теста из «Тесты:» **дословно** присутствует в `test/run-tests.js`;
6. фича, у которой инвентарь видел тест, обязана его процитировать;
7. обязательные разделы на месте.

Пункт 5 — главный. Тест переименовали, спека ссылается на старое имя — это ровно
начало расхождения, и ловится оно за секунду вместо шести недель.

Сам список фич не пересказывается руками: `tools/extract-features.js` разбирает
`docs/INVENTORY.md` в машинный `docs/specs/_features.json`. Пересчёт markdown-таблицы «на глаз» —
тот же класс ошибки; при написании этого скрипта он и случился дважды
(экранированная черта в ячейке дала 46 вместо 47, склейка соседних путей — семь
несуществующих файлов).

## Чем платим

* **Спека дороже в написании.** Нельзя сослаться на «примерно тот тест»; надо найти
  дословный заголовок. Это и есть цена проверяемости.
* **Переименование теста ломает гейт.** Намеренно: переименовал — обнови спеку.
* **Гейт не проверяет СМЫСЛ.** Он ловит протухшие ссылки, но не то, что абзац
  описывает поведение неверно. Против этого работает второй механизм — спеку
  пишет один агент, а независимый пытается её опровергнуть по коду.

## Номера строк гниют, и гейт этого не ловит

Известное ограничение, названное сразу, чтобы им не пользовались как гарантией.

Проверяется **путь**, а не диапазон строк: `src/main.js:1940-1996` считается
верным, пока существует `src/main.js`. Между тем любая правка выше по файлу
сдвигает все ссылки ниже — и они молча становятся неточными.

Это не гипотеза. При первом же прогоне независимая проверка нашла у одной спеки
систематический сдвиг **ровно на −8 строк**, и часть таких сдвигов навела моя же
правка `src/main.js` (десять строк комментария), сделанная уже после написания
спек. Из 3281 проверенного утверждения опровергнуто 313 — около десяти процентов,
и номера строк там доминируют.

**Отсюда правило чтения:** авторитетны путь и ИМЯ (функции, флага, ключа
конфига). Диапазон строк — удобство, чтобы быстро найти место, и не более. Имя
переживает вставку абзаца выше, номер строки — нет.

**Почему всё-таки оставлены.** Без них спека на файл в две тысячи строк отправляет
читателя искать вручную, а это ровно та цена, из-за которой документы перестают
читать. Гнилой указатель хуже точного, но лучше отсутствующего — при условии, что
про его гнилость сказано прямо. Сказано здесь.

Усилить это можно проверкой имён: каждый идентификатор, названный в спеке, должен
встречаться в процитированном файле. Сегодня такой проверки нет — и заявлять, что
она есть, было бы ровно тем сортом неправды, против которого написан весь документ.

## Честное «НЕТ» обязано проходить

Первая редакция гейта разворачивала спеку, которая честно писала «Тесты: НЕТ»:
регулярка `/^\s*НЕТ\b/` не срабатывала, потому что в JavaScript `\b` строится на
латинском `\w`, и кириллическая «Т» для него не буква.

Дефект мелкий, последствие — нет: гейт **наказывал за честность** и подталкивал
выдумать заголовок теста, то есть работал против собственной цели. Найдено
подлогом, закреплено случаем «честное НЕТ проходит».
