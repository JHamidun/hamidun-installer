# Hamidun Bridge Bot — спецификация воронки (хэндофф для разработки бота)

> **ЦЕЛЕВОЙ БОТ: существующий `@vibecodeguidebot`** (уже развёрнут на сервере). Это НЕ новый бот —
> воронку ниже встраиваем в него. Установщик уже шлёт юзера сюда (`config.json` → `links.bot`).
> Бот опознаёт юзера по `tg_id` (он уже /start'нул бота через email-deeplink на лендинге), поэтому
> персональный токен в ссылке финального экрана НЕ нужен. Что установщик шлёт боту на самом деле
> (актуально на 09.10.2026) — в разделе «Что установщик шлёт боту» ниже.
>
> **Статус на 09.10.2026.** Компонент «AI-мост» в установщике СКРЫТ, пока в `config.json` пуст
> `bridge.enrollEndpoint` (сейчас пуст; `components.json` → `hideWhileUnconfigured`): человек его не видит
> и поставить не может. Поэтому ветка «мост → trial → тарифы → оплата» ниже — это ЗАДЕЛ на будущее,
> а не работающая воронка: бот не должен предлагать мост как готовый, пока владелец не вписал адрес
> enroll-сервиса и не включил ветку.

Бот = вход в продукт Hamidun: выдаёт ссылку на установщик, ловит юзера после установки (deeplink),
даёт инструкцию «как пользоваться» и продаёт «AI-мост» (стабильный зарубежный IP для Claude/OpenAI)
тем, у кого блокировки. **Базовый продукт (установщик + конфиг + Claude Code) — бесплатный лид-магнит.
Мост — монетизация.** Сделано по разбору конкурента «Реле AI» — с исправлением его ошибок (см. в конце).

## Полный флоу

```
Лендинг (email-капча)
  → бот+email получают ссылку на установщик (deeplink t.me/Bot?start=dl_<token>)
  → юзер качает установщик → ставит (Claude Code + VS Code + конфиг; Cursor, Claude Desktop и др. — по желанию;
    «AI-мост» скрыт, пока не настроен enroll-сервис)
  → финальный экран установщика открывает t.me/Bot?start=installed_<os> (или failed_<id>_<os>, если что-то не встало)
  → бот: пост-инсталл экран
       ├─ «Просто пользоваться»  → инструкция (3 шага) + видео
       └─ «Есть блокировки → мост» → ценность → trial 14д → тарифы → оплата
             → бот выдаёт bridge_token → приложение само тянет SSH-доступ по токену
             → тумблер «AI-мост» в приложении → Включить
```

## Deep-link токены (склейка лендинг ↔ бот ↔ установщик)

- `dl_<token>` — выдаётся при email-капче на лендинге. `/start dl_<token>` → бот связывает email↔tg_id,
  отдаёт ссылку на установщик (и дублирует на email).
- Payload финального экрана установщика (`src/renderer/finish-link.js`; Telegram принимает в `start`
  только `A-Za-z0-9_-`, до 64 символов). Токена `inst_<token>` в установщике НЕТ — бот знает человека по tg_id:
  - `installed_win` / `installed_mac` — обязательное встало и проверка после установки зелёная (необязательное
    и «частично» могли не встать — на payload это не влияет; база `config.json` → `finish.botStartPayload` = `installed`
    + суффикс платформы);
  - `failed_<id>_win` / `failed_<id>_mac` — не встал обязательный компонент ИЛИ красная проверка после
    установки; `<id>` — первый из итога прогона (напр. `failed_claude_win`, `failed_vscode_mac`). Итог берётся из
    общего расчёта прогона, а не только из упавших шагов: проверка verify всегда выходит с кодом 0.
  - голая ссылка без `?start=` — плашка «Не едет?» во время установки, пока ничего не упало; если уже упало,
    плашка несёт тот же `failed_<id>_<os>`.
- `bridge_token` — выдаётся после оплаты/trial. Приложение (компонент «AI-мост») дёргает enroll-endpoint
  с этим токеном и САМО получает SSH-доступ. Юзер ничего руками не вводит. **В этом релизе не используется**
  (компонент скрыт, пока `bridge.enrollEndpoint` пуст).

## Состояния пользователя (FSM — ПРОЩАЮЩАЯ)

`new → email_captured → installer_sent → installed → (free | trial | paid)`.
**Любой неожиданный ввод → показать текущее меню. НЕ зацикливать** (главная ошибка ReleAI — см. ниже).

## Команды и экраны

- `/start [payload]` — роутинг по payload (`dl_<token>` / `installed_<os>` / `failed_<id>_<os>` / пусто).
  Пустой → приветствие + меню.
- **Экран после email (`dl_`):** «Спасибо! Вот установщик: [ссылка]. После установки я сам тебя встречу.»
- **Пост-инсталл (`installed_<os>`):** «Установка готова! 🎉 Открой VS Code → панель Claude Code (значок ✳) →
  войди подпиской.» (Cursor — только если человек выбрал его.) Кнопки:
  - «✅ Просто пользоваться» → 3-шаговая инструкция + ссылка на короткое видео;
  - «🔓 У меня блокировки» → пока моста нет — совет про VPN на весь компьютер в режиме TUN (раздел «Если ты в
    России» в памятке «Что дальше»), а не экран моста. Экран моста — только когда ветка включена владельцем.
- **Не встало (`failed_<id>_<os>`):** бот спрашивает, что именно случилось, и просит нажать в установщике
  «📋 Скопировать отчёт для поддержки» и ВСТАВИТЬ текст в чат (одно сообщение, до ~3500 знаков: шаг, причина, система,
  uid, последние строки журнала; пути профиля и ключи вычищены). Файл журнала просить НЕ нужно: вложения до бота
  доходят не всегда.
- **Экран моста** (заделом, см. «Статус»): объяснить ценность (стабильный чистый IP только для Claude — не VPN, не тормозит,
  работает поверх твоего VPN, аккаунт не банят за прыжки IP) → кнопка «Включить trial 14 дн бесплатно».
- `/status` — план, остаток trial, кол-во устройств, ключ.
- `/pay` — тарифы + оплата (TG Stars / ЮKassa). После оплаты/trial → выдать `bridge_token` + инструкция
  «Открой приложение → переключатель «AI-мост» → Включить».
- `/bridge` — статус моста / вкл-выкл / сменить сервер.
- `/support` — @поддержка.
- Атрибуцию («откуда узнал») спрашивать ОПЦИОНАЛЬНО и ПОСЛЕ выдачи ценности, кнопкой «пропустить». НЕ гейтом.
- **Mac-примечание (обязательно в экран выдачи ссылки для Mac).** Приложение подписано Apple
  Developer ID и нотаризовано — диалога «приложение повреждено» и команд `xattr` в норме нет,
  извиняться за подпись не нужно. Но одно требование осталось, и бот обязан его проговорить
  ДО скачивания, одной фразой:

  > «Открой dmg и запусти "Hamidun Setup" **двойным кликом прямо в окне образа**.
  > **Не перетаскивай в "Программы"** — установщику нужны файлы, которые лежат в образе
  > рядом с ним; из "Программ" он их не найдёт.»

  Это НЕ про Gatekeeper и не обходной путь, а архитектура mac-сборки: офлайн-vendor едет
  сиблингом рядом с `.app` (нотаризация не пускает его внутрь бандла). Перетащил в
  «Программы» — приложение блокирует установку стоп-экраном.

  **Старую формулировку «перетащи в Программы, затем `xattr -cr "/Applications/Hamidun Setup.app"`»
  бот давать НЕ должен ни при каких условиях** — она приводит пользователя ровно к тому
  стоп-экрану, с которым он пришёл, и разговор идёт по кругу.

  **Системное требование — тоже ДО скачивания, одной фразой:** «Нужна macOS 13 Ventura или
  новее (лучше 13.5+).» Установщик собран на Electron 44, ему нужна macOS 13; 13.5 — нижняя
  граница Node.js 24 из комплекта (на 13.0–13.4 установщик откроется, но Node там официально
  не поддерживается — советовать обновиться).

  **«Установщик не открывается на старом Маке»** (macOS пишет, что приложению нужна более новая
  версия системы; в dmg он есть, а запуститься не даёт) — это НЕ карантин и не поломка: система
  отказывает ещё до первого экрана установщика, поэтому ни стоп-экрана, ни кнопки «Исправить
  автоматически» там нет. `xattr` и «перетащи в Программы» здесь не лечат — не предлагать.
  Ответ: попросить открыть меню Apple → «Об этом Mac» и назвать версию. Меньше 13 → обновить
  (меню Apple → «Системные настройки» → «Обновление ПО»). Обновление до macOS 13 не предлагается
  → Mac слишком старый (в основном Маки 2013–2017 годов выпуска; точный список — у Apple,
  «macOS Ventura: совместимые компьютеры»): поставить на другом компьютере (подойдёт и
  Windows-версия).

  Если человек уже перетащил и упёрся в стоп-экран: в самом установщике есть кнопка
  «Исправить автоматически» — она отмонтирует образ, снимет карантин с `.dmg` и откроет его
  заново. Просить сначала нажать её; ручная однострочная команда лежит внутри dmg в файле
  «ПРОЧТИ ЕСЛИ ПИШЕТ ПОВРЕЖДЕНО.txt» и в том же стоп-экране. Канон формулировок —
  `MAC-BUILD.md`, раздел «Как запускать готовый dmg».

- **Windows-примечание:** exe подписан кодовым сертификатом Certum с 05.10.2026 (издатель **Zhemal Khamidun**;
  подробности — `WIN-SIGNING.md`). В окне UAC теперь «Проверенный издатель», а не «неизвестный». Но репутация у нового
  сертификата копится по мере скачиваний, поэтому у части людей синий экран SmartScreen «Windows защитила ваш компьютер»
  ещё появляется — уже с именем издателя. Бот объясняет: «Подробнее → Выполнить в любом случае»; говорить, что файл
  «не подписан», нельзя — это неправда. Сборки до 05.10 подписи не имеют. Платформы не путать: на macOS
  подпись и нотаризация есть изначально.

## Что установщик шлёт боту (актуально на 09.10.2026)

Отправляет главный процесс установщика (`send-telemetry`), POST JSON на `config.json` → `telemetry.url`;
пустой адрес = выключено. Человек может снять галочку «Отправлять отчёт об установке» на экране выбора — тогда
событий нет вовсе. Тексты ошибок чистятся от путей профиля, имени пользователя, e-mail и IP.

```
{ "event": "install_started" | "installed" | "open_editor",
  "platform": "win" | "mac",  "edition": "lite" | "offline",
  "mode": "install" | "repair",
  "uid": "<tg_id из имени скачанного файла Hamidun-Setup-…--u<uid>.exe>" | null,
  "ok": true|false,
  "failed":  ["<id>", …],     // обязательные компоненты, которые не встали, и компонент, названный красной проверкой
  "skipped": ["<id>", …],     // осознанные пропуски и необязательное, что не встало — НЕ провал
  "selected": ["<id>", …],    // только у install_started
  "errors": [{ "id": "<id>", "stage": "net|integrity|env|fail|partial|verify|aborted", "error": "<текст до 300 знаков>" }],
  "duration_sec": 0 }
```

- `ok=false` ВСЕГДА идёт с названным компонентом в `failed` (красная проверка называет свой компонент).
- `stage`: `net` — оборвалась докачка; `integrity` — файл не совпал с эталоном; `env` — не подготовилась защищённая папка
  загрузки; `fail` — шаг упал; `partial` — компонент работает, но без необязательной части (код 121; на `ok` не влияет);
  `verify` — красная проверка после установки; `aborted` — окно закрыли посреди установки (шлёт main).
- `mode=repair` — кнопка «Проверить и починить»: прогоняется ТОЛЬКО служебный шаг `verify`, ничего не ставится
  (`selected=["verify"]`). Для бота это не установка: не поздравлять «Установка готова» и не считать воронку.
- Если окно закрыли посреди установки, главный процесс сам шлёт `installed` с `ok=false` и `errors[0].stage="aborted"`
  (шаг, на котором оборвали, и сколько минут прошло); при согласии на отчёт это единственный след такой попытки.

## Bridge enroll-контракт (бэкенд моста)

Реализация — `installer/server/enroll-ssh-server.js` (выдаёт SSH-доступ):

```
POST https://bridge.hamidun.../enroll
  body: { "bridgeToken": "...", "client": "hostname" }
  200 -> { "sshHost": "1.2.3.4", "sshPort": 22, "sshUser": "rele",
           "sshKey": "<private key>", "pacDomains": ["claude.ai","anthropic.com","openai.com","chatgpt.com"] }
```

Приложение поднимает SSH `-D` (paramiko, локальный SOCKS5), пишет PAC с `pacDomains` в системный прокси,
для Claude Code CLI ставит `HTTPS_PROXY`. 1 платящий = 1 выделенный VPS (Стандарт) либо общий пул (Лайт).
Инвайт/токен-авторизация обязательна (иначе любой наплодит пиров). Rate-limit + fail-closed (см. enroll-ssh-server.js).

## Анти-паттерны (исправляем ошибки ReleAI — проверено вживую)

- ❌ **НЕ гейтить вход атрибуцией.** У ReleAI `/start` сразу спрашивает «откуда узнал?» inline-кнопкой,
  и пока не нажмёшь — `/key`, `/status`, `/pay` ВСЕ зацикливаются назад. Новый юзер застревает → конверсия 0.
- ❌ **FSM не должна зацикливаться** на любом «неожиданном» вводе — показывай меню, не кидай в начало.
- ❌ **Единые факты лендинг↔бот↔приложение.** У ReleAI лендинг пишет «оплата в Telegram», бот — ЮKassa. Доверие падает.
- ❌ **Не заставляй вводить SSH/ключ вручную.** У ReleAI: скачай exe → введи ключ → введи SSH к VPS. Для новичка стена.
  У нас: deeplink-токен → приложение само всё подтягивает. Один клик.
- ✅ Партнёрку/промокоды — продуктизировать (у ReleAI 50% спрятано только в личку).
- ✅ Mac — есть (через GitHub Actions), не извиняться за отсутствие DMG.

## Пример хендлера /start (псевдокод, разбор payload)

```python
async def on_start(msg):
    user = upsert_user(msg.from_user)            # создаём/находим по tg_id
    payload = parse_start_payload(msg)            # "dl_<t>" | "installed_<os>" | "failed_<id>_<os>" | ""
    if payload.startswith("dl_"):
        tok = consume_token(payload[3:], type="dl")   # связываем email<->tg_id
        user.state = "installer_sent"
        return send(user, "Спасибо! Вот установщик: " + installer_url(user),
                    also_email=tok.email)             # дублируем ссылку на email
    if payload.startswith("installed_"):
        user.state = "installed"
        return send_post_install_menu(user)           # «Просто пользоваться / Есть блокировки»
    if payload.startswith("failed_"):
        comp = payload.split("_")[1]                  # id первого не вставшего компонента
        return send_failed_menu(user, comp)           # просим «Скопировать отчёт» и вставить текст в чат
    # обычный /start
    return send_welcome_menu(user)                    # ценность + кнопка «Получить установщик»

# Включение моста после оплаты/trial:
async def grant_bridge(user, plan):
    vps = provision_or_pick_vps(user, plan)           # Standard: выделенный; Lite: пул
    bt = issue_bridge_token(user, vps)                # сохраняем в tokens(type=bridge)
    register_token_on_enroll_server(bt, vps)          # POST /admin/token (см. enroll-ssh-server.js)
    return send(user, "Мост готов 🎉 Открой приложение → значок в трее → Включить.\n"
                      "Токен подтянется автоматически.")  # либо отдать bridge_token для вставки
```

**Связь с установленным приложением:** приложение (агент `agent/bridge_agent.py`) дёргает
`bridge.enrollEndpoint` с `bridgeToken` и САМО получает SSH-доступ. Бот лишь выдаёт токен и
регистрирует его на enroll-сервере. Юзер ничего руками не вводит.
