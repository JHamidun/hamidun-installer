## 1. Молчаливые отказы (5)

Общий признак: механизм не работает, а ни лог, ни экран, ни зелёный CI об этом не говорят.

### 1.1. `src/uid-fallback.js` не существует, но `uid-telemetry.js` его вызывает — высокая

Файла нет ни на диске (`test -f src/uid-fallback.js` → ABSENT), ни в git (`git ls-files src/` его не показывает), ни в истории (`git log -- src/uid-fallback.js` пуст), при этом он не в `.gitignore`. Требование лежит в `src/uid-telemetry.js:97`:

```js
const fromDownloads = require('./uid-fallback').findDownloadedUid({ platform, env });
```

Строка внутри функции и обёрнута в `try/catch` двумя строками ниже (`} catch (e) { /* uid необязателен */ }`), поэтому `MODULE_NOT_FOUND` проглатывается. Проверено запуском: `resolveUid({platform:'win32',argv:['x'],env:{}})` возвращает `""`. Тестов на этот путь ноль — `grep -c "uid-fallback" test/run-tests.js` → 0, и весь набор при этом зелёный (423/0/2).

**Что увидит человек:** ничего. Установка пройдёт нормально. Но метка, по которой бот академии узнаёт, кому пришла помощь, не доедет — а именно этот файл и был написан против замера 26.07–20.08, где доставка метки провалилась до 27% на Windows и 5% на macOS. То есть починка от провала сама не работает и выглядит как работающая.

### 1.2. `assert:clean` не подключён к mac-путям и не проверяет mac-имена — высокая

`package.json:20`: `"dist:mac": "npm run fetch:config && npm run preflight -- --platform darwin && electron-builder --mac"` — гейта нет. `.github/workflows/build-mac.yml` его тоже не вызывает. Всего вызовов три: `package.json:13` (определение), `:17` (`dist`), `:18` (`dist:win`).

Мутирует `config.json` при этом именно mac-путь: `tools/build-lite.js:317-320` пишет `edition:'lite'` и возвращает значения только в `finally` (`:377`), который не отрабатывает при Ctrl+C. Застрявший маркер читает `tools/preflight-build.js:390-393`, и на darwin это снимает `config-fresh` (`:403`) — единственный гейт, способный дать fail — и `npm-cache-dupes` (`:410`). Выключаются оба слоя: `tools/before-pack.js:21` (хук `beforePack`, который «обойти нельзя») зовёт тот же `runPreflight`. Ничто на mac-пути маркер не сбрасывает.

Хуже: даже подключив гейт, mac-остаток он не поймает — `tools/build-lite.js:281,285` ставят `build.mac.artifactName` и `build.dmg.artifactName` в `Hamidun-Setup-Mac-Lite.${ext}`, а `tools/assert-clean.js:35-40` смотрит только `build.win.artifactName` и `build.portable.artifactName`.

**Что увидит человек:** сборщик увидит нормальную зелёную сборку. Пользователь получит офлайн-dmg с именем `…-Lite.dmg` и без единой предполётной проверки — включая свежесть конфига, ради которой гейт и написан.

*Оговорка от проверки:* претензия к `assert-clean.js:49` («не ловит `offlineEdition:true`») снята — `true` это штатный маркер офлайн-издания, который пишут фетчеры вендора; ловить его нельзя, `assert:clean` в `dist:win` стоит до `fetch:vendor` и валил бы каждую вторую нормальную сборку.

### 1.3. Маяк завершения курса уходит неподписанным во всех сборках — средняя

`config.json:43` — `"beaconSecret": ""`, и заполнять его нечему. Комментарий в `config.json:39` признаёт это прямым текстом: прежняя редакция утверждала, что значение подставляет `fetch-vendor` на сборке — проверено, в `tools/fetch-vendor.ps1` нет ни одного упоминания `beaconSecret`, и в кредах ключа тоже нет. Тестов на маяк нет вовсе (`grep HM_COURSE_BEACON` по `test/run-tests.js` → 0 совпадений). Сам маяк ожил только 20.08.2026, до этого переменную никто не клал в `childEnv` (`src/main.js:1138-1148`).

**Что увидит человек:** ученик дойдёт до конца курса, сигнал уйдёт, академия пометит его как недоказанный и не засчитает. Ни установщик, ни ученик об этом не узнают.

### 1.4. Инструкция для macOS копируется в dmg с подавлением ошибки — средняя

`.github/workflows/build-mac.yml:139` и `build-mac-lite.yml:314`:

```sh
cp "assets/mac/ПРОЧТИ ЕСЛИ ПИШЕТ ПОВРЕЖДЕНО.txt" "$ST/" 2>/dev/null || true
```

`set -e` активен (`build-mac.yml:114`), поэтому `|| true` несущий, а `2>/dev/null` гасит сообщение. Наличие файла в `$ST` или в образе никто не проверяет. Рядом гейты жёсткие: нет `.app` → `exit 1` (`:116`), не-universal бинарь → `exit 1` (`:122-123`). Подстраховка `package.json:155-172` не работает: отгружаемый dmg собирает не electron-builder — `:141` делает `rm -f "$OUT"` и пересобирает через `hdiutil`, и именно он уходит в S3 (`:199`).

**Что увидит человек:** ничего необычного, и в этом весь смысл понижения тяжести. Та же команда разблокировки лежит в интерфейсе приложения дважды (модалка и несмываемый баннер) и побайтово сверяется с файлом тестом `test/run-tests.js:5444-5466`; есть самолечение карантина (`src/main.js:3358+`) и кнопка «Исправить автоматически» (`src/renderer/app.js:739+`), а нотаризация в CI живая. Потеря бьёт только в сценарии, когда приложение не стартует вовсе и путь через UI недостижим. Правка — три символа.

### 1.5. Скрепка молча не появится без WebView2 на Windows 10 — средняя

`scripts/windows/mascot.ps1:20-34` требует WebView2 Runtime. На Win10 он может отсутствовать. Обещанный в описании компонента `Ctrl+Shift+D` в коде установщика не проверяется ничем.

**Что увидит человек:** галочка «Скрепка» отмечена зелёным на финальном экране, а помощника на экране нет. Человек будет считать, что не понял, как его вызвать.

## 2. Противоречия документов и кода (12)

Общий признак: документ существует, читается как источник правды и отправляет читателя не туда. Ни один из них не помечен как устаревший.

### 2.1. `README.md:30` описывает lite-сборку наоборот — высокая

README обещает: `dist:win:lite # ГИБРИД: вшит только конфиг, приложения качаются при установке (~75 МБ)`. Конфиг — единственный из названных, который в lite как раз **не** вшивается: `remote-components.json` содержит запись `config | win32 | 129076529`, а `tools/build-lite.js:45-49` вшивает `checksums.json` + `apps/uv` + `course/vibecoding-course.zip`. Подтверждено артефактом: `release/win-unpacked/resources/vendor` содержит ровно эти три вещи, `config-pack` там нет. `tools/preflight-build.js:400-403` сам это признаёт и сознательно отключает гейт свежести конфига для lite. Размер тоже мимо: фактический `release/Hamidun-Setup-Windows-Lite.exe` = 87 950 026 Б (83,9 МиБ) против «~75 МБ». `README.md:31` про `dist:mac` несёт ту же фразу, хотя `build.mac.extraResources` = null и vendor в `.app` не попадает вовсе.

Правки требует README, а не код: состав lite обоснован комментарием `tools/build-lite.js:43-44`.

**Что увидит человек:** сборщик соберёт не то, что думает, а при разборе инцидента будет искать конфиг внутри exe, где его нет.

### 2.2. Рецепт офлайн-сборки mac в README даёт кирпич — высокая

`README.md:34-36` описывает два шага: `bash tools/fetch-vendor-mac.sh`, затем `electron-builder --mac`. Третьего шага — сборки финального dmg через `hdiutil` со стейджингом `.app` + vendor рядом — нет ни словом, ссылки на `build-mac.yml` или `MAC-BUILD.md` тоже нет.

Буквальное исполнение рецепта даёт не «онлайн-издание», а нерабочее приложение: `fetch-vendor-mac.sh:701-722` пишет в `config.json` маркер `offlineEdition:true`, конфиг едет внутрь `.app` глобальным `extraResources` (`package.json:77-80`), а vendor рядом никто не кладёт — в `build.mac` (`package.json:134-154`) нет ни одного `extraResources`. Дальше `vendorComplete()` ложно (`src/main.js:77-82`), `isOfflineEdition()` истинно (`:89-92`), `vendorBlockInfo()` возвращает `blocked/'incomplete-vendor'` (`:143-152`). Реальную сборку делает `.github/workflows/build-mac.yml:135-153`; причина, по которой vendor нельзя вшивать в `.app`, названа в `tools/build-lite.js:16-19` — нотаризация ругается на неподписанные Mach-O внутри вложенных архивов.

**Что увидит человек:** жёсткий стоп-экран ещё до кнопки «Установить», без объяснения, что виноват способ сборки.

### 2.3. Пять документов дают три взаимоисключающие инструкции по запуску на macOS — высокая

Файл, который едет в образ, `assets/mac/ПРОЧТИ ЕСЛИ ПИШЕТ ПОВРЕЖДЕНО.txt:29-32`, требует **не** перетаскивать приложение в «Программы» и запускать двойным кликом в окне dmg; `:15-16` велит удалить из «Программ», если уже перетащил. `MAC-BUILD.md:30-34` и `MAC-SIGNING.md:52-53` предписывают ровно обратное, причём оба явно называют это инструкцией для пользователя («Инструкция пользователю», «Пользователь открывает так»). `docs/bridge-bot-spec.md:58-62` доводит сломанную инструкцию до конечного пользователя через бота поддержки и вдобавок ложно утверждает, что «та же инструкция лежит внутри dmg». `README.md:92` предлагает третий путь — правый клик → «Открыть», — хотя `MAC-BUILD.md:20` сам пишет, что это «убрали в Sequoia».

Правоту версии из dmg подтверждает код: на macOS офлайн-vendor лежит рядом с `.app` внутри образа (`src/main.js:32-41,545-547`), а запуск из «Программ» ловится и жёстко блокируется (`:58-64,143-152`) модалкой с прямым требованием удалить приложение из «Программ» (`src/renderer/app.js:665,670,677`).

Это рассинхронизация, а не решение: sibling-vendor и hard-stop приехали 2026-07-20/21, `MAC-BUILD.md` правился 2026-07-11, `MAC-SIGNING.md` — 2026-07-02, строка `README.md:92` не менялась с первого коммита 2026-06-22.

**Что увидит человек:** выполнит инструкцию из документа или от бота поддержки, перетащит приложение в «Программы» и получит стоп-экран. Дальше — по кругу, потому что бот повторит ту же инструкцию.

### 2.4. Документы говорят «подписи нет», а Developer ID и нотаризация включены — высокая

`README.md:88-94` («Сборки пока не подписаны»), `README.md:106` («⏳ подпись/нотаризация»), `MAC-SIGNING.md:50-54` («Пока аккаунта нет (текущее состояние)… ad-hoc подписью»), `MAC-BUILD.md:14` («Сборка без Apple Developer ID (v1)»), `WIN-SIGNING.md:46` (macOS = «ad-hoc»), комментарий-шапка `.github/workflows/build-mac.yml:5` («Без подписи (v1)»), плюс всё ещё едущий в dmg файл `assets/mac/ПРОЧТИ ЕСЛИ ПИШЕТ ПОВРЕЖДЕНО.txt`, и пользовательский текст `docs/bridge-bot-spec.md:58-62`, где бот сообщает на Mac-экране «приложение не подписано Apple Developer ID… Убрать диалог совсем = нотаризация (v2, $99/год)».

**Что увидит человек:** поддержка будет объяснять пользователю несуществующую проблему и предлагать обходной путь вместо того, чтобы разбираться с настоящей причиной.

**Что увидит человек:** тот, кто оценивает безопасность продукта, будет искать защиту sha-пиннингом там, где доставки по сети вовсе нет, и не найдёт настоящую.

### 2.6. Модель угроз застыла на round-4 и врёт в обе стороны — средняя
