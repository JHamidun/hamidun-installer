# Definition of Done

Задача считается сделанной, когда выполнены **все** пункты. Не «выглядит
работающим», а подтверждено.

Каждый пункт здесь стоит не из общих соображений: рядом назван случай, на
котором мы горели без него.

---

## 1. Проверено то, что уедет, а не то, что на диске

- [ ] Если `git status` не пуст — тесты прогнаны на чистом дереве:
      `git stash -u && npm test; git stash pop`.

> 2026-08-24: `src/main.js` закоммичен вместе с чужими правками формы `resolve`,
> а парный тест — нет. Локально 424/0, потому что на диске лежал НОВЫЙ тест;
> в CI старый и красно. Зелёный прогон на грязном дереве не говорит ничего о том,
> что уехало в репозиторий.

## 1a. Документы сверены с кодом, а не только тесты

- [ ] `npm run specs:check` — зелёный. Он падает, когда спека ссылается на
      исчезнувший файл или на переименованный тест.
- [ ] Правил поведение фичи — открой её спеку `docs/specs/<id>.md` и приведи в
      соответствие. Спека, отставшая от кода, вреднее её отсутствия: по ней
      принимают решения.
- [ ] Завёл или убрал фичу — `npm run specs` (перегенерирует список и указатель).

> Из 48 находок аудита 2026-08-25 **двенадцать** — документы, противоречащие коду,
> и половина высоких была там же. Ни один не был помечен устаревшим: все читались
> складно. `npm test` про это молчит — он проверяет код, а не рассказ о коде.

## 2. Коммит собран перечислением путей

- [ ] `git add <конкретные пути>`, не `git add -A` и не `git add .`.
- [ ] `git diff --cached` просмотрен ДО коммита.

> Тот же случай: `git add src/main.js` затащил чужую незавершённую работу.
> Плюс 2026-08-26: `git add -A` при живом рое захватил 1900 строк чужих правок.

## 3. Успех подтверждён артефактом, а не кодом возврата конвейера

- [ ] Для сборок: метка времени артефакта новее начала прогона, размер осмыслен.
- [ ] Скрипт пишет явный маркер в лог: `echo "EXIT=$?" >> log`.

> 2026-08-24: `npm run build` не существует — «Missing script», а `.exe` от
> прошлой сборки остались на диске: провал выглядел успехом. И дважды «exit code
> 0» в уведомлении оказывался кодом `tail`, а не сборки.

## 4. Проверка умеет падать

- [ ] Новый тест или гейт проверен отрицательным контролем: подложи то, что он
      ОБЯЗАН поймать, и убедись, что ловит.

> 2026-08-23: три раза за день проверка отчитывалась бодро, ничего не проверив.
> Регрессионный тест на 422 содержит зеркало прежнего типа именно поэтому.

## 5. Автор не подтверждает сам себя

- [ ] Верификация сделана свежим контекстом: другой агент, или прогон с диска и
      из git, а не пересказ автора.
- [ ] Для находок ревью — воспроизведение, а не утверждение.

## 6. Наружу — только после сверки

- [ ] Опубликованное скачано обратно и сверено (размер, sha или побайтно).
- [ ] Перед публикацией — прогон на личные данные, если артефакт раздаётся людям.

> 2026-08-24: в exe каждому покупателю ехало юридическое имя владельца двумя
> документами. Текстовые сканеры их не видели — проверять надо САМ артефакт.

## 7. Задача закрыта в бэклоге

- [ ] `bd close <id>` с одной строкой: чем подтверждено.
- [ ] Если что-то из объёма не сделано — заведена отдельная задача, а не молчание.

---

## Чего DoD НЕ требует

- Стопроцентного покрытия тестами. Требуется тест на то, что чинили.
- Документации на каждую строку. Требуется спека на фичу.
- Красивого кода. Требуется работающий и объяснимый.
